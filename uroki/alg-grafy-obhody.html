Шаг 1 из 8

Граф: вершины, рёбра, степень

Пять перекрёстков и дороги между ними: 1–2, 1–3, 2–4, 3–4, 4–5. Перекрёстки называют вершинами, дороги рёбрами. Этот граф будет примером на весь урок.

  1 ── 2
  │    │
  3 ── 4 ── 5

Граф G = (V, E): множество вершин V и множество рёбер E, ребро соединяет две вершины. n это число вершин, m число рёбер. Степень вершины это сколько рёбер её касается.

Здесь n = 5, m = 5. Степени: у 1, 2 и 3 по 2, у 4 три, у 5 одна. Сумма 2 + 2 + 2 + 3 + 1 = 10 = 2m: каждое ребро касается двух вершин и посчитано дважды. Если у рёбер есть направление, как у улиц с односторонним движением, граф называют ориентированным.

Сделай сам. В графе 6 рёбер. Чему равна сумма степеней всех вершин? Может ли в графе быть ровно одна вершина нечётной степени?

Сумма степеней 2 · 6 = 12. Одной нечётной быть не может: сумма всегда чётная, а если нечётное слагаемое одно, сумма вышла бы нечётной.

Ответить 6, по числу рёбер. Ребро 1–2 добавляет единицу и к степени 1, и к степени 2, поэтому каждое ребро в сумме даёт 2.

Граф: вершины V (n штук), рёбра E (m штук). Степень = число рёбер у вершины.

Сумма степеней = 2m.

Шаг 2 из 8

Как хранить граф: матрица или списки

Способ первый: таблица n × n, в клетке на пересечении строки u и столбца v, её пишут [u][v], стоит единица, если ребро есть. Её называют матрицей смежности. Способ второй: у каждой вершины список её соседей, это списки смежности.

1: 2 3
2: 1 4
3: 1 4
4: 2 3 5
5: 4

Матрица смежности занимает n² клеток и отвечает «есть ли ребро u–v» за O(1). Списки смежности занимают n + 2m записей, и соседей вершины v перебирают за её степень. Для графов, где рёбер мало, берут списки.

В Java так:

List<List<Integer>> g = new ArrayList<>();
for (int i = 0; i <= n; i++) g.add(new ArrayList<>());
// ребро u–v
g.get(u).add(v);
g.get(v).add(u);

List<List<Integer>> это список, в котором лежат списки целых: по одному списку соседей на вершину. Цикл кладёт в g n + 1 пустых списков. g.get(u) достаёт список номер u, а .add(v) дописывает в него соседа v. Список с номером 0 остаётся пустым, чтобы вершины шли с единицы, как на картинке.

Сделай сам. Граф на 10 000 вершинах и 30 000 рёбрах. Сколько клеток у матрицы и сколько записей у списков? Что выбрать?
Показать ответСкрыть ответ

Матрица 10⁴ · 10⁴ = 10⁸ клеток, почти все нули. Списки 10 000 + 2 · 30 000 = 70 000 записей. Списки меньше в тысячу с лишним раз.

Посчитать для списков n + m = 40 000. Неориентированное ребро лежит в двух списках, у обоих концов, поэтому 2m.

Матрица: n² памяти, ребро за O(1). Списки: n + 2m, соседи за степень.

Рёбер мало → списки.

Шаг 3 из 8

Обход в ширину: волнами

Кинули камень в воду в вершине 1. Первая волна доходит до соседей 2 и 3, вторая до их соседей, это 4, третья до 5. Номер волны и есть расстояние в рёбрах.

Чтобы обходить волнами, нужна очередь из урока про кучи, первым пришёл, первым ушёл.

  1. Очередь [1], расстояние до 1 равно 0.
  2. Достали 1. Соседи 2 и 3 новые, расстояние 1. Очередь [2, 3].
  3. Достали 2. Сосед 4 новый, расстояние 2. Сосед 1 уже был. Очередь [3, 4].
  4. Достали 3. Соседи 1 и 4 уже были. Очередь [4].
  5. Достали 4. Сосед 5 новый, расстояние 3. Очередь [5].
  6. Достали 5, новых нет, очередь пуста.

Обход в ширину, BFS: кладём старт в очередь, потом достаём вершину и кладём в конец всех её непосещённых соседей. Вершины выходят по возрастанию расстояния, поэтому BFS находит кратчайший путь в рёбрах.

Итог: 1:0, 2:1, 3:1, 4:2, 5:3. Каждая вершина попадает в очередь один раз, каждое ребро смотрим дважды, с двух концов. Время O(n + m).

Сделай сам. Запусти BFS из вершины 5. Соседей бери по возрастанию. В каком порядке вершины выйдут из очереди, какие расстояния?
Показать ответСкрыть ответ

Порядок 5, 4, 2, 3, 1. Расстояния 5:0, 4:1, 2:2, 3:2, 1:3.

Помечать вершину посещённой, когда её достали, а не когда положили. Тогда вершину 4 положат в очередь дважды, от 2 и от 3. В большом графе одну вершину кладут десятки раз, и очередь раздувается. Метку ставят в момент, когда кладут.

BFS: очередь. Достал вершину → в конец всех новых соседей, метка при добавлении.

Номер волны = кратчайшее число рёбер. O(n + m).

Шаг 4 из 8

BFS на Java

// вверху файла: import java.util.*;
static int[] bfs(List<List<Integer>> g, int s) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, -1);              // -1 значит «ещё не были»
    ArrayDeque<Integer> q = new ArrayDeque<>();
    dist[s] = 0;
    q.add(s);
    while (!q.isEmpty()) {
        int u = q.poll();               // достать из начала
        for (int w : g.get(u)) {
            if (dist[w] == -1) {
                dist[w] = dist[u] + 1;
                q.add(w);               // положить в конец
            }
        }
    }
    return dist;
}

Сначала служебное. import java.util.* подключает сразу все классы из java.util, звёздочка значит «всё». new int[g.size()] создаёт массив такой длины, сколько списков в g, заполненный нулями. Arrays.fill(dist, -1) записывает −1 во все его ячейки.

ArrayDeque это дек из урока про кучи, им пользуются как очередью: add кладёт в конец, poll достаёт из начала, isEmpty проверяет, пуста ли. Массив dist одновременно хранит расстояния и метки посещения.

Для графа из шага 1 bfs(g, 1) вернёт [-1, 0, 1, 1, 2, 3]. Нулевая ячейка −1, вершины 0 в графе нет. ! в !q.isEmpty() значит «не».

Сделай сам. Добавь в граф вершину 6 без рёбер. Что вернёт bfs(g, 1) для неё и почему это удобно?
Показать ответСкрыть ответ

dist[6] = -1: до неё не дошла ни одна волна. Так сразу видно, что из 1 в 6 пути нет.

Заполнить dist нулями, как Java делает по умолчанию, и проверять dist[w] == 0. Старт тоже имеет расстояние 0, и BFS будет снова и снова класть его в очередь. Нужно значение, которого не бывает у настоящего расстояния, поэтому −1.

ArrayDeque: add в конец, poll из начала.

dist заполняю −1, −1 = не были. В конце −1 = недостижима.

Шаг 5 из 8

Обход в глубину: рекурсией

Другой способ обойти граф: идти как можно дальше, а упёрся, вернуться на шаг и попробовать другую дорогу. Так ходят по лабиринту, держась рукой за стену.

static void dfs(List<List<Integer>> g, int v, boolean[] seen, List<Integer> order) {
    seen[v] = true;
    order.add(v);
    for (int w : g.get(v))
        if (!seen[w]) dfs(g, w, seen, order);
}

seen это массив меток: seen[v] = true значит «уже были в v». for без фигурных скобок повторяет одну следующую строку, здесь это if.

Обход в глубину, DFS: пометить вершину и рекурсивно зайти в каждого непосещённого соседа. Возврат из рекурсии и есть шаг назад. Время тоже O(n + m), памяти уходит на глубину рекурсии.

Из 1, соседи по возрастанию: 1 → 2 → 4 → 3. У 3 соседи 1 и 4 уже были, возвращаемся в 4 → 5. Порядок 1, 2, 4, 3, 5. Из 3 мы видели уже посещённую 1. В 3 мы пришли из 4, эту вершину называют родителем 3 в обходе. Вершина 1 не родитель, и всё же уже посещена: значит, до неё есть второй путь, и в графе есть цикл 1–2–4–3–1.

Сделай сам. В каком порядке DFS обойдёт граф из вершины 5? Соседей бери по возрастанию.
Показать ответСкрыть ответ

5 → 4. У 4 соседи 2, 3, 5, первый новый 2 → 2. У 2 соседи 1 и 4, новый 1 → 1. У 1 соседи 2 и 3, новый 3 → 3. Порядок 5, 4, 2, 1, 3.

Ответить 5, 4, 2, 3, 1, как в BFS из 5. BFS после 4 берёт всех её соседей подряд, а DFS сразу уходит в глубину через 2 и доходит до 1 раньше, чем до 3.

DFS: пометил → рекурсивно в каждого нового соседа. Возврат = шаг назад. O(n + m).

Встретил посещённую вершину, не родителя → есть цикл.

Шаг 6 из 8

Компоненты связности

Граф может распадаться на куски, между которыми нет дорог. Вершины 1–6, рёбра 1–2, 2–3, 4–5. Кусков три: {1, 2, 3}, {4, 5} и одинокая {6}.

Компонента связности это наибольший кусок графа, где из любой вершины можно дойти до любой. Посчитать их: перебираем вершины по порядку, и от каждой ещё не посещённой запускаем DFS. Сколько запусков, столько компонент.

boolean[] seen = new boolean[n + 1];
int count = 0;
for (int v = 1; v <= n; v++) {
    if (!seen[v]) {
        count++;
        dfs(g, v, seen, new ArrayList<>());
    }
}

new boolean[n + 1] создаёт массив меток, где сначала везде false, то есть нигде не были.

Здесь DFS из 1 пометит 1, 2, 3. Вершины 2 и 3 пропускаем. DFS из 4 пометит 4, 5. DFS из 6 пометит только 6. Запусков 3. Всё вместе O(n + m): каждая вершина помечается один раз за всю программу.

Сделай сам. В этот граф добавили ребро 3–4. Сколько теперь компонент? А если вместо него добавить ребро 1–3?
Показать ответСкрыть ответ

С ребром 3–4 два куска: {1, 2, 3, 4, 5} и {6}. С ребром 1–3 по-прежнему три: оно соединяет вершины, которые уже были в одной компоненте, и только добавляет цикл.

Каждый раз создавать новый массив seen внутри цикла. Тогда DFS из 2 снова обойдёт {1, 2, 3}, и счётчик насчитает 6 компонент вместо 3. Метки общие на весь подсчёт.

Компонента: наибольший связный кусок.

Число компонент = число запусков DFS от непосещённых, seen один на всех.

Шаг 7 из 8

Лабиринт как граф

Задача с лабы 10.10. Лабиринт клетками, S старт, F финиш, # стена, точка проход. Ходить можно вверх, вниз, влево и вправо. Найти самый короткий путь.

S . # .
. # . .
. . . #
# . . F

Клетку пишем как (строка, столбец) с нуля: S это (0, 0), F это (3, 3). Каждая свободная клетка это вершина, а соседние свободные клетки соединены ребром. Списки хранить не нужно: соседей считаем на лету.

Клетчатый лабиринт это граф. Соседи клетки (r, c) это (r − 1, c), (r + 1, c), (r, c − 1), (r, c + 1), если они внутри поля и не стена. Кратчайший путь ищет обычный BFS.

int[] dr = {-1, 1, 0, 0};
int[] dc = {0, 0, -1, 1};
// внутри BFS, клетка (r, c) достана из очереди:
for (int k = 0; k < 4; k++) {
    int nr = r + dr[k], nc = c + dc[k];
    if (nr < 0 || nc < 0 || nr >= R || nc >= C) continue;   // за краем
    if (maze[nr][nc] == '#' || dist[nr][nc] != -1) continue;  // стена или были
    dist[nr][nc] = dist[r][c] + 1;
    q.add(new int[]{nr, nc});
}

Как читать код. maze это двумерный массив символов, maze[r][c] клетка в строке r и столбце c. Так же устроен dist. R и C это число строк и столбцов поля. Пара dr[k], dc[k] задаёт один из четырёх ходов: при k = 0 это (−1, 0), шаг вверх. В очередь кладём клетку как массив из двух чисел, new int[]{nr, nc}.

|| значит «или», continue пропускает остаток тела цикла и переходит к следующему k. BFS из S даёт расстояния, стены помечены #:

0 1 # 7
1 # 5 6
2 3 4 #
# 4 5 6

До F 6 шагов.

Сделай сам. Почему до клетки (0, 3) в правом верхнем углу 7 шагов, хотя по прямой от S она в трёх клетках? Каким путём идёт BFS?

Прямо мешает стена (0, 2), поэтому к (0, 3) можно подойти только снизу, из (1, 3). Путь: вниз до (2, 0), вправо до (2, 2), вверх в (1, 2), вправо в (1, 3), вверх в (0, 3). Это 2 + 2 + 1 + 1 + 1 = 7.

Пустить DFS вместо BFS. DFS найдёт какой-то путь, но не обязательно короткий: первым он идёт по первой попавшейся ветке. Кратчайший путь в рёбрах даёт только обход волнами.

Лабиринт: клетка = вершина, 4 соседа dr = {-1,1,0,0}, dc = {0,0,-1,1}.

Проверка: внутри поля, не стена, не были. Кратчайший путь → BFS.

Шаг 8 из 8

Восстановить сам путь

BFS знает длину пути, но не дорогу. Чтобы вывести дорогу, при каждой новой клетке запомним, из какой клетки мы в неё пришли.

// там же, где ставим dist:
prevR[nr][nc] = r;
prevC[nr][nc] = c;

// после BFS идём от финиша назад:
List<String> path = new ArrayList<>();
int r = 3, c = 3;
while (!(r == 0 && c == 0)) {
    path.add("(" + r + ", " + c + ")");
    int pr = prevR[r][c], pc = prevC[r][c];
    r = pr; c = pc;
}
path.add("(0, 0)");
Collections.reverse(path);       // от старта к финишу

Чтобы восстановить путь, храним для каждой вершины предка, ту вершину, из которой в неё пришли. Потом идём от финиша по предкам до старта и разворачиваем список.

prevR и prevC это два двумерных массива: строка и столбец клетки, откуда пришли. Collections.reverse переворачивает список задом наперёд. && значит «и». Для лабиринта выйдет (0, 0) (1, 0) (2, 0) (2, 1) (3, 1) (3, 2) (3, 3), шесть ходов. Есть и другой путь той же длины, через (2, 2). BFS выдаёт один из кратчайших, какой именно, зависит от порядка соседей в dr и dc.

Забыть развернуть и выдать путь от финиша к старту. Длина та же, но в лабиринте с ответом «куда идти» это будет инструкция задом наперёд.
