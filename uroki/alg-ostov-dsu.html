Шаг 1 из 8

Остов и минимальный остов

Хотим, чтобы из любого дома можно было дойти до любого по кабелю, и заплатить как можно меньше. Лишний кабель не нужен: если между домами уже есть дорога по кабелю, второй путь только тратит деньги. Значит, циклов быть не должно.

Дерево это связный граф без циклов. В дереве из n вершин ровно n − 1 рёбер: меньше, и граф развалится, больше, и появится цикл.

Остов, или остовное дерево, это дерево из рёбер графа, которое проходит через все его вершины. Минимальный остов это остов с наименьшей суммой весов.

В графе 1 вершин 4, значит в остове 3 ребра. Например, A–C, B–C, B–D это остов, вес 3 + 2 + 5 = 10. А A–B, B–C, C–D тоже остов, вес 1 + 2 + 4 = 7. Дешевле 7 не выйдет, это покажет шаг 2.

Проверить только число рёбер: «пять, значит остов». Пять рёбер нужны, но этого мало. Ещё нужно, чтобы не было цикла и все вершины были связаны.

Дерево: связно, без циклов, n − 1 рёбер.

Остов: дерево из рёбер графа через все вершины. Минимальный: наименьшая сумма весов.

Шаг 2 из 8

Алгоритм Краскала: от лёгких рёбер

Самая простая жадная мысль: брать сначала самые дешёвые рёбра. Только ребро, которое замыкает цикл, брать нельзя, оно лишнее.

Алгоритм Краскала: сортируем рёбра по весу и идём от лёгких к тяжёлым. Ребро берём, если его концы лежат в разных кусках уже набранного леса. Если в одном куске, ребро замкнёт цикл, пропускаем. Набрали n − 1 рёбер, остов готов.

Краскал: рёбра по возрастанию. Концы в разных кусках → берём, в одном → цикл, пропуск. Стоп на n − 1 ребре.

Шаг 3 из 8

DSU: у каждого куска свой главный

Самое трудное в Краскале это вопрос «в одном ли куске A и C». Запускать DFS на каждое ребро дорого: m рёбер по O(n + m) каждое. Нужна структура, которая отвечает почти мгновенно.

DSU, по-английски Union-Find, система непересекающихся множеств. Каждый кусок хранится деревом: у каждой вершины есть родитель parent[x], у корня родитель он сам. Корень это главный в куске, его представитель. find(x) идёт от x по родителям до корня. Две вершины в одном куске, если у них один корень.

Вершины 0–4. parent = [0, 0, 2, 2, 4]. Читаем: у 1 родитель 0, у 3 родитель 2, а 0, 2 и 4 сами себе родители, это корни. Кусков три: {0, 1}, {2, 3}, {4}.

find(1): 1 → 0, у 0 родитель 0, корень 0. find(3): 3 → 2, корень 2. Корни разные, значит 1 и 3 в разных кусках.

Сделай сам. parent = [0, 0, 1, 2, 4]. Чему равны find(3) и find(4)? Сколько кусков?
Показать ответСкрыть ответ

find(3): 3 → 2 → 1 → 0, корень 0. find(4) = 4, она сама корень. Корней два, 0 и 4, кусков два: {0, 1, 2, 3} и {4}.

Ответить find(3) = 2, остановившись на родителе. Родитель это ещё не корень. Идём, пока parent[x] == x.

DSU: parent[x], корень: parent[r] == r. find(x): вверх до корня.

Один кусок ⇔ один корень.

Шаг 4 из 8

union и ранг

Когда Краскал берёт ребро, два куска сливаются в один. В DSU для этого достаточно подвесить один корень под другой. Вопрос в том, какой под какой.

union(x, y): находим корни x и y. Если корень один, они уже вместе, ничего не делаем. Иначе подвешиваем корень с меньшим рангом под корень с большим. Ранг это примерная высота дерева. Если ранги равны, подвешиваем любой, и ранг нового корня растёт на 1.

Пример со слайда. Пять вершин 0–4, сначала каждая сама по себе: parent = [0, 1, 2, 3, 4], rank = [0, 0, 0, 0, 0].

операциячто происходитparentrank
union(0, 1)ранги 0 и 0, 1 под 0, ранг 0 стал 10 0 2 3 41 0 0 0 0
union(2, 3)3 под 2, ранг 2 стал 10 0 2 2 41 0 1 0 0
union(1, 2)корни 0 и 2, ранги 1 и 1, 2 под 0, ранг 0 стал 20 0 0 2 42 0 1 0 0

Зачем ранг. Если подвешивать как попало, дерево может вытянуться в цепочку длиной n, и find будет идти через все вершины. Невысокое дерево под высокое не делает высокое выше.

Сделай сам. Продолжи таблицу: union(4, 3), потом union(1, 3). Что станет с parent и rank? Для простоты считай, что find пока только читает родителей и ничего не меняет.

union(4, 3): корень 4 это 4, ранг 0. Корень 3: 3 → 2 → 0, это 0, ранг 2. Меньший под больший: 4 под 0. parent = [0, 0, 0, 2, 0], ранги не меняются: [2, 0, 1, 0, 0].

union(1, 3): корень 1 это 0, корень 3 это 0. Корень один, уже вместе, ничего не делаем.

Подвесить 0 под 4, потому что в вызове 4 стоит первым. Порядок аргументов не важен, решает ранг. Под 4 дерево стало бы выше на 1.

union(x, y): корни rx, ry. Равны → уже вместе. Иначе меньший ранг под больший, при равных ранг корня +1.

Шаг 5 из 8

Сжатие путей

Вторая хитрость. Раз find всё равно прошёл весь путь до корня, можно заодно перевесить все вершины этого пути прямо на корень. В следующий раз путь будет в один шаг.

Сжатие путей: в find(x) каждой вершине на пути до корня записываем родителем сам корень. Вместе с рангом это даёт O(α(n)) на операцию. α это обратная функция Аккермана, она растёт так медленно, что на любых реальных данных не больше 4. Считай, что почти константа.

Пример: parent = [0, 0, 1, 2, 4], цепочка 3 → 2 → 1 → 0. find(3) находит корень 0 и по дороге назад ставит родителем 0 вершинам 3, 2 и 1. Стало parent = [0, 0, 0, 0, 4]. Теперь find(3) делает один шаг.

Ранги при сжатии не пересчитывают. Поэтому ранг и называют примерной высотой: после сжатия дерево ниже, чем говорит ранг.

Сделай сам. В таблице шага 4 после union(1, 2) было parent = [0, 0, 0, 2, 4]. Вызвали find(3) со сжатием. Каким станет parent?
Показать ответСкрыть ответ

Путь 3 → 2 → 0, корень 0. Вершину 3 перевешиваем на 0, у 2 родитель и так 0. parent = [0, 0, 0, 0, 4]. Так и написано на слайде лекции.

Перевесить на корень только саму вершину 3, а промежуточные оставить. Сжатие касается всех вершин на пути. В этом примере разницы нет, потому что у 2 родитель уже корень, но в цепочке 3 → 2 → 1 → 0 надо перевесить и 2, и 1.

Сжатие путей: в find всем на пути родитель = корень.

Ранг + сжатие: O(α(n)), α ≤ 4 на практике.

Шаг 6 из 8

DSU на Java

static int[] parent, rank;

static int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]);    // сжатие путей
    return parent[x];
}

static boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;         // уже в одном куске
    if (rank[ra] < rank[rb]) {          // пусть ra будет выше
        int t = ra; ra = rb; rb = t;
    }
    parent[rb] = ra;                    // низкое под высокое
    if (rank[ra] == rank[rb]) rank[ra]++;
    return true;
}

Массивы объявлены над методами со словом static, поэтому их видят оба метода. Перед работой их создают: parent = new int[n], rank = new int[n], и в цикле пишут parent[i] = i, каждый сам себе корень. Ранги Java сама заполнит нулями.

find рекурсивный: «мой корень это корень моего родителя». На возврате из рекурсии каждая вершина пути получает корень родителем, это и есть сжатие. union возвращает true, если куски слились, и false, если были уже вместе. Этот ответ и нужен Краскалу.

Три строки с t меняют местами ra и rb. После них ra всегда корень с рангом не меньше, и дальше код один на оба случая.

Сделай сам. n = 4, всё только создано. Что вернут по очереди union(0, 1), union(2, 3), union(1, 0), union(3, 1)? Какой массив parent будет в конце?

union(0, 1): true, 1 под 0, ранг 0 стал 1. union(2, 3): true, 3 под 2, ранг 2 стал 1. union(1, 0): корни 0 и 0, false. union(3, 1): ra = 2, rb = 0, ранги 1 и 1, обмена нет, 0 под 2, ранг 2 стал 2, true. parent = [2, 0, 2, 2].

Написать parent[b] = a вместо parent[rb] = ra. Тогда подвешивается сама вершина, а не корень её куска. Её старый кусок потеряет связь, и DSU начнёт врать про компоненты.

find: if (parent[x] != x) parent[x] = find(parent[x]), вернуть parent[x].

union: подвешиваю корень под корень. false = уже вместе.

Шаг 7 из 8

Краскал на Java и его сложность

Рёбра храним массивом троек int[]{u, v, вес}. Вершины A, B, C, D графа 1 это 0, 1, 2, 3.

// вверху файла: import java.util.*;
static int kruskal(int n, int[][] edges) {
    parent = new int[n];
    rank = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);   // по весу
    int total = 0, taken = 0;
    for (int[] e : edges) {
        if (union(e[0], e[1])) {                 // разные куски
            total += e[2];
            taken++;
            if (taken == n - 1) break;
        }
    }
    return total;
}

// в main:
int[][] edges = { {0, 1, 1}, {1, 2, 2}, {0, 2, 3}, {2, 3, 4}, {1, 3, 5} };
System.out.println(kruskal(4, edges));         // 7

Запись (a, b) -> a[2] - b[2] ты видел в Дейкстре с кучей: это правило сравнения. Здесь две тройки сравниваются по третьему числу, весу. union сам и проверяет куски, и сливает их, поэтому отдельный find не нужен.

Краскал стоит O(m log m). Дороже всего сортировка рёбер. Все union вместе стоят O(m · α(n)), почти линейно, и на фоне сортировки не видны.

Шаг 8 из 8

Алгоритм Прима: растим из одной вершины

Другой способ, его разбирали на лабе 17.10. Не смотрим на все рёбра сразу, а растим одно дерево от стартовой вершины.

Алгоритм Прима: начинаем с одной вершины. На каждом шаге берём самое лёгкое ребро, у которого один конец уже в дереве, а другой ещё снаружи, и добавляем внешний конец в дерево. Повторяем, пока не войдут все вершины.

Граф 1 из A. Дерево {A}, наружу A–B 1 и A–C 3, берём A–B. Дерево {A, B}, наружу A–C 3, B–C 2, B–D 5, берём B–C. Дерево {A, B, C}, наружу C–D 4 и B–D 5, берём C–D. Ребро A–C 3 теперь ведёт внутрь, оно не годится. Тот же остов, вес 7.

Код похож на Дейкстру с кучей. Разница одна: в куче лежит не расстояние от старта, а вес одного ребра.

// g.get(u) список рёбер из u, ребро int[]{сосед, вес}
static int prim(List<List<int[]>> g, int s) {
    boolean[] inTree = new boolean[g.size()];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    pq.add(new int[]{0, s});               // {вес ребра, вершина}
    int total = 0;
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int w = top[0], u = top[1];
        if (inTree[u]) continue;           // уже в дереве, ребро внутрь
        inTree[u] = true;
        total += w;
        for (int[] e : g.get(u))
            if (!inTree[e[0]]) pq.add(new int[]{e[1], e[0]});
    }
    return total;
}

Граф неориентированный, поэтому ребро кладут в оба списка, к u и к v. Прим с кучей стоит O(m log n). На слайде лекции подписи перепутаны: у Краскала написано «рост дерева из одной вершины», а это Прим. У Прима указан Union-Find, а он нужен Краскалу. Запомни правильно: Краскал = сортировка + DSU, Прим = рост из вершины + куча.
