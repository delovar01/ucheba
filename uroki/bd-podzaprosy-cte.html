Подзапросы, WITH и множества

Базы данных · лекции 2–3 от 29.09 (подзапросы) и лекция 4 от 13.10 (WITH, UNION, EXCEPT) · около 55 минут

Подзапрос это запрос внутри другого запроса. Его ответ становится числом, списком или целой таблицей для внешнего запроса. На лекции 4 сказали так: подзапросы превращают SQL в «лапшу», а WITH позволяет писать сверху вниз, шаг за шагом, как код на Python. Здесь и то и другое, а в конце операции над результатами как над множествами.

Нужно уже уметь JOIN, GROUP BY и CASE: если плывёт, сначала уроки «Сортировка, фильтры и JOIN», «LEFT JOIN и GROUP BY» и «CASE и даты». Всё на твоей базе ml_tracker. Как проходить: читаешь шаг, решаешь «сделай сам» сам и только потом открываешь ответ.

Шаг 1 из 11

Подзапрос-число в WHERE

Хотим наборы данных, которые больше среднего. Среднее сначала надо посчитать, а в WHERE писать AVG нельзя. Решение: посчитать его отдельным запросом прямо внутри условия.

SELECT name, count
FROM datasets
WHERE count > (SELECT AVG(count) FROM datasets);

Подзапрос пишут в круглых скобках, база выполняет его первым. Если он возвращает одно число, его можно ставить туда, где ждут число. Такой подзапрос называют скалярным.

Внутренний запрос даёт 23648.5. Дальше база ищет count > 23648.5: IMDB Reviews 50000 и MNIST 70000. Проверяй подзапрос так же: выдели его без скобок и запусти один.

Сделай сам. Оценки accuracy, которые выше средней accuracy. Номер запуска и значение.
Показать ответСкрыть ответ 
SELECT experiments_id, mean_metric
FROM metrics
WHERE name_metric = 'accuracy'
  AND mean_metric > (SELECT AVG(mean_metric)
                     FROM metrics
                     WHERE name_metric = 'accuracy');

Средняя accuracy 0.911. Выше неё четыре: запуски 3 (0.960), 5 (0.982), 8 (0.991), 9 (0.947).

Вернуть из подзапроса не одно число, а столбец: WHERE mean_metric > (SELECT mean_metric FROM metrics WHERE …). Число нельзя сравнить со списком, PostgreSQL ответит more than one row returned by a subquery used as an expression, «подзапрос вернул больше одной строки». Где нужно одно число, внутри должен быть AVG, MAX или другой агрегат.

WHERE x > (SELECT AVG(x) FROM t), подзапрос в скобках выполняется первым.

Там, где ждут число, подзапрос обязан вернуть одно значение.

Шаг 2 из 11

IN (SELECT …): подзапрос-список

На каких наборах данных запускали Resnet, модель 3? Номера наборов лежат в запусках, названия в datasets.

SELECT name
FROM datasets
WHERE id IN (SELECT dataset_id
             FROM experiments
             WHERE model_id = 3);

Если подзапрос возвращает один столбец и много строк, это список. Его ставят после IN, как список в скобках из урока про фильтры, только значения база находит сама. Пример с лекции такой же: фильмы с теми рейтингами, которые есть у фильмов со словом PET в названии.

Подзапрос даёт 1, 3, 5. Ответ: iris, California Housing, MNIST.

Чем это лучше JOIN? IN не размножает строки. У Resnet все три набора разные, и разницы не видно. Но возьми другую модель: Logisticregression запускали на iris дважды. Тот же запрос с model_id этой модели через JOIN выдал бы iris два раза, а через IN один.

Сделай сам. Какие модели запускал Щайхутдинов Азат, исследователь 2? Через IN.

Выбрать в подзапросе не тот столбец: SELECT id FROM experiments WHERE researcher_id = 2. Это номера запусков 3, 7, 8, а не моделей. Ошибки не будет, но ответ будет про модели с номерами 3, 7 и 8, а из них есть только Resnet. Подзапрос должен вернуть то, с чем сравниваешь, здесь model_id.

Подзапрос в IN возвращает ровно один столбец, и тот, с которым сравниваешь.

Шаг 3 из 11

NOT IN и ловушка с NULL

Кто из исследователей не сделал ни одного запуска?

SELECT full_name
FROM researchers
WHERE id NOT IN (SELECT researcher_id FROM experiments);

Ответ: Смирнов Олег. NOT IN значит «нет в списке».

Если в списке после NOT IN есть хоть один NULL, ответ всегда пустой. x NOT IN (2, NULL) для базы значит «x не 2 и x не NULL». Второе сравнение с неизвестным даёт «неизвестно», а WHERE пропускает только «да».

Вот где это стреляет на твоих данных. Хотим тех, кто не из групп Ивановой и Смирнова:

SELECT full_name
FROM researchers
WHERE grp NOT IN (SELECT grp FROM researchers WHERE id IN (3, 4));

Ждём Павленко и Щайхутдинова из РИ-250932, а приходит пусто: у Смирнова группа NULL, и она попала в список. Лечится условием внутри подзапроса: WHERE id IN (3, 4) AND grp IS NOT NULL.

Сделай сам. Какие модели ни разу не запускали? Может ли здесь сработать ловушка с NULL?
Показать ответСкрыть ответ

FROM models
WHERE id NOT IN (SELECT model_id FROM experiments);

CatBoost. Ловушки не будет: у model_id стоит NOT NULL, пустого номера в запусках нет.

Писать NOT IN по столбцу, где бывает пусто, и верить пустому ответу. Пустой ответ здесь не значит «таких нет». Если в столбце бывает NULL, бери NOT EXISTS из следующего шага, он этой ловушки не знает.

WHERE id NOT IN (SELECT …): кого нет в списке.

Один NULL в списке, и NOT IN вернёт пусто.

Шаг 4 из 11

EXISTS: есть хоть одна строка

У кого из исследователей есть упавший запуск?

SELECT r.full_name
FROM researchers r
WHERE EXISTS (SELECT 1
              FROM experiments e
              WHERE e.researcher_id = r.id
                AND e.status = 'failed');

EXISTS (подзапрос) верно, если подзапрос вернул хотя бы одну строку. NOT EXISTS верно, если ни одной. Что именно выбрать внутри, не важно, поэтому пишут SELECT 1.

Внутри стоит r.id из внешнего запроса. Такой подзапрос называют коррелированным: база считает его заново для каждого исследователя. Для Павленко ищет его упавшие запуски, не находит. Для Щайхутдинова находит запуск 7. Ответ: Щайхутдинов Азат. Подзапросы в шагах 1–3 ссылок наружу не имели, их можно было запустить отдельно.

Сделай сам. Запуски, у которых нет ни одной оценки. Номер и статус.
Показать ответСкрыть ответ 
SELECT e.id, e.status
FROM experiments e
WHERE NOT EXISTS (SELECT 1
                  FROM metrics m
                  WHERE m.experiments_id = e.id);

Одна строка: запуск 7, failed. Упавший запуск ничего не намерил.

Забыть связь с внешним запросом: NOT EXISTS (SELECT 1 FROM metrics m). Тогда подзапрос спрашивает «есть ли в базе хоть одна оценка вообще». Есть, значит NOT EXISTS ложно для всех, и ответ пустой. Внутри всегда нужно условие вида m.experiments_id = e.id.

WHERE NOT EXISTS (SELECT 1 FROM t2 WHERE t2.ссылка = t.id)

Без условия на внешнюю таблицу EXISTS проверяет всю таблицу разом.

Шаг 5 из 11

Подзапрос в FROM: таблица на лету

Сколько оценок в среднем приходится на запуск? Сначала надо посчитать оценки у каждого запуска, потом среднее этих чисел. AVG(COUNT(*)) не сработает: PostgreSQL ответит aggregate function calls cannot be nested, агрегат в агрегат вкладывать нельзя.

SELECT AVG(n)
FROM (SELECT experiments_id, COUNT(*) AS n
      FROM metrics
      GROUP BY experiments_id) AS po_zapuskam;

Подзапрос можно поставить после FROM, тогда его ответ работает как обычная таблица. Её называют производной таблицей. Дай ей имя через AS: по нему обращаешься к её столбцам, а в PostgreSQL до 16-й версии без имени будет ошибка subquery in FROM must have an alias. MySQL без имени тоже не пустит.

Внутренний запрос даёт восемь строк: у запусков 1, 2, 3 и 6 по две оценки, у 4, 5, 8 и 9 по одной. Всего 12 оценок на 8 запусков, среднее 1.5.

Сделай сам. Лучшая accuracy на каждом наборе данных, с названием набора. Сначала производная таблица «номер набора и лучшая accuracy», потом к ней JOIN datasets.
Показать ответСкрыть ответ 
SELECT d.name, b.best
FROM (SELECT e.dataset_id, MAX(m.mean_metric) AS best
      FROM metrics m
      JOIN experiments e ON e.id = m.experiments_id
      WHERE m.name_metric = 'accuracy'
      GROUP BY e.dataset_id) AS b
JOIN datasets d ON d.id = b.dataset_id
ORDER BY b.best DESC;

Четыре строки: MNIST 0.991, pirs 0.960, iris 0.947, IMDB Reviews 0.874. У California Housing только r2, у Titanic оценок нет, их в ответе нет.

Забыть AS best у MAX внутри. Тогда столбец назовётся max, и b.best снаружи даст column b.best does not exist. Снаружи видны только те имена, которые ты дал внутри.

FROM (SELECT … GROUP BY …) AS имя: ответ подзапроса как таблица.

Агрегат от агрегата считают только так, AVG(COUNT(*)) нельзя.

Шаг 6 из 11

WITH: подзапрос с именем наверху

Тот же запрос из «сделай сам» шага 5, но читается сверху вниз.

WITH best AS (
    SELECT e.dataset_id, MAX(m.mean_metric) AS best
    FROM metrics m
    JOIN experiments e ON e.id = m.experiments_id
    WHERE m.name_metric = 'accuracy'
    GROUP BY e.dataset_id
)
SELECT d.name, b.best
FROM best b
JOIN datasets d ON d.id = b.dataset_id
ORDER BY b.best DESC;

WITH имя AS (запрос) объявляет временную таблицу до основного запроса. Это называется CTE, от common table expression, «общее табличное выражение». Живёт она только в этом запросе. Ответ тот же: MNIST 0.991, pirs 0.960, iris 0.947, IMDB Reviews 0.874.

Пример лекции такой же формы: в WITH сумма платежей каждого клиента, а снизу JOIN к клиентам, сортировка и топ-5.

Сделай сам. Перепиши через WITH запрос шага 5 про среднее число оценок на запуск.
Показать ответСкрыть ответ 
WITH po_zapuskam AS (
    SELECT experiments_id, COUNT(*) AS n
    FROM metrics
    GROUP BY experiments_id
)
SELECT AVG(n) FROM po_zapuskam;

Поставить точку с запятой после скобки WITH: … ); SELECT AVG(n) FROM po_zapuskam;. Точка с запятой заканчивает запрос, и WITH остаётся без основной части, а второй запрос не знает po_zapuskam: relation "po_zapuskam" does not exist. Точка с запятой одна, в самом конце.

WITH имя AS (SELECT …) SELECT … FROM имя;

CTE живёт только внутри одного запроса, ; только в конце.

Шаг 7 из 11

Несколько CTE подряд

Кто из исследователей в среднем берёт accuracy выше, чем средняя по всем? Три шага: собрать accuracy с номером исследователя, посчитать среднее у каждого, сравнить с общим.

WITH acc AS (
    SELECT e.researcher_id, m.mean_metric
    FROM metrics m
    JOIN experiments e ON e.id = m.experiments_id
    WHERE m.name_metric = 'accuracy'
),
po_lyudyam AS (
    SELECT researcher_id, AVG(mean_metric) AS srednyaya
    FROM acc
    GROUP BY researcher_id
)
SELECT r.full_name, p.srednyaya
FROM po_lyudyam p
JOIN researchers r ON r.id = p.researcher_id
WHERE p.srednyaya > (SELECT AVG(mean_metric) FROM acc)
ORDER BY p.srednyaya DESC;

В одном WITH можно объявить несколько CTE через запятую, слово WITH пишется один раз. Следующий может брать данные из предыдущего, а основной запрос из любого и сколько угодно раз. Здесь acc используется дважды.

Средние: Павленко 0.832, Щайхутдинов 0.976, Иванова 0.965, общая 0.911. Ответ: Щайхутдинов Азат 0.976, Иванова Мария 0.965.

Сделай сам. Наборы данных, на которых запусков больше, чем в среднем на набор. Первый CTE: число запусков у каждого набора.
Показать ответСкрыть ответ 
WITH po_naboram AS (
    SELECT dataset_id, COUNT(*) AS n
    FROM experiments
    GROUP BY dataset_id
)
SELECT d.name, p.n
FROM po_naboram p
JOIN datasets d ON d.id = p.dataset_id
WHERE p.n > (SELECT AVG(n) FROM po_naboram)
ORDER BY p.n DESC;

9 запусков на 6 наборов, в среднем 1.5. Больше: iris 3 и MNIST 2.

Писать WITH перед каждым CTE: WITH a AS (…), WITH b AS (…). Это синтаксическая ошибка. Слово одно, дальше только запятые.

WITH a AS (…), b AS (SELECT … FROM a) SELECT …

На CTE можно ссылаться много раз, и из следующих CTE тоже.

Шаг 8 из 11

COALESCE в CTE: ноль вместо пустоты

На лекции 4 задача была про клиентов проката: посчитать, сколько потратил каждый, разделить на «Новичков», «Любителей» и «Фанатов» и показать фанатов первыми. Сделаем то же на твоей базе за два шага. В этом шаге посчитаем, сколько эпох всего прогнал каждый исследователь, включая Смирнова с нулём.

WITH epohi AS (
    SELECT r.full_name, COALESCE(SUM(e.count_apoh), 0) AS vsego
    FROM researchers r
    LEFT JOIN experiments e ON e.researcher_id = r.id
    GROUP BY r.id, r.full_name
)
SELECT full_name, vsego
FROM epohi
ORDER BY vsego DESC;

COALESCE(x, 0) возвращает первое непустое из списка: если x пустой, будет 0. У Смирнова запусков нет, SUM по пустой кучке даёт NULL, а с COALESCE ноль.

Эпохи: Щайхутдинов 1 + 1 + 10, Иванова 1 + 5 + 1, Павленко 1 + 3. У его запуска 2 эпохи не записаны, SUM пустую клетку пропускает.

    SELECT m.name, COALESCE(SUM(e.count_apoh), 0) AS vsego

Написать JOIN вместо LEFT JOIN. У CatBoost запусков нет, обычный JOIN выкинет её совсем, и до COALESCE дело не дойдёт. Ноль можно показать, только если строка модели осталась.

COALESCE(x, 0): пусто превращается в 0.

Шаг 9 из 11

Итоговая задача лекции: CASE для метки и для очереди

Берём epohi из прошлого шага и делим людей на группы: больше 10 эпох «много», от 5 до 10 «середина», меньше «новичок». Сначала «много», потом «середина», потом «новички».

WITH epohi AS (
    SELECT r.full_name, COALESCE(SUM(e.count_apoh), 0) AS vsego
    FROM researchers r
    LEFT JOIN experiments e ON e.researcher_id = r.id
    GROUP BY r.id, r.full_name
)
SELECT full_name, vsego,
       CASE
           WHEN vsego > 10 THEN 'много'
           WHEN vsego >= 5 THEN 'середина'
           ELSE 'новичок'
       END AS gruppa
FROM epohi
ORDER BY CASE
             WHEN vsego > 10 THEN 1
             WHEN vsego >= 5 THEN 2
             ELSE 3
         END,
         full_name;

Первый CASE в SELECT ты знаешь из урока про CASE, он даёт метку.

CASE можно поставить и в ORDER BY. Тогда база сортирует не по столбцу, а по числу, которое вернул CASE: «много» получает 1, «середина» 2, «новичок» 3, и строки встают по этим номерам. После запятой второй ключ сортировки, full_name: внутри одного номера по алфавиту. Сортировать прямо по метке нельзя: по алфавиту «много» встанет раньше «новичка», но «середина» уедет в конец.

Сделай сам. Каждой модели число запусков и подпись: 0 «не запускали», 1 или 2 «пару раз», больше «часто». Сначала самые частые.
Показать ответСкрыть ответ 
WITH zapuski AS (
    SELECT m.name, COUNT(e.id) AS n
    FROM models m
    LEFT JOIN experiments e ON e.model_id = m.id
    GROUP BY m.id, m.name
)
SELECT name, n,
       CASE
           WHEN n = 0  THEN 'не запускали'
           WHEN n <= 2 THEN 'пару раз'
           ELSE 'часто'
       END AS kak
FROM zapuski
ORDER BY n DESC, name;

Resnet 3 часто, Logisticregression 2, RandomForest 2, rubert-tiny2 2 пару раз, CatBoost 0 не запускали.

Написать COUNT(*) вместо COUNT(e.id). После LEFT JOIN у CatBoost одна строка с пустым запуском, и COUNT(*) насчитает 1, «пару раз». COUNT(e.id) пустые не считает и даст 0.

Схема лекции: CTE считает итог, снаружи CASE даёт метку и CASE в ORDER BY ставит очередь.

ORDER BY CASE … THEN 1 … THEN 2 … END сортирует в своём порядке, а не по алфавиту.

Шаг 10 из 11

UNION: сложить два ответа

Какими моделями работали Павленко или Щайхутдинов? Два запроса, ответы сложим.

SELECT m.name FROM models m
JOIN experiments e ON e.model_id = m.id
WHERE e.researcher_id = 1
UNION
SELECT m.name FROM models m
JOIN experiments e ON e.model_id = m.id
WHERE e.researcher_id = 2
ORDER BY name;

запрос1 UNION запрос2 ставит строки второго ответа под строки первого и убирает повторы. UNION ALL повторы оставляет и работает быстрее. Условие: у обоих запросов одинаковое число столбцов и похожие типы.

Павленко: Logisticregression, Resnet, rubert-tiny2. Щайхутдинов: RandomForest, RandomForest, Resnet. UNION даёт четыре: Logisticregression, RandomForest, Resnet, rubert-tiny2. UNION ALL дал бы все шесть строк. ORDER BY пишется один раз, в самом конце, и сортирует общий ответ.

SELECT m.name FROM models m
JOIN experiments e ON e.model_id = m.id
WHERE e.researcher_id = 2;

INTERSECT оставляет строки, которые есть в обоих ответах, это пересечение. EXCEPT оставляет строки первого ответа, которых нет во втором, это разность. Порядок у EXCEPT важен, у INTERSECT нет.

INTERSECT: Resnet. Если заменить на EXCEPT: Logisticregression и rubert-tiny2. Если поменять половины местами, EXCEPT даст RandomForest.

На лекции предупреждали: в MySQL до версии 8.0.31 INTERSECT и EXCEPT не было, их заменяли на JOIN, EXISTS и LEFT JOIN … IS NULL. В PostgreSQL они есть давно.
