Чистая функция и побочный эффект

public class Main {
    static int total = 0;

    static int add(int a, int b) {
        return a + b;
    }

    static int addToTotal(int x) {
        total += x;
        return total;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));
        System.out.println(add(2, 3));
        System.out.println(addToTotal(5));
        System.out.println(addToTotal(5));
    }
}

Чистая функция возвращает одно и то же для одинаковых аргументов и ничего не меняет вокруг себя. add из примеров Корелина чистая: add(2, 3) всегда 5. addToTotal меняет общее поле total, это побочный эффект: тот же вызов с 5 вернул сначала 5, потом 10.

Мысль лекции: функциональное программирование держится на чистых функциях и неизменяемых данных. Такой код проще проверять, его результат зависит только от входа. Java берёт у этого подхода лямбды, функции высшего порядка и Stream, они дальше.

Функциональный интерфейс и лямбда

Калькулятор из seminar2. Сначала по-старому, классом, потом лямбдой:

interface Calculator {
    double calculate(int a, int b);
}

class Sum implements Calculator {
    @Override
    public double calculate(int a, int b) {
        return a + b;
    }
}

public class Main {
    public static void main(String[] args) {
        Calculator sumClass = new Sum();
        System.out.println("Сумма классом: " + sumClass.calculate(5, 3));

        Calculator sum = (a, b) -> a + b;
        Calculator product = (a, b) -> a * b;
        Calculator hypotenuse = (a, b) -> Math.sqrt(a * a + b * b);
        System.out.println("Сумма: " + sum.calculate(5, 3));
        System.out.println("Произведение: " + product.calculate(5, 3));
        System.out.println("Гипотенуза: " + hypotenuse.calculate(3, 4));
    }
}
Сумма классом: 8.0
Сумма: 8.0
Произведение: 15.0
Гипотенуза: 5.0

Функциональный интерфейс: интерфейс ровно с одним абстрактным методом. Лямбда (a, b) -> a + b это короткая запись класса, который реализует такой интерфейс: слева от стрелки параметры метода, справа то, что он возвращает. Типы a и b писать не надо, Java берёт их из calculate(int a, int b). Ответ double, поэтому 8 печатается как 8.0.

Над таким интерфейсом ставят @FunctionalInterface, как у Корелина. Если дописать второй абстрактный метод, компилятор скажет Unexpected @FunctionalInterface annotation и multiple non-overriding abstract methods found: лямбда не знала бы, какой из двух методов она заменяет.

Function: из одного значения другое

import java.util.function.Function;

public class Main {
    public static void main(String[] args) {
        Function<Integer, Integer> increment = x -> x + 1;
        Function<Integer, Integer> square = x -> x * x;
        Function<String, Integer> length = s -> s.length();

        System.out.println(increment.apply(3));
        System.out.println(square.apply(3));
        System.out.println(length.apply("банан"));

        Function<Integer, Integer> incrementThenSquare = increment.andThen(square);
        System.out.println(incrementThenSquare.apply(3));
    }
}
4
9
5
16

Свой интерфейс на каждый случай писать не нужно: в пакете java.util.function готовые есть. Function<T, R> принимает значение типа T и возвращает R, метод у него apply. Типы в угловых скобках называют дженериками, параметрами типа, как у ArrayList<String>. Там пишут только классы, поэтому вместо int стоит Integer, класс-обёртка над числом. Java сама переводит одно в другое.

andThen из примера Корелина склеивает две функции в новую: сначала прибавить 1, потом в квадрат. (3 + 1)² = 16. Это композиция функций со слайда.

Читать a.andThen(b) справа налево. Порядок как в тексте: сначала a, потом b.

Function<T, R>: apply(t) даёт R. В скобках классы: Integer, не int.

Predicate: проверка да или нет

import java.util.function.Predicate;

public class Main {
    public static void main(String[] args) {
        Predicate<String> containsA = s -> s.contains("a");
        Predicate<String> containsB = s -> s.contains("b");
        Predicate<String> isLong = s -> s.length() > 5;

        System.out.println(containsA.test("apple"));
        System.out.println(containsA.and(containsB).test("banana"));
        System.out.println(containsA.and(containsB).test("apple"));
        System.out.println(containsB.or(isLong).test("cherry"));
        System.out.println(isLong.negate().test("cherry"));

}

Predicate<T> принимает значение и возвращает boolean, метод у него test. s.contains("a") отвечает true, если в строке s есть кусок "a". Проверки склеиваются: and это «обе верны», or это «хотя бы одна», negate это «наоборот». Пример Корелина: в «banana» есть и a, и b, поэтому true. В «apple» нет b. В «cherry» нет b, но шесть букв, or даёт true.

Consumer и Supplier

import java.util.List;
import java.util.function.Consumer;
import java.util.function.Supplier;

public class Main {
    static int stockOrDefault(Integer stock, Supplier<Integer> fallback) {
        if (stock != null) {
            return stock;
        }
        return fallback.get();
    }

    public static void main(String[] args) {
        Consumer<String> printUpperCase = s -> System.out.println(s.toUpperCase());
        List<String> words = List.of("apple", "banana", "cherry");
        for (String w : words) {
            printUpperCase.accept(w);
        }
        words.forEach(printUpperCase);

        Supplier<String> greeting = () -> "Добрый вечер";
        System.out.println(greeting.get());

        System.out.println(stockOrDefault(25, () -> 0));
        System.out.println(stockOrDefault(null, () -> 0));
    }
}

Две новые записи до главного. List.of("apple", "banana", "cherry") сразу создаёт список из перечисленных значений. List это общий тип для списков, ArrayList один из них, поэтому со списком работает тот же цикл «для каждого». Параметр stock имеет тип Integer, а не int: объект может быть null, «остатка не знаем», а простое число int не может.

Consumer<T> принимает значение и ничего не возвращает, метод accept. Это действие: напечатать, сохранить. У списка есть forEach, он отдаёт каждый элемент такому действию, и цикл писать не надо. Supplier<T> ничего не принимает и выдаёт значение, метод get. Им передают «как получить запасное значение»: у Корелина остаток товара по умолчанию задан как () -> 0.

Четыре готовых интерфейса запомни парами. Function берёт и отдаёт. Predicate берёт и отвечает да или нет. Consumer только берёт. Supplier только отдаёт. Ещё есть Runnable: ничего не берёт и не отдаёт, просто запуск задачи.

Функция в параметре: пример лектора

Главный пример лекции, ProductService из seminar2. Товар ищут по номеру. Не нашли, тогда цену считает функция, которую передал вызывающий.

@FunctionalInterface
interface ItemNotFoundHandler {
    double handle(List<Product> items);
}

class ProductService {
    private final List<Product> products = new ArrayList<>();

    public void addProduct(Product p) {
        products.add(p);
    }

    public double getProductPriceOrDefault(int productId, ItemNotFoundHandler handler) {
        for (Product p : products) {
            if (p.getId() == productId) {
                return p.getPrice();
            }
        }
        return handler.handle(products);
    }
}

Класс Product с полями id, name, price и геттерами, товары как у лектора: Laptop 1500, Smartphone 800, Tablet 600, Smartwatch 200, Headphones 100, номера с 1 по 5. Конструктор Product(int id, String name, double price). Строки внутри main:

Stream, поток, это конвейер по элементам списка. stream() ставит список на конвейер. filter оставляет элементы, для которых предикат вернул true. map превращает каждый элемент функцией: товар в имя, цену в цену со скидкой. В конце элементы собирают обратно в список: toList() или collect(Collectors.toList()), для второго нужен import java.util.stream.Collectors;. Порядок элементов сохраняется.

Цикл с if и add делает то же, но цепочку читают как фразу: «из товаров отбери дороже 500, возьми имена, собери в список».
