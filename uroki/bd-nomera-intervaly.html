ROW_NUMBER() это оконная функция: она ставит каждой строке номер 1, 2, 3 и так далее. В каком порядке нумеровать, говорит ORDER BY внутри OVER ( ). Скобки после ROW_NUMBER всегда пустые.

Первое место у запуска, где число эпох вообще не записано. Это не ошибка базы, так PostgreSQL сортирует всегда.

При сортировке по убыванию DESC PostgreSQL ставит NULL первыми, по возрастанию последними: пустое для него «больше всех». NULLS LAST после DESC отправляет пустые в конец, NULLS FIRST в начало. Работает и в OVER, и в обычном ORDER BY.

ROUND средней и CASE по ней

Это нужно в задаче 1 практики про жюри: средняя оценка с округлением и слово «строгий» или «лояльный» по средней. У нас то же на исследователях: средняя всех оценок его запусков.

SELECT r.full_name,
       ROUND(AVG(m.mean_metric)::numeric, 2) AS srednyaya,
       CASE WHEN AVG(m.mean_metric) < 0.85 THEN 'слабее'
            ELSE 'сильнее'
       END AS uroven
FROM researchers r
JOIN experiments e ON e.researcher_id = r.id
JOIN metrics m     ON m.experiments_id = e.id
GROUP BY r.full_name;

ROUND(x, 2) округляет до двух знаков после точки, ROUND(x, 1) до одного. В PostgreSQL округление до знаков работает только для типа numeric, поэтому перед ним стоит ::numeric. Внутри CASE можно сравнивать агрегат, AVG(…), как обычное число.

У Степана шесть оценок: 0.787, 0.721, 0.835, 0.789, 0.874, 0.866. Сумма 4.872, делим на 6, выходит 0.812, округляем до 0.81. Это меньше 0.85, поэтому «слабее». Порядок строк может быть другим.
