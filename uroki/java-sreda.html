Среда разработки и первая программа

Java · лаба 8.09, конспект 01 · до всех ПР · около 40 минут

Самый первый урок по Java, до типов и if. Девять шагов: поставить JDK, собрать и запустить программу руками, завести проект в IntelliJ IDEA, читать сообщения об ошибках и остановить программу отладчиком на нужной строке. Это нужно на каждой лабе: половина времени уходит не на задачу, а на «почему не запускается».

Как проходить: читаешь шаг, решаешь «сделай сам» и только потом открываешь ответ. Все сообщения об ошибках в уроке настоящие, получены запуском на JDK 21.

Шаг 1 из 9

JDK: что ставить и как проверить

Чтобы писать на Java, на компьютере нужен JDK. Проверяют его в терминале, окне для текстовых команд: нажми Win+R, набери cmd и Enter. Две команды:

java -version
javac -version
openjdk version "21.0.12.1" 2026-08-18 LTS
OpenJDK Runtime Environment Temurin-21.0.12.1+1 (build 21.0.12.1+1-LTS)
OpenJDK 64-Bit Server VM Temurin-21.0.12.1+1 (build 21.0.12.1+1-LTS, mixed mode, sharing)
javac 21.0.12.1

JDK, набор разработчика, состоит из двух главных программ. javac это компилятор: он проверяет твой код и переводит его в байт-код. java это виртуальная машина JVM: она исполняет байт-код. Байт-код это команды не для процессора, а для JVM, поэтому одна программа идёт и на Windows, и на Linux.

Где взять: сайт adoptium.net, Temurin 21, Windows x64, JDK, файл .msi. При установке проверь, что включена «Add to PATH», и включи «Set JAVA_HOME»: она по умолчанию выключена. PATH это список папок, где Windows ищет программу по имени. Без него терминал не найдёт javac. Проще всего поставить JDK прямо из IDEA, это шаг 3.

Сделай сам. На компьютере в аудитории java -version отвечает версией, а javac -version пишет «не является внутренней или внешней командой». Что стоит на этом компьютере?
Показать ответСкрыть ответ

Стоит только JRE, среда для запуска готовых программ, без компилятора. Запускать чужие программы можно, собрать свою нельзя. Нужен полный JDK. Второй вариант: JDK поставили, но терминал открыт ещё до установки и не знает нового PATH. Открой новое окно терминала.

Проверить только java -version и решить, что всё стоит. Ошибка вылезет позже, на первой сборке.

JDK = javac (компилятор) + java (JVM, исполняет байт-код).

Проверка: обе команды -version отвечают версией.

Шаг 2 из 9

Собрать и запустить руками

Файл Main.java в папке C:\java:

public class Main {
    public static void main(String[] args) {
        System.out.println("Лаба 1 работает");
    }
}

Каркас пока не разбирай по словам, переписывай как есть. Первая строка заводит класс Main, вторая его метод main, а System.out.println("…") печатает текст из кавычек. По словам каркас разберём в уроке про типы и if.

В терминале команда cd переходит в папку, дальше две команды Java:

cd C:\java
javac Main.java
java Main
Лаба 1 работает

Две команды, два этапа. javac Main.java компилирует: рядом появляется файл Main.class с байт-кодом. java Main запускает: JVM берёт класс Main и выполняет его метод main. Метод main это точка входа, с его первой строки начинается любая программа.

Если ошибка в коде, javac скажет о ней и .class не создаст. Запускать тогда нечего. Есть короткий путь одной командой, java Main.java, он сам компилирует в памяти и запускает. На лабах всё равно работают в IDEA, но знать два этапа надо: так понятнее, какая ошибка откуда.

Сделай сам. После javac Main.java студент запускает java Main.class. Что будет?
Показать ответСкрыть ответ 
Error: Could not find or load main class Main.class
Caused by: java.lang.ClassNotFoundException: Main.class

Команде java нужно имя класса, а не имя файла. Она ищет класс с именем «Main.class» и не находит. Правильно java Main.

Путать, кому что давать. javac получает имя файла с .java, java получает имя класса без всякого расширения.

javac Main.java даёт Main.class, java Main запускает.

Программа начинается с первой строки метода main.

Шаг 5 из 9

Читать сообщение компилятора

Программа с ошибкой, в четвёртой строке нет точки с запятой. Строка int a = 7; заводит целое число a, равное 7, а println(a * 2) печатает удвоенное. Переменные подробно в следующем уроке.

public class Main {
    public static void main(String[] args) {
        int a = 7;
        System.out.println(a * 2)
        System.out.println("Готово");
    }
}
Main.java:4: error: ';' expected
        System.out.println(a * 2)
                                 ^
1 error

Сообщение компилятора читается слева направо: файл Main.java, номер строки 4, слово error, потом что не так. Ниже сама строка, а значок ^ показывает место, где компилятор споткнулся. Последняя строка говорит, сколько всего ошибок.

В IDEA та же ошибка видна дважды: строка подчёркнута красным ещё до запуска, а при запуске окно Build пишет java: ';' expected со ссылкой на строку. Чинить всегда с первой ошибки в списке. Одна пропущенная скобка часто даёт ещё несколько ошибок ниже, и они исчезают сами.

Сделай сам. Что сломано и в какой строке? Сначала найди глазами, потом открой ответ. 
public class Main {
    public static void main(String[] args) {
        System.out.println("Первая строка");
        System.out.println("Вторая строка);
    }
}
Показать ответСкрыть ответ 
Main.java:4: error: unclosed string literal
        System.out.println("Вторая строка);
                           ^
1 error

«Незакрытая строка» в строке 4: после слова строка нет закрывающей кавычки. Значок стоит на открывающей кавычке, откуда строка началась. Правильно "Вторая строка");.

Искать ошибку там, где стоит ^, буквально. Значок показывает, где компилятор понял, что что-то не так. Сама причина может быть чуть левее или в конце той же строки.

Файл:строка: error: что не так, ниже строка и ^.

Чини с первой ошибки, остальные часто уходят сами.

Шаг 6 из 9

cannot find symbol: опечатка в имени

Самая частая ошибка на лабах. Переменная называется total, а напечатать пытаемся totl:

public class Main {
    public static void main(String[] args) {
        int total = 5;
        System.out.println(totl);
    }
}
Main.java:4: error: cannot find symbol
        System.out.println(totl);
                           ^
  symbol:   variable totl
  location: class Main
1 error

cannot find symbol значит «не знаю такого имени». Две строки ниже уточняют: symbol что именно не найдено, здесь переменная totl, а location где искали, в классе Main. Причин три. Опечатка. Переменная заведена внутри других фигурных скобок и отсюда не видна. Забыт import, строка в начале файла, которая подключает готовый класс, о ней шаг 9.

Java различает большие и маленькие буквы. Total и total это два разных имени.

Сделай сам. Студент написал system.out.println("Привет"); с маленькой s. Что скажет компилятор?
Показать ответСкрыть ответ 
Main.java:3: error: package system does not exist
        system.out.println("Привет");
              ^
1 error

Не cannot find symbol, а «пакета system не существует». Компилятор не нашёл класса system и решил, что это имя пакета, то есть папки с классами. Класс называется System с большой буквы.

Ждать дословно знакомое сообщение. Текст бывает разный, а причина одна и та же: имя написано не так. Сначала проверь буквы и регистр.

cannot find symbol: смотри строку symbol, там неизвестное имя.

Регистр важен: System, не system.

Шаг 7 из 9

Ошибка во время работы: исключение

Эта программа компилируется без ошибок. Падает она уже при запуске:

public class Main {
    public static void main(String[] args) {
        int apples = 10;
        int people = 0;
        System.out.println("Делим яблоки");
        System.out.println(apples / people);
        System.out.println("Конец");
    }
}
Делим яблоки
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Main.main(Main.java:6)

Исключение это ошибка, которая случилась во время работы программы. Компилятор её не видит, ведь код написан правильно, просто данные плохие. Программа останавливается на этой строке, дальше не идёт: «Конец» не напечатан. В IDEA код выхода будет 1, а не 0.

Читать так: тип исключения ArithmeticException, «арифметическая ошибка», пояснение / by zero, «деление на ноль». Строка at Main.main(Main.java:6) говорит, где: метод main класса Main, файл Main.java, строка 6. В IDEA Main.java:6 синяя, по ней можно нажать и перейти к строке.

Сделай сам. Ошибка компиляции или исключение? Разложи: пропущена ;, деление на ноль, опечатка в имени переменной, ввели буквы там, где программа ждала число.
Показать ответСкрыть ответ

Компиляция: пропущенная ; и опечатка в имени. Их видно по тексту программы, она даже не запустится. Исключения: деление на ноль и буквы вместо числа. Это зависит от данных, программа запустится и упадёт по ходу.

Думать, что раз программа собралась, она верная. Сборка проверяет только запись. Деление на ноль и плохой ввод ловятся только запуском на разных данных.

Исключение: программа собралась, но упала при запуске.

Читай тип, пояснение и строку at …(Main.java:N).

Шаг 8 из 9

Отладчик: остановиться и посмотреть переменные

Программа должна сложить 1 + 2 + 3 + 4 = 10, но печатает другое. Ошибки нет, просто ответ неверный.

public class Main {
    public static void main(String[] args) {
        int sum = 0;
        for (int i = 1; i < 4; i++) {
            sum += i;
        }
        System.out.println("Сумма от 1 до 4: " + sum);
    }
}
Сумма от 1 до 4: 6

Отладчик запускает программу и останавливает её на точке останова, чтобы посмотреть значения переменных. Точку ставят кликом по полю слева от номера строки, появляется красный кружок. Запуск не Run, а Debug: значок жука рядом с треугольником или Shift+F9.

Поставь точку на строку sum += i; и запусти Debug. Программа встанет на ней, внизу окно Variables покажет i и sum. F9 (Resume) едет до следующей остановки. F8 (Step Over) делает ровно одну строку.

Цикл for подробно разберём в уроке про циклы. Пока хватит такого чтения: i начинается с 1, после каждого круга растёт на 1, и строка sum += i; повторяется, пока верно условие i < 4. Сама строка sum += i прибавляет i к sum.

Сделай сам. Точка останова на sum += i;, жмёшь F9 после каждой остановки. Сколько раз программа встанет и какие i и sum покажет каждый раз? Где ошибка?
Показать ответСкрыть ответ

Три остановки. Окно показывает значения до выполнения строки: i = 1, sum = 0, потом i = 2, sum = 1, потом i = 3, sum = 3. Четвёртой остановки с i = 4 нет, цикл кончился раньше. Условие i < 4 не пускает четвёрку. Нужно i <= 4, тогда ответ 10.

Думать, что на остановке строка уже выполнена. Отладчик стоит перед строкой: на первой остановке sum ещё 0, а не 1.

Точка останова: клик слева от номера строки. Запуск Debug, Shift+F9.

F8 одна строка, F9 до следующей точки. Значения в окне Variables.
