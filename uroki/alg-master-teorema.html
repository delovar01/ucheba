Рекурренты, мастер-теорема и нижняя граница сортировки

Алгоритмы · лекция 17.09, вторая половина · под ПР1 «Анализ сложности» · около 50 минут

Вторая половина лекции 17.09. В прошлом уроке сложность считали по циклам. Теперь функции, которые вызывают сами себя: для них сначала пишут формулу через саму себя, а потом её решают. В конце узнаешь, почему сортировать сравнениями быстрее n log n нельзя в принципе. Девять шагов.

Как проходить: читаешь шаг, переписываешь рамку «Перепиши в тетрадь», решаешь «сделай сам» на бумаге и только потом открываешь ответ. Если в шаге что-то непонятно, дальше не иди: сначала задай вопрос по этому шагу.

Шаг 1 из 9

Рекуррентное соотношение

Сначала одна вещь из программирования: функция может вызывать сама себя на задаче поменьше. Например, сумма 1 + 2 + … + n:

def s(n):
    if n == 0: return 0       # самая маленькая задача, ответ сразу
    return n + s(n - 1)       # та же задача, но на единицу меньше

s(3) вызовет s(2), та вызовет s(1), потом s(0) = 0, и ответы сложатся: 1, 3, 6. Такой приём называют рекурсией, подробно он в уроке про рекурсию. Здесь хватит идеи: функция решает задачу через себя же на куске поменьше.

Сортировка слиянием: делим массив пополам, сортируем каждую половину этой же функцией, потом сливаем две отсортированные половины в одну. Слияние идёт одним проходом: каждый раз берём меньший из двух первых элементов, это n операций.

Сколько стоит сортировка n элементов? Две сортировки по n/2 плюс слияние за n. Записываем это прямо так.

Рекуррентное соотношение, коротко рекуррента, это запись T(n) через T от меньших чисел. Для слияния T(n) = 2T(n/2) + n, и ещё нужна база, например T(1) = 1.

Как читать запись aT(n/b) + f(n): функция вызывает себя a раз, каждый раз на куске в b раз меньше, и сверх вызовов делает f(n) своей работы. Бинарный поиск смотрит в середину и идёт в одну половину: T(n) = T(n/2) + 1.

Сделай сам. Напиши рекурренту для возведения в степень. Функция power(a, n) считает aⁿ и пользуется тем, что aⁿ = a^(n/2) · a^(n/2). Значок ^ значит степень. Вариант 1 считает half = power(a, n/2) один раз и возвращает half * half. Вариант 2 возвращает power(a, n/2) * power(a, n/2).
Показать ответСкрыть ответ

Вариант 1: T(n) = T(n/2) + 1, один вызов и одно умножение. Вариант 2: T(n) = 2T(n/2) + 1, два вызова. В шаге 6 увидишь, что первый стоит log n, а второй n.

Считать варианты одинаковыми, «ведь результат тот же». Результат тот же, но во втором одно и то же считается дважды, и на каждом уровне вызовов вдвое больше.

Рекуррента: T(n) через T от меньших + база.

aT(n/b) + f(n): a вызовов, кусок в b раз меньше, f своя работа. Слияние 2T(n/2) + n, бинпоиск T(n/2) + 1.

Шаг 2 из 9

Раскрутка: когда задача уменьшается на единицу

Бывает, что функция отрезает от задачи один элемент: T(n) = T(n − 1) + n, T(1) = 1. Так ведёт себя быстрая сортировка, когда ей не везёт с разбиением.

Подставляем формулу в саму себя, пока не дойдём до базы:

T(n) = n + T(n − 1) = n + (n − 1) + T(n − 2) = … = n + (n − 1) + … + 2 + 1

Раскрутка: подставляем рекурренту в саму себя до базы и складываем то, что накопилось. Здесь вышла сумма n(n + 1)/2 = Θ(n²).

Проверка на числах: T(1) = 1, T(2) = 3, T(3) = 6, T(4) = 10, T(5) = 15 = 5 · 6 / 2.

Сделай сам. Ханойские башни, головоломка про перекладывание n дисков. Чтобы решить, хватит её формулы: T(n) = 2T(n − 1) + 1, T(1) = 1. Посчитай T(2), T(3), T(4), угадай формулу и найди T(10).

Ответить Θ(n), потому что «задача уменьшается на один, как в примере». Важно ещё, сколько вызовов: здесь их два, и на каждом уровне число вызовов удваивается.

Раскрутка: подставляю в себя до базы, складываю.

T(n − 1) + n → Θ(n²), 2T(n − 1) + 1 → 2ⁿ − 1.

Шаг 3 из 9

Дерево рекурсии

Для деления пополам раскрутка путается. Нарисуем вызовы деревом для T(n) = 2T(n/2) + n: каждый вызов это узел, рядом пишем его собственную работу.

уровень 0:            n                → n
уровень 1:       n/2      n/2          → n
уровень 2:    n/4  n/4  n/4  n/4       → n
…
листья:       1 1 1 … 1  (n штук)      → n

Дерево рекурсии: узел это вызов, у узла пишем работу без учёта вложенных вызовов. T(n) равно сумме всех узлов. Удобно складывать по уровням.

Здесь на уровне i ровно 2ⁱ узлов по n/2ⁱ, сумма уровня n. Уровней log₂ n + 1, потому что n делится пополам до 1. Итого n(log₂ n + 1) = Θ(n log n).

Проверка на n = 8: T(1) = 1, T(2) = 2 + 2 = 4, T(4) = 8 + 4 = 12, T(8) = 24 + 8 = 32. А формула даёт 8 · (3 + 1) = 32.

Сделай сам. По той же формуле найди T(16) и проверь его по рекурренте через T(8) = 32.
Показать ответСкрыть ответ

Формула: 16 · (4 + 1) = 80. Рекуррента: 2 · 32 + 16 = 80.

Забыть уровень листьев и написать n · log₂ n = 64. Уровней на один больше, чем делений пополам. Для Θ это не важно, а для точного числа важно.

Дерево: узел = вызов, у узла его работа. T(n) = сумма по уровням.

2T(n/2) + n: каждый уровень n, уровней log₂ n + 1 → Θ(n log n).

Шаг 4 из 9

Где сидит работа: в корне или в листьях

В шаге 3 все уровни стоили одинаково. Так бывает не всегда.

T(n) = 2T(n/2) + n². Уровень i: 2ⁱ узлов по (n/2ⁱ)², сумма n²/2ⁱ. Уровни стоят n², n²/2, n²/4, … Это геометрическая сумма, она меньше удвоенного первого члена: T(n) < 2n². Почти вся работа в корне, ответ Θ(n²).

T(n) = 4T(n/2) + n. Уровень i: 4ⁱ узлов по n/2ⁱ, сумма 2ⁱ · n. Уровни растут: n, 2n, 4n, … Теперь самый тяжёлый последний уровень, листья. Уровней log₂ n, и на каждом узлов вчетверо больше, поэтому листьев 4^(log₂ n). Перепишем 4 как 2²: 4^(log₂ n) = (2^(log₂ n))² = n², потому что 2^(log₂ n) = n по смыслу логарифма. Ответ Θ(n²).

Суммы уровней убывают в одно и то же число раз: правит корень, ответ Θ(f(n)). Равны: Θ(f(n) · log n). Растут: правят листья, ответ равен числу листьев.

Сделай сам. T(n) = 3T(n/2) + n. Чему равна сумма уровня i? Кто правит: корень, все поровну или листья?
Показать ответСкрыть ответ

Уровень i: 3ⁱ узлов по n/2ⁱ, сумма (3/2)ⁱ · n. Растёт в 1.5 раза с каждым уровнем, значит правят листья. Сколько их, посчитаем в следующем шаге.

Смотреть только на корень и ответить Θ(n), «ведь работа f = n». Работа одного вызова маленькая, но вызовов втрое больше на каждом уровне, и внизу их сумма обгоняет корень.

Уровни убывают → корень, Θ(f). Равны → Θ(f log n). Растут → листья.

Шаг 5 из 9

Число листьев: n в степени log_b a

У дерева для aT(n/b) + f(n) на каждом уровне вызовов в a раз больше, а уровней log_b n: столько раз n делится на b до 1. Запись log_b n значит логарифм n по основанию b, например log_3 9 = 2. Значит листьев a^(log_b n).

Такую запись переводят в степень n по правилу из шага 11 матана: a^(log_b n) = n^(log_b a).

У дерева aT(n/b) + f(n) листьев n^(log_b a). Это число называют критической функцией, с ним сравнивают f(n).

Примеры: 4T(n/2) даёт n^(log₂ 4) = n² листьев. 2T(n/2) даёт n¹ = n. 3T(n/2) даёт n^(log₂ 3) ≈ n^1.585. T(n/2) даёт n⁰ = 1, дерево без ветвлений.

Сделай сам. Сколько листьев у 8T(n/2), 9T(n/3) и 2T(n/4)?
Показать ответСкрыть ответ

n^(log₂ 8) = n³. n^(log₃ 9) = n². n^(log₄ 2) = n^½ = √n, потому что 4^½ = 2.

Перепутать a и b и написать n^(log_a b). Для 2T(n/4) вышло бы n² вместо √n. Под логарифмом число вызовов a, основание это во сколько раз уменьшается кусок, b.

Листьев у aT(n/b): a^(log_b n) = n^(log_b a).

Глубина дерева log_b n.

Шаг 6 из 9

Мастер-теорема

Шаги 4 и 5 вместе дают готовый ответ без рисования. Сравниваем работу корня f(n) с числом листьев n^(log_b a).

Мастер-теорема для T(n) = aT(n/b) + f(n), где a ≥ 1, b > 1. Случай 1: f меньше листьев хотя бы в n^ε раз при каком-то ε > 0, ответ Θ(n^(log_b a)). Случай 2: f равно листьям по порядку, ответ Θ(n^(log_b a) · log n). Случай 3: f больше листьев хотя бы в n^ε раз, ответ Θ(f(n)).

ε («эпсилон») значит «какое-то положительное число, пусть маленькое». «Меньше в n^ε раз» значит меньше по степени, а не на логарифм.

Шаг 7 из 9

Когда мастер-теорема молчит

У случая 3 есть ещё условие регулярности: a · f(n/b) ≤ c · f(n) с каким-то c < 1. По-простому: суммы уровней правда убывают. Для 4T(n/2) + n³: 4 · (n/2)³ = ½n³, c = ½, условие выполнено. Для обычных степеней n оно выполняется само.

Мастер-теорема не применима в четырёх случаях. Задача уменьшается вычитанием, как T(n − 1). Куски разного размера, как T(n/3) + T(2n/3). Число вызовов a не постоянное. Или f отличается от числа листьев только в log n раз.

Последний случай самый коварный. 2T(n/2) + n log n: листьев n, а f больше в log n раз. Это меньше, чем n^ε при любом ε, так что ни случай 2, ни случай 3. Тогда складываем уровни дерева руками, логарифм тут по основанию 2.

  1. На уровне i стоят 2ⁱ узлов, у каждого кусок n/2ⁱ, и работа узла (n/2ⁱ) · log(n/2ⁱ).
  2. Логарифм дроби: log(n/2ⁱ) = log n − i. Умножаем на число узлов: уровень стоит 2ⁱ · (n/2ⁱ) · (log n − i) = n(log n − i).
  3. Складываем уровни i = 0, 1, …, log n − 1: n · (log n + (log n − 1) + … + 1) = n · log n · (log n + 1) / 2. Это сумма 1 + 2 + … + k из прошлого урока.
  4. Итого Θ(n log² n). Запись log² n значит log n · log n.

Для кусков разного размера на лекции была теорема Акра–Бацци. T(n/3) + T(2n/3) + n там решается за Θ(n log n): куски в сумме дают n, и каждый полный уровень дерева стоит n. Самая длинная ветка идёт по кускам 2n/3, уровней около log n, отсюда n log n.

Показать ответСкрыть ответ

а) Листьев n^(log₄ 3) ≈ n^0.79, f = n² больше по степени. Регулярность: 3 · (n/4)² = 3/16 · n², c = 3/16 < 1. Случай 3, Θ(n²). б) Вычитание, теорема молчит. Раскрутка: 1 + 1 + … + 1 = n, Θ(n). в) f меньше листьев n только в log n раз, это дыра между случаями 1 и 2.

В пункте в выбрать случай 1, «ведь n / log n меньше n». Для случая 1 нужно меньше в n^ε раз, а log n растёт медленнее любой степени n.

Шаг 8 из 9

Дерево решений: нижняя граница сортировки

Слияние сортирует за n log n. Можно ли быстрее, если элементы только сравнивать? Ответ с лекции: нельзя. Это утверждение не про один алгоритм, а про все сразу.

Любую сортировку сравнениями можно нарисовать деревом решений. В узле сравнение «x₁ < x₂?», две ветки «да» и «нет», в листе готовый порядок. Для трёх элементов:

x1<x2 ?
├─да─ x2<x3 ?
│     ├─да── x1<x2<x3
│     └─нет─ x1<x3 ?
│           ├─да── x1<x3<x2
│           └─нет─ x3<x1<x2
└─нет─ x1<x3 ?
      ├─да── x2<x1<x3
      └─нет─ x2<x3 ?
            ├─да── x2<x3<x1
            └─нет─ x3<x2<x1

Разных порядков трёх элементов 3! = 6, и у каждого должен быть свой лист, иначе на одном из входов алгоритм ошибётся. Высота дерева это самый длинный путь, то есть число сравнений в худшем случае. Дерево бинарное, у каждого узла не больше двух веток. Поэтому с каждым уровнем узлов становится не больше чем вдвое больше: 1, 2, 4, …, и в дереве высоты h листьев не больше 2ʰ.

Листьев не меньше n! и не больше 2ʰ. Значит 2ʰ ≥ n!, и h ≥ log₂ n!. Любая сортировка сравнениями делает в худшем случае не меньше ⌈log₂ n!⌉ сравнений.

Для трёх: log₂ 6 ≈ 2.58, округляем вверх, 3. В дереве выше так и есть.

Сделай сам. Не меньше скольких сравнений нужно в худшем случае, чтобы отсортировать 4 элемента? А 5? Подсказка: 2⁴ = 16, 2⁵ = 32, 2⁷ = 128.
Показать ответСкрыть ответ

4 элемента: 4! = 24. 2⁴ = 16 < 24 ≤ 32 = 2⁵, значит 5 сравнений. 5 элементов: 5! = 120, 64 < 120 ≤ 128, значит 7.

Считать, что граница это log₂ n, то есть 2 для четырёх элементов. Листья это не элементы, а все их порядки, их n!.

Дерево решений: узел = сравнение, лист = порядок. Листьев ≥ n!, ≤ 2ʰ.

Сравнений в худшем ≥ ⌈log₂ n!⌉.

Шаг 9 из 9

log₂ n! растёт как n log n

Осталось понять, что такое log₂ n! по порядку. Оценим n! сверху и снизу.

Сверху: n! = 1 · 2 · … · n ≤ n · n · … · n = nⁿ. По правилу log(x^k) = k log x из шага 2 матана: log₂ n! ≤ n log₂ n.

Снизу: в произведении n! верхняя половина множителей, от n/2 до n, каждый не меньше n/2. Их n/2 штук. Значит n! ≥ (n/2)^(n/2) и log₂ n! ≥ (n/2) · log₂(n/2).

Почему низ тоже порядка n log n. log₂(n/2) = log₂ n − 1. При n ≥ 4 единица не больше половины log₂ n, поэтому log₂ n − 1 ≥ ½ log₂ n. Тогда (n/2) · log₂(n/2) ≥ (n/2) · ½ log₂ n = ¼ n log₂ n. Сверху n log₂ n, снизу ¼ n log₂ n, это Θ по определению из прошлого урока.

log₂ n! = Θ(n log n). Поэтому сортировка сравнениями не бывает быстрее n log n, а слияние с его Θ(n log n) оптимально.

На числах при n = 8: 8! = 40 320, log₂ 40 320 ≈ 15.3. Сверху 8 · 3 = 24, снизу 4 · 2 = 8. Число зажато между ними.

Граница только для сравнений. Сортировка подсчётом использует само число как номер ячейки массива и обходит n log n. Это тема ПР2.

Сделай сам. Не меньше скольких сравнений нужно для 10 элементов? 10! = 3 628 800, 2²¹ = 2 097 152, 2²² = 4 194 304. Сравни с n log₂ n при n = 10.
Показать ответСкрыть ответ

2²¹ < 10! ≤ 2²², значит не меньше 22 сравнений. n log₂ n = 10 · 3.32 ≈ 33. Граница 22 меньше, но того же порядка: верхняя оценка n log n, нижняя (n/2) log(n/2) = 5 · 2.32 ≈ 12.

Думать, что граница запрещает любую быструю сортировку. Она запрещает только сортировки, которые узнают порядок одними сравнениями. Подсчёт и поразрядная сортировка устроены иначе.

(n/2)^(n/2) ≤ n! ≤ nⁿ → log₂ n! = Θ(n log n).

Сортировка сравнениями Ω(n log n), слияние оптимально.

1. Раскруткой реши T(n) = T(n − 1) + 2, T(1) = 0. Найди точную формулу и Θ.
2. Нарисуй дерево для T(n) = 2T(n/2) + 1, T(1) = 1. Сколько узлов на уровне i, чему равна сумма всех уровней при n = 8?
3. Мастер-теорема: а) 9T(n/3) + n, б) T(2n/3) + 1, в) 3T(n/3) + n, г) 2T(n/2) + n². Для каждой: число листьев, случай, ответ. В пункте б кусок 2n/3 = n / (3/2), то есть b = 3/2, а a = 1.
4. Почему мастер-теорема не решает T(n) = 4T(n/2) + n² log n? Чему, по-твоему, равен ответ, если сложить уровни дерева? Действуй как в шаге 7 с 2T(n/2) + n log n.
5. Сколько сравнений минимум нужно в худшем случае, чтобы отсортировать 6 элементов? 6! = 720.

Ответы сохраняются на этом телефоне, можно закрыть страницу и вернуться.
