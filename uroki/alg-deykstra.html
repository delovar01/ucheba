Алгоритм Дейкстры: кратчайшие пути с весами

Алгоритмы · лекция 5.10 и лаба 10.10 · под ПР3 «Графы» · около 45 минут

Вторая часть графов с лекции 5.10 и лабы 10.10. В прошлом уроке BFS искал путь с наименьшим числом рёбер. Теперь у дорог есть длина, и нужен путь с наименьшей суммой длин. Так работает навигатор. Восемь шагов.

Как проходить: читаешь шаг, переписываешь рамку «Перепиши в тетрадь», решаешь «сделай сам» на бумаге и только потом открываешь ответ. Таблицу Дейкстры веди в тетради строка за строкой. Если в шаге что-то непонятно, дальше не иди: сначала задай вопрос по этому шагу.

Шаг 1 из 8

Взвешенный граф: BFS здесь врёт

Пример с лекции. Дороги с односторонним движением и длиной: A→B 4, A→C 1, C→B 2, B→D 1, C→D 5, D→E 3.

      4
  A ─────→ B ──1──→ D ──3──→ E
  │        ↑        ↑
  1        2        │
  ↓        │        │
  C ───────┘        │
  └────────5────────┘

BFS скажет, что до B один шаг, прямая дорога A→B. Но её длина 4, а путь A→C→B длиной 1 + 2 = 3. Меньше рёбер не значит короче.

Во взвешенном графе у каждого ребра есть вес, здесь длина. Длина пути это сумма весов его рёбер. Кратчайший путь это путь с наименьшей длиной, и BFS его не находит.

Сделай сам. Выпиши все пути из A в D и их длины. Какой кратчайший? Сколько в нём рёбер?
Показать ответСкрыть ответ

A→B→D: 4 + 1 = 5. A→C→D: 1 + 5 = 6. A→C→B→D: 1 + 2 + 1 = 4. Кратчайший последний, длина 4, в нём три ребра, больше всех.

Пропустить путь A→C→B→D, потому что он «длинный» по числу рёбер. Перебирая пути руками, легко потерять самый выгодный. Поэтому нужен алгоритм.

Взвешенный граф: длина пути = сумма весов. Меньше рёбер ≠ короче, BFS не годится.

Шаг 2 из 8

Релаксация ребра

Будем хранить для каждой вершины лучшую известную длину пути из A, массив dist. Сначала dist[A] = 0, остальные ∞, бесконечность, «пока пути не знаем».

Посмотрели рёбра из A: dist[B] = 4, dist[C] = 1. Теперь ребро C→B длиной 2. Если идти в B через C, выйдет dist[C] + 2 = 3. Это меньше 4, значит запоминаем 3.

Релаксация ребра u→v с весом w: если dist[u] + w < dist[v], то dist[v] = dist[u] + w. Нашли через u путь короче, чем знали, и обновили.

Релаксация никогда не делает ответ хуже: dist только уменьшается. Вопрос в том, в каком порядке релаксировать рёбра, чтобы быстро дойти до точных расстояний. Это и решает Дейкстра.

Сделай сам. Сейчас dist[C] = 1, dist[D] = 5. Релаксируем ребро C→D весом 5. Что станет с dist[D]? А если бы dist[D] был ∞?
Показать ответСкрыть ответ

1 + 5 = 6, это не меньше 5, dist[D] остаётся 5. Если бы было ∞, стало бы 6: любое число меньше бесконечности.

Обновлять всегда, без сравнения: dist[v] = dist[u] + w. Тогда D получит 6, и хороший путь длиной 5 забудется. Обновляют только когда стало короче.

Релаксация u→v, вес w: если dist[u] + w < dist[v], то dist[v] = dist[u] + w.

Старт: dist[s] = 0, остальные ∞.

Шаг 3 из 8

Идея Дейкстры: фиксировать ближайшую

После первого шага dist[C] = 1, dist[B] = 4, остальные ∞. Может ли до C найтись путь короче 1? Любой другой путь в C выходит из A через другое ребро, а самое короткое ребро из A как раз до C. Дальше веса только прибавляются, и меньше 1 не выйдет.

Алгоритм Дейкстры: среди ещё не зафиксированных вершин берём ту, у которой dist меньше всех, объявляем её расстояние окончательным и релаксируем все рёбра из неё. Повторяем, пока вершины не кончатся.

Почему выбранная вершина u правда готова. Возьмём любой другой путь из старта в u. Где-то он впервые выходит за зафиксированные вершины, в какую-то вершину x. До x он стоит не меньше dist[x], а dist[x] не меньше dist[u], ведь u выбрали как наименьшую. Дальше от x до u веса не отрицательные, длина может только расти. Значит этот путь не короче dist[u]. Это рассуждение держится на одном условии: все веса ≥ 0. Без него алгоритм ломается, это шаг 8.

Сделай сам. Почему после фиксации C нельзя сразу зафиксировать и B с dist[B] = 4?
Показать ответСкрыть ответ

Из C ещё не релаксировали рёбра. Ребро C→B даст 1 + 2 = 3. Фиксируем по одной вершине и только после релаксации рёбер из предыдущей.

Фиксировать вершины в порядке, в каком до них дошли, как в BFS. Дейкстра выбирает по наименьшему dist, а не по времени появления.

Дейкстра: берём нефиксированную с min dist → фиксируем → релаксируем её рёбра. Повтор.

Работает только при весах ≥ 0.

Шаг 5 из 8

Дейкстра на Java: массив, O(n²)

Вершины A–E нумеруем 0–4. Граф храним матрицей весов: int[][] w это двумерный массив, w[u][v] длина ребра u→v, или −1, если ребра нет. w.length число строк, то есть вершин. done отмечает зафиксированные вершины.

static int[] dijkstra(int[][] w, int s) {
    int n = w.length;
    int[] dist = new int[n];
    boolean[] done = new boolean[n];
    Arrays.fill(dist, Integer.MAX_VALUE);    // ∞
    dist[s] = 0;
    for (int k = 0; k < n; k++) {
        int u = -1;                           // ищем ближайшую нефиксированную
        for (int v = 0; v < n; v++)
            if (!done[v] && (u == -1 || dist[v] < dist[u])) u = v;
        if (dist[u] == Integer.MAX_VALUE) break;   // остальные недостижимы
        done[u] = true;
        for (int v = 0; v < n; v++)                // релаксация
            if (w[u][v] >= 0 && dist[u] + w[u][v] < dist[v])
                dist[v] = dist[u] + w[u][v];
    }
    return dist;
}

Дейкстра на массиве: n раз ищем минимум за n и релаксируем строку матрицы за n. Итого O(n²). Так он записан на слайдах лекции.

Integer.MAX_VALUE самое большое int, оно играет роль ∞. Строка с break нужна не только для скорости: прибавить вес к MAX_VALUE значит переполнить int, это ловушка из шага 2 урока про Java. Для примера вернётся [0, 3, 1, 4, 7].

Сделай сам. Сколько примерно операций сделает эта версия на графе из 10 000 вершин? И почему без строки с break на графе с недостижимой вершиной может выйти неверный ответ?
Показать ответСкрыть ответ

n² = 10⁸, около секунды на Java. Без break выбрали бы вершину с dist = MAX_VALUE, и MAX_VALUE + 5 переполнится в большое отрицательное число. Оно меньше любого dist, и соседи получат отрицательные расстояния.

Брать в поиске минимума и зафиксированные вершины. Тогда снова и снова выбирается старт с dist = 0, и алгоритм никуда не двигается. Проверка !done[v] обязательна.

Массив: n раз (поиск min за n + релаксация за n) → O(n²).

∞ = Integer.MAX_VALUE, недостижимую не трогаю, иначе переполнение.

Шаг 6 из 8

Восстановить путь

Как в лабиринте из прошлого урока: при каждом удачном обновлении запоминаем, откуда пришли.

// в релаксации, рядом с dist[v] = …
prev[v] = u;

Для примера из шага 4 prev такой: B ← C, C ← A, D ← B, E ← D. Идём от E назад: E ← D ← B ← C ← A, разворачиваем: A → C → B → D → E, длина 1 + 2 + 1 + 3 = 7.

Предок вершины в Дейкстре перезаписывается при каждом улучшении. Окончательный предок тот, что был при последнем обновлении перед фиксацией. Путь восстанавливают от финиша по предкам и разворачивают.

У D предок сначала был C, на шаге 2 таблицы, потом стал B, на шаге 3. Остался B, потому что путь через B короче.

Сделай сам. В графе из «сделай сам» шага 4 восстанови путь из 1 в 5. Какой предок у 5 и у 6?
Показать ответСкрыть ответ

5 получила 20 от 6. Через 4 вышло бы 20 + 6 = 26, это не короче, обновления нет. Предок 5 это 6, у 6 предок 3, у 3 предок 1. Путь 1 → 3 → 6 → 5, длина 9 + 2 + 9 = 20.

Брать предком первую вершину, из которой вообще дошли. У 6 первым предком была 1 с длиной 14, но потом через 3 нашлось 11, и предок сменился на 3.

prev[v] = u при каждом улучшении. Путь: от финиша по prev, развернуть.

Шаг 7 из 8

Дейкстра с кучей

Дорогая часть массивной версии это поиск минимума за n на каждом шаге. Достать минимум быстро умеет очередь с приоритетом из урока про кучи. В Java это PriorityQueue.

// g.get(u) список рёбер из u, ребро int[]{сосед, вес}
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.add(new int[]{0, s});                  // {расстояние, вершина}
while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int d = top[0], u = top[1];
    if (d > dist[u]) continue;            // устаревшая запись
    for (int[] e : g.get(u)) {
        int v = e[0], len = e[1];
        if (d + len < dist[v]) {
            dist[v] = d + len;
            pq.add(new int[]{dist[v], v});
        }
    }
}

Здесь граф хранится списками, как в прошлом уроке, только в списке u лежат не номера соседей, а пары «сосед, вес». Массив dist заранее заполнен Integer.MAX_VALUE, а dist[s] = 0, как в шаге 5. В куче лежат пары {расстояние, вершина}, poll достаёт пару с наименьшим расстоянием.

Запись со стрелкой (a, b) -> a[0] - b[0] это короткая функция прямо внутри вызова: получает две пары a и b и возвращает разность их первых чисел. Если разность отрицательная, a считается меньше. Так куча узнаёт, что сравнивать надо по расстоянию. Старую запись вершины из кучи не удаляют, просто кладут новую, покороче. Когда достанут старую, строка с continue её пропустит.

С двоичной кучей Дейкстра стоит O((n + m) log n): каждое ребро может положить запись в кучу за log. В куче бывает до m записей, но рёбер не больше n², поэтому log m ≤ log n² = 2 log n, и это тот же O(log n). На графах, где рёбер мало, это намного быстрее n².

Сделай сам. n = 10 000 вершин, m = 30 000 рёбер. Сравни n² и (n + m) log₂ n. log₂ 10⁴ ≈ 13.3. А если граф полный, рёбер около n²?
Показать ответСкрыть ответ

n² = 10⁸. (10⁴ + 3 · 10⁴) · 13.3 ≈ 5.3 · 10⁵, почти в 200 раз меньше. Для полного графа m ≈ n², и куча даёт n² log n, хуже массива. Тогда берут массивную версию.

Считать, что с кучей всегда лучше. Куча выигрывает только когда рёбер намного меньше n². На плотном графе лишний log n на каждое ребро делает её медленнее.

С кучей: O((n + m) log n), на массиве O(n²). Рёбер мало → куча, граф плотный → массив.

Устаревшую запись пропускаю: if (d > dist[u]) continue.

Шаг 8 из 8

Отрицательные веса ломают Дейкстру

Рёбра: S→A 4, S→B 5, B→A −3, A→C 2. Отрицательный вес бывает, например, если ребро это не расстояние, а расход, и на каком-то участке получаешь деньги назад.

  1. Фиксируем S: A = 4, B = 5.
  2. Фиксируем A, она ближе: C = 6.
  3. Фиксируем B: ребро B→A даёт 5 − 3 = 2 < 4. Но A уже зафиксирована, и C от неё уже посчитана.

Дейкстра ответит A = 4, C = 6. Правильно A = 2 через B, и C = 4.

Дейкстра верна, только если все веса не отрицательные. С отрицательными весами путь через дальнюю вершину может оказаться короче, и зафиксированное расстояние уже не исправить. Для них на лекции был алгоритм Форда–Беллмана, O(n · m).

Сделай сам. Одногруппник предлагает: «прибавим ко всем весам 3, отрицательных не станет, и запустим Дейкстру». Проверь на этом графе. Какой путь до A он найдёт?
Показать ответСкрыть ответ

Новые веса: S→A 7, S→B 8, B→A 0, A→C 5. Путь S→A теперь 7, а S→B→A стал 8 + 0 = 8. Дейкстра честно найдёт S→A, и это неверный путь для исходного графа: там S→B→A длиной 2 короче S→A длиной 4.

Думать, что прибавка ко всем рёбрам ничего не меняет. Она прибавляет 3 к каждому ребру пути, и пути из многих рёбер дорожают сильнее, чем короткие. Порядок путей ломается.

Дейкстра только при весах ≥ 0. Отрицательные → Форд–Беллман, O(nm).

Прибавить ко всем весам число нельзя, это меняет кратчайший путь.
