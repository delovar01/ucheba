Шаг 1 из 11

CREATE DATABASE и активная база в DBeaver

Открой SQL-редактор на подключении к PostgreSQL и выполни:

CREATE DATABASE probnaya;

CREATE DATABASE имя создаёт пустую базу. Это команда части SQL, которая строит устройство базы, она называется DDL. К ней же относятся CREATE TABLE, ALTER и DROP.

Теперь в DBeaver обнови список баз клавишей F5, найди probnaya и сверху в редакторе выбери её активной, чтобы рядом стояла зелёная галочка. Грабля с лабы GrantPlatform: если активна база по умолчанию postgres, все таблицы уедут туда, а твоя останется пустой.

Удалить базу целиком: DROP DATABASE IF EXISTS probnaya;. Слова IF EXISTS значат «если есть»: базы нет, нет и ошибки. Сам DROP удаляет насовсем, отменить нельзя. Запускай его, когда активна другая база, например postgres: базу, к которой ты сейчас подключён, PostgreSQL удалить не даст.

На слайдах типы MySQL, а у тебя PostgreSQL, и часть названий другие. Вот типы, которые нужны в твоей базе, и где они у тебя стоят.

NUMERIC(6,3) хранит число точно: всего 6 цифр, из них 3 после точки. Самое большое такое число 999.999. Лишние цифры после точки база округлит, а слишком большое число не примет.

Шаг 4 из 11

PRIMARY KEY и SERIAL: номер выдаёт база

У каждой таблицы нужен первичный ключ, номер строки, который не повторяется. Писать номера руками неудобно, пусть их выдаёт база.

DROP TABLE IF EXISTS models;
CREATE TABLE models (
    id        SERIAL PRIMARY KEY,
    name      VARCHAR(100),
    framework VARCHAR(30)
);
INSERT INTO models (name, framework) VALUES
    ('Resnet', 'pytorch'),
    ('CatBoost', 'catboost');

PRIMARY KEY делает столбец первичным ключом: база не пустит повтор и пустоту. SERIAL это целое число со счётчиком: если номер не написать, база возьмёт следующий. Resnet получит 1, CatBoost 2.

Строки в таблицу кладёт команда INSERT INTO таблица (столбцы) VALUES (значения), (значения);. В первых скобках столбцы, которые заполняешь, дальше по скобкам на строку. Столбец id мы не назвали, поэтому номер выдал счётчик. Подробно INSERT будет в уроке про изменение данных, здесь хватит этого.

Сделай сам. В пустую таблицу с id SERIAL PRIMARY KEY вставили строку, вписав номер руками: INSERT INTO models (id, name) VALUES (1, 'Resnet');. Потом вставляют следующую без номера: INSERT INTO models (name) VALUES ('CatBoost');. Что будет?
Показать ответСкрыть ответ

Вторая вставка упадёт: duplicate key value violates unique constraint "models_pkey", «такой ключ уже есть». Счётчик не знал про ручную единицу и выдал CatBoost тоже 1. Constraint по-английски «ограничение», правило на столбце. models_pkey имя этого правила, база склеила его из имени таблицы и pkey, первичного ключа.

Вписывать id руками «для порядка». С SERIAL номера пиши только базе, иначе счётчик рано или поздно наткнётся на твой номер.

id SERIAL PRIMARY KEY: номер даёт база, в INSERT его не пиши.

INSERT INTO t (a, b) VALUES (1, 'x'); кладёт строку.

Шаг 5 из 11

GENERATED AS IDENTITY: тот же счётчик по стандарту

SERIAL есть только в PostgreSQL. В стандарте SQL счётчик записывают длиннее.

id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY

GENERATED AS IDENTITY значит «номер генерирует база». Слово ALWAYS, «всегда», запрещает вписывать номер обычным INSERT. Если вместо него написать BY DEFAULT, «по умолчанию», номер вписать можно, как с SERIAL.

Сделай сам. Повтори вставку из прошлого шага, INSERT INTO models (id, name) VALUES (1, 'Resnet');, но в таблицу с id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY. Что ответит база?
Показать ответСкрыть ответ

Не пустит сразу, на первой же вставке: cannot insert a non-DEFAULT value into column "id", «в этот столбец свои значения нельзя». Ошибка выходит раньше и понятнее, чем с SERIAL.

Думать, что с BY DEFAULT будет так же. Там ручная единица пройдёт, а следующая вставка без номера упадёт на повторе ключа, ровно как в прошлом шаге.

GENERATED ALWAYS AS IDENTITY: номер даёт база, руками не впишешь.

С BY DEFAULT вписать можно, и грабля та же, что у SERIAL.

NOT NULL и UNIQUE

Так у тебя устроены исследователи.

CREATE TABLE researchers (
    id        SERIAL PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email     VARCHAR(100) UNIQUE,
    grp       VARCHAR(20)
);

Правила пишут после типа, их называют ограничениями, по-английски constraint. Это слово ты уже видел в тексте ошибки в шаге 4. NOT NULL значит «клетка обязана быть заполнена»: без имени исследователя не завести. UNIQUE значит «два одинаковых значения в столбце нельзя»: вторую строку с stepan@urfu.ru база не пустит.

У grp правил нет, поэтому у Смирнова группа может быть NULL. Можно ставить два правила сразу: email VARCHAR(100) NOT NULL UNIQUE, тогда почта обязательна и не повторяется.

Шаг 7 из 11

DEFAULT: что подставить, если не сказали

В твоих запусках два столбца с запасным значением.

created_at TIMESTAMP   DEFAULT now(),
status     VARCHAR(20) DEFAULT 'running'

DEFAULT значение подставляется, когда столбец в INSERT не упомянули вовсе. now() значит «текущие дата и время»: новый запуск сам получит время записи и статус running, «идёт».

Запасное значение можно попросить и явно, словом DEFAULT на месте значения:

INSERT INTO experiments (researcher_id, dataset_id, count_apoh, status)
VALUES (1, 1, 3, DEFAULT);   -- статус станет running
Сделай сам. Две вставки в запуски. В первой столбца status нет совсем. Во второй он есть, и в нём явно написано NULL. Какой статус будет у каждого запуска?
Показать ответСкрыть ответ

Первый получит running. У второго будет NULL: ему прямо сказали «пусто», и база послушалась. DEFAULT срабатывает только когда про столбец молчат.

Ждать, что DEFAULT заменит любую пустоту. Чтобы пустой статус был невозможен совсем, к DEFAULT добавляют NOT NULL: status VARCHAR(20) NOT NULL DEFAULT 'running'. Тогда явный NULL база не примет.

Шаг 8 из 11

CHECK: значение проходит проверку

В твоих наборах данных число строк не может быть нулём или минусом.

count INTEGER NOT NULL CHECK (count > 0)

CHECK (условие) пропускает строку, только если условие верно. Попытка записать набор с count = 0 упадёт с ошибкой violates check constraint "datasets_count_check". Имя правила база склеила сама: таблица, столбец, слово check.

У эпох проверка на промежуток: CHECK (count_apoh BETWEEN 1 AND 1000). BETWEEN 1 AND 1000 значит «от 1 до 1000», обе границы входят. Список допустимых значений тоже делают через CHECK: в PostgreSQL пишут CHECK (status IN ('running', 'done', 'failed')), где IN значит «одно из перечисленных». В MySQL для этого есть ещё тип ENUM.

У тебя на status такой проверки нет. Значит, опечатка 'dnoe' спокойно ляжет в базу, а запрос WHERE status = 'done' этот запуск не увидит.

Сделай сам. У count_apoh стоит CHECK (count_apoh BETWEEN 1 AND 1000), а NOT NULL нет. Пройдут ли вставки с эпохами (а) 1000, (б) 1001, (в) NULL?
Показать ответСкрыть ответ

(а) пройдёт, граница входит. (б) упадёт. (в) пройдёт: CHECK отказывает, только когда условие ложно, а с NULL оно «неизвестно».

Думать, что CHECK заодно запрещает пустоту. Не запрещает. Если эпохи обязательны, пиши оба правила: count_apoh INTEGER NOT NULL CHECK (count_apoh BETWEEN 1 AND 1000).

Запуск ссылается на исследователя и на набор данных.

CREATE TABLE experiments (
    id            SERIAL PRIMARY KEY,
    researcher_id INTEGER NOT NULL REFERENCES researchers(id),
    dataset_id    INTEGER NOT NULL REFERENCES datasets(id),

Шаг 11 из 11

ALTER TABLE: поменять готовую таблицу

Таблица уже с данными, а в неё нужно добавить столбец или правило. Удалять и создавать заново жалко данных.

ALTER TABLE experiments ADD COLUMN notes TEXT;

ALTER TABLE experiments
    ADD CONSTRAINT experiments_status_check
    CHECK (status IN ('running', 'done', 'failed'));

ALTER TABLE datasets RENAME COLUMN count TO rows_count;

ALTER TABLE меняет устройство готовой таблицы и не трогает строки, если не просили. ADD COLUMN добавляет столбец, у старых строк в нём будет NULL. ADD CONSTRAINT имя … добавляет правило, своё имя нужно, чтобы по ошибке было понятно, что сработало. RENAME COLUMN переименовывает столбец.

Ещё пригодятся DROP COLUMN, он убирает столбец, и ALTER COLUMN имя SET NOT NULL, он делает столбец обязательным. Новое правило база проверяет на всех старых строках. Если хоть одна не проходит, правило не добавится.

Сделай сам. В пробной базе из шага 10 выполняют ALTER TABLE researchers ALTER COLUMN grp SET NOT NULL;. Получится? Если нет, как сделать, чтобы получилось? Не получится: column "grp" of relation "researchers" contains null values, у Смирнова группа пустая. Сначала заполни пустоту, например UPDATE researchers SET grp = 'РИ-250932' WHERE grp IS NULL;, а уже потом ставь SET NOT NULL.

Путать ALTER TABLE и UPDATE. Оба «меняют», но ALTER меняет устройство таблицы, это DDL из шага 1. А UPDATE меняет значения в строках, это другая часть SQL, она называется DML. Новый столбец через UPDATE не добавить.

ALTER TABLE t ADD COLUMN …, ADD CONSTRAINT имя CHECK (…), RENAME COLUMN a TO b.

Новое правило не добавится, если старые строки его нарушают.
