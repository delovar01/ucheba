Наследование и полиморфизм

Java · лаба 20.10, слайды «ООП часть II» и примеры Корелина seminar1 · под ПР4, срок 1.12 · около 70 минут

Третий урок про ООП, после классов и инкапсуляции. Там каждый класс жил сам по себе. Здесь один класс строится на основе другого: extends, super, переопределение с @Override, полиморфизм, абстрактный класс и интерфейс. Примеры с машинами и шахматами взяты из кода лектора seminar1 и слайдов части II.

Классы снова лежат в одном файле Main.java, чтобы код можно было запустить целиком. В IDEA каждый класс в своём файле.

Шаг 5 из 12

super.метод(): дополнить, а не заменить

Пример из ElectricCar Корелина: электромобиль запускается по-родительски, но только если есть заряд.

class ElectricCar extends Car {
    private int charge;

    public ElectricCar(int charge) {
        this.charge = charge;
    }

    @Override
    public void startEngine() {
        if (charge > 0) {
            super.startEngine();
        } else {
            System.out.println("Батарея пуста, заряд " + charge);
        }
    }
}
new ElectricCar(80).startEngine();
new ElectricCar(0).startEngine();
Двигатель запущен
Батарея пуста, заряд 0

super.startEngine() вызывает версию метода из родителя. Слайд 24: чтобы вызвать версию суперкласса, нужна ссылка super. Так наследник добавляет проверку или действие вокруг готового поведения и не копирует код родителя.

Сделай сам. В переопределённом startEngine написали System.out.println("Проверка батареи"); startEngine(); без слова super. Что будет при запуске?

Без super метод вызывает сам себя, свою же новую версию, тот снова себя, и так без конца. Такой вызов самого себя называют рекурсией. Каждый незаконченный вызов Java держит в особой памяти, стеке вызовов. Она кончается, и программа падает с StackOverflowError, «стек переполнен». Проверено запуском.

Забыть super. перед вызовом родительской версии. Компилятор не ругается, ошибка видна только при запуске.

super.метод(): вызвать версию родителя изнутри наследника.

Без super метод зовёт сам себя.

Шаг 7 из 12

Полиморфизм: одна переменная, разные объекты

Пример со слайда 23: шахматные фигуры.

import java.util.Arrays;

class ChessPiece {
    public String[] getPossibleMoves() {
        return new String[0];
    }
}

class Knight extends ChessPiece {
    @Override
    public String[] getPossibleMoves() {
        return new String[] {"g1f3", "g1h3"};
    }
}

class Pawn extends ChessPiece {
    @Override
    public String[] getPossibleMoves() {
        return new String[] {"e2e3", "e2e4"};
    }
}

public class Main {
    public static void main(String[] args) {
        ChessPiece[] pieces = {new Knight(), new Pawn(), new ChessPiece()};
        for (ChessPiece p : pieces) {
            System.out.println(Arrays.toString(p.getPossibleMoves()));
        }
    }
}
[g1f3, g1h3]
[e2e3, e2e4]
[]

Слайд 26: переменной типа суперкласса можно присвоить ссылку на объект любого подкласса. Массив ChessPiece[] держит коня, пешку и просто фигуру. Полиморфизм: один и тот же вызов p.getPossibleMoves() работает по-разному. Слайд 24: версия метода выбирается при запуске по типу объекта, а не по типу переменной. Переменная везде ChessPiece, а ходы у каждого свои.

Про запись массивов в коде. new String[] {"g1f3", "g1h3"} создаёт массив строк сразу со значениями, new String[0] пустой массив. Цикл «для каждого» из урока про классы работает и с массивом: for (ChessPiece p : pieces) берёт фигуры по очереди.

Цикл не знает, какие фигуры бывают. Добавишь ферзя, цикл менять не придётся. У Корелина в Main так же: Car[] cars = {new ElectricCar(), new ElectricCar(), new GasCar()} и один цикл для всех.

Шаг 9 из 12

Абстрактный класс

По мотивам Vehicle из seminar1-oop: заправка у грузовика и электробуса разная, общего способа нет.

abstract class Vehicle {
    protected double fuel;

    public abstract void refuel(double amount);

    public double getFuel() {
        return fuel;
    }
}

class Truck extends Vehicle {
    @Override
    public void refuel(double amount) {
        fuel += amount;
        System.out.println("Грузовик: дизель +" + amount);
    }
}

class ElectricBus extends Vehicle {
    @Override
    public void refuel(double amount) {
        fuel += amount * 0.9;
        System.out.println("Автобус: заряд +" + amount + ", потери 10%");
    }
}
Vehicle[] park = {new Truck(), new ElectricBus()};
for (Vehicle v : park) {
    v.refuel(50);
    System.out.println(v.getFuel());
}

50.0
Автобус: заряд +50.0, потери 10%
45.0

Абстрактный метод объявлен без тела, после скобок сразу ;: «такой метод есть, но как он работает, решит наследник». Класс с абстрактным методом обязан быть abstract. Создать его объект нельзя: new Vehicle() даёт Vehicle is abstract; cannot be instantiated. Обычные поля и методы, как getFuel, у абстрактного класса тоже есть, наследники получают их готовыми.

Шаг 10 из 12

Интерфейс: обещание методов

Интерфейсы Startable и Fuelable взяты из seminar1-oop, класс сокращён.

interface Startable {
    void startEngine();
    void stopEngine();
}

interface Fuelable {
    void refuel(double amount);
    double checkFuelLevel();
}

class Car implements Startable, Fuelable {
    private double fuelLevel = 10;

    @Override
    public void startEngine() {
        System.out.println("Двигатель запущен");
    }

    @Override
    public void stopEngine() {
        System.out.println("Двигатель заглушен");
    }

    @Override
    public void refuel(double amount) {
        fuelLevel += amount;
    }

    @Override
    public double checkFuelLevel() {
        return fuelLevel;
    }
}

class Canister implements Fuelable {
    private double liters = 0;

    @Override
    public void refuel(double amount) {
        liters += amount;
    }

    @Override
    public double checkFuelLevel() {
        return liters;

}
Fuelable[] tanks = {new Car(), new Canister()};

Интерфейс это список методов без тела, которые класс обещает написать. Обещание даётся словом implements, «реализует». Методы интерфейса всегда открытые, поэтому в классе они public. Полей у объекта интерфейс не даёт, конструктора у него нет.

Родитель у класса один, а интерфейсов сколько угодно: машина и заводится, и заправляется. Канистра машиной не является, но заправляется, и цикл по Fuelable[] работает с обеими. Интерфейс описывает умение, абстрактный класс описывает общий род с готовыми полями.

Квадрат является прямоугольником, по геометрии всё верно:

class Rectangle {
    protected int width;
    protected int height;

    public void setWidth(int width) {
        this.width = width;
    }

    public void setHeight(int height) {
        this.height = height;
    }

    public int area() {
        return width * height;
    }
}

class Square extends Rectangle {
    @Override
    public void setWidth(int side) {
        width = side;
        height = side;
    }

    @Override
    public void setHeight(int side) {
        width = side;
        height = side;
    }
}

        r.setHeight(2);

    public static void main(String[] args) {
        stretch(new Rectangle());
        stretch(new Square());
    }
}

Слайды 18–19: наследование моделирует отношение «является», но не каждое такое отношение надо делать через extends, и не стоит наследовать только ради чужих методов.
