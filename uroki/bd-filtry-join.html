ORDER BY: по убыванию

Хотим увидеть наборы данных от самого большого к самому маленькому.

FROM datasets

ORDER BY значит «упорядочить по». После него пишешь столбец, по которому сортировать.

Шаг 3 из 10

BETWEEN: число в промежутке

Это задание 2. Нужны наборы данных, в которых от 200 до 21000 строк.

SELECT name, count
FROM datasets
WHERE count BETWEEN 200 AND 21000
ORDER BY count;

x BETWEEN a AND b значит «x от a до b», обе границы включены. Это то же самое, что x >= a AND x <= b, только короче. AND значит «и»: должны выполниться оба условия.

Подходят pirs 210, Titanic 891 и California Housing 20640. iris с 150 меньше 200, IMDB и MNIST больше 21000.

Сделай сам. Какие оценки в metrics лежат от 0.8 до 0.9? Сначала найди их глазами в таблице выше, потом напиши запрос.
Показать ответСкрыть ответ 
SELECT experiments_id, name_metric, mean_metric
FROM metrics
WHERE mean_metric BETWEEN 0.8 AND 0.9;

Четыре строки: 0.835 (запуск 2), 0.812 (запуск 4), 0.874 и 0.866 (запуск 6). 0.789 чуть меньше 0.8 и не попадает.

Перепутать границы: BETWEEN 0.9 AND 0.8. Ошибки база не покажет, просто вернёт пусто: число не может быть одновременно не меньше 0.9 и не больше 0.8. Меньшая граница всегда первая.

WHERE x BETWEEN a AND b, обе границы входят.

Сначала меньшая граница, потом большая.

Шаг 4 из 10

Диапазон дат: ловушка со временем

Задание 2 можно делать и по дате. Хотим запуски с 1 по 11 октября включительно.

SELECT id, created_at
FROM experiments
WHERE created_at BETWEEN '2026-10-01' AND '2026-10-11';

База вернёт запуски 6 и 7. А запуск 8 от 11 октября пропал, хотя 11-е мы просили включить.

created_at у тебя TIMESTAMP, то есть дата вместе со временем. Дата без времени '2026-10-11' для базы значит 11 октября в 00:00, самое начало дня. Запуск 8 был в 23:20, это позже границы.

Надёжный способ: «не раньше начала первого дня и строго раньше начала следующего за последним».

SELECT id, created_at
FROM experiments
WHERE created_at >= '2026-10-01'
  AND created_at <  '2026-10-12';

Теперь запуски 6, 7 и 8.

Сделай сам. Все запуски сентября. Напиши запрос надёжным способом. Сколько строк?
Показать ответСкрыть ответ 
SELECT id, created_at
FROM experiments
WHERE created_at >= '2026-09-01'
  AND created_at <  '2026-10-01';

Пять строк, запуски 1–5. Граница «меньше 1 октября» сама включает весь день 30 сентября до последней секунды.

Написать <= '2026-09-30'. Сейчас ответ случайно верный, потому что 30-го запусков нет. Но запуск 30 сентября в 15:00 такой запрос потеряет, как потерял запуск 8 выше.

Дата со временем: >= 'первый день' AND < 'день после последнего'.

'2026-10-11' это 11.10 в 00:00, а не весь день.

Это задание 3. Нужны наборы данных для текста или для картинок, то есть с типом nlp или cv.

SELECT name, type_task

x IN ('a', 'b') значит «x равен одному из значений в скобках». Это короче цепочки type_task = 'nlp' OR type_task = 'cv', а ответ тот же. OR значит «или».

Получится IMDB Reviews (nlp) и MNIST (cv).

Шаг 6 из 10

LIKE: поиск по куску текста

Это задание 4. Знак = находит текст, только если он совпал целиком. А если нужно «начинается на R» или «содержит слово»?

SELECT name
FROM models
WHERE name LIKE 'R%';

LIKE сравнивает текст с шаблоном. В шаблоне знак % значит «тут любой кусок текста, хоть пустой». 'R%' читается «R, а дальше что угодно».

Результат: RandomForest, Resnet. Ещё два шаблона на наборах данных:

  • LIKE '%s' «что угодно, а в конце s»: iris, pirs, IMDB Reviews;
  • LIKE '%Housing%' «где-то внутри есть Housing»: California Housing.

Есть второй знак, _: ровно один любой символ. LIKE '_NIST' найдёт MNIST, потому что перед NIST одна буква.

Сделай сам. Найди исследователя, у которого в full_name есть слово «Степан».
Показать ответСкрыть ответ 
SELECT full_name
FROM researchers
WHERE full_name LIKE '%Степан%';

Павленко Степан. % нужен с обеих сторон: перед именем стоит фамилия.

Забыть %: LIKE 'Степан'. Без знаков шаблон работает как = и ищет строку, равную «Степан» целиком. Такой нет, ответ пустой.

LIKE 'А%' начинается, '%а' кончается, '%а%' содержит.

Шаг 7 из 10

ILIKE: без разницы, большая буква или маленькая

Вернёмся к шагу 6. Модель rubert-tiny2 тоже начинается на r, но запрос LIKE 'R%' её не нашёл. В PostgreSQL LIKE различает большие и маленькие буквы: R и r для него разные.

SELECT name
FROM models
WHERE name ILIKE 'r%';

ILIKE работает как LIKE, но не различает большие и маленькие буквы. Теперь ответ RandomForest, Resnet и rubert-tiny2.

Сделай сам. Какие наборы данных найдёт name LIKE '%m%', а какие name ILIKE '%m%'?
Показать ответСкрыть ответ

LIKE '%m%' не найдёт ничего: маленькой m нет ни в одном названии. ILIKE '%m%' найдёт IMDB Reviews и MNIST, у них большая M.

Думать, что пустой ответ значит «запрос сломан». Запрос верный, просто LIKE строго отличает большие буквы от маленьких. Если ищешь по имени, которое люди пишут как попало, бери ILIKE. В MySQL ILIKE нет, там LIKE и так не различает большие и маленькие буквы.

LIKE различает R и r, ILIKE нет.

Знаки % и _ у них одинаковые.

Шаг 8 из 10

IS NULL: найти пустые клетки

Это задание 5. У Смирнова Олега не указана группа: в клетке grp пусто, это NULL. Найдём его.

Шаг 9 из 10

JOIN: склеить две таблицы

Это задание 6. В experiments вместо имени исследователя стоит номер, researcher_id. Хотим видеть рядом с запуском имя.

SELECT e.id, r.full_name, e.status
FROM experiments e
JOIN researchers r ON r.id = e.researcher_id
ORDER BY e.id;

Здесь две новые записи, но они про одно. experiments e даёт таблице короткое имя e, чтобы дальше писать e.status вместо experiments.status. Точка значит «столбец из этой таблицы».

JOIN … ON условие приклеивает к каждой строке левой таблицы строку правой, для которой условие верно. ON r.id = e.researcher_id читается «номер исследователя совпадает с номером, записанным в запуске».

Таблицу, на строки которой ссылаются по номеру, называют справочником. Здесь справочники researchers, datasets и models, а experiments на них ссылается.
