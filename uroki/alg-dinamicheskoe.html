Динамическое программирование

Алгоритмы · лаба 24.10 · около 70 минут

Урок по лабе 24.10. Там разбирали четыре задачи: числа Фибоначчи, рюкзак, общую подпоследовательность двух строк и лабиринт. Здесь они же, по порядку, тринадцать шагов, в каждом одна новая вещь. Числа в примерах те же, что на слайдах Зубарева, а «сделай сам» на своих.

Как проходить: читаешь шаг, переписываешь рамку «Перепиши в тетрадь», решаешь «сделай сам» на бумаге и только потом открываешь ответ. Таблицы рисуй в тетради клетками, строки и столбцы подписывай. Если в шаге что-то непонятно, дальше не иди: сначала задай вопрос по этому шагу.

Нужно помнить рекурсию: функция вызывает сама себя, пока не дойдёт до простого случая. Это было в уроке про рекурсию.

Шаг 1 из 13

Рекурсия, которая считает одно и то же

Числа Фибоначчи: первые два 0 и 1, каждое следующее равно сумме двух предыдущих. 0, 1, 1, 2, 3, 5, 8, 13… Номер числа обозначают n, начиная с нуля: fib(0) = 0, fib(1) = 1, fib(5) = 5.

Прямо по определению пишется так:

long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

Распишем, какие вызовы сделает fib(5). Каждый вызов, кроме fib(1) и fib(0), рождает ещё два:

fib(5)
├─ fib(4)
│  ├─ fib(3)
│  │  ├─ fib(2)
│  │  │  ├─ fib(1)
│  │  │  └─ fib(0)
│  │  └─ fib(1)
│  └─ fib(2)
│     ├─ fib(1)
│     └─ fib(0)
└─ fib(3)
   ├─ fib(2)
   │  ├─ fib(1)
   │  └─ fib(0)
   └─ fib(1)

Всего 15 вызовов. При этом fib(3) посчитан два раза, а fib(2) три раза. Каждый раз заново, хотя ответ тот же.

Перекрывающиеся подзадачи: в рекурсии одна и та же подзадача встречается много раз и каждый раз решается заново. Из-за этого число вызовов растёт примерно как 1,618ⁿ: на лабе fib(40) сделал 331 миллион вызовов.

Подзадача здесь это вызов с меньшим n. Чтобы найти fib(5), нужны подзадачи fib(4) и fib(3).

Сделай сам. Сколько вызовов сделает fib(6)? Сколько раз внутри него посчитается fib(2)? Подсказка: вызовов у fib(6) столько, сколько у fib(5), плюс сколько у fib(4), плюс сам первый вызов. У fib(4) их 9.
Показать ответСкрыть ответ

15 + 9 + 1 = 25 вызовов. fib(2) считается 5 раз: 3 раза внутри fib(5) и 2 раза внутри fib(4).

Забыть «+1» за сам вызов fib(6) и получить 24. Каждый вызов, включая самый первый, тоже считается.

Наивный fib решает одни и те же подзадачи заново. Вызовов ≈ 1,618ⁿ.

Шаг 2 из 13

Мемоизация: запомнить ответ

Заведём массив memo на n + 1 ячеек и заполним его числом −1, это значит «ещё не считали». Перед тем как считать, смотрим в memo. Посчитали, записали туда.

long fib(int n, long[] memo) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    return memo[n];
}

Для fib(5) теперь 9 вызовов вместо 15. Ветка fib(4) идёт до самого низа и по дороге записывает memo[2], memo[3], memo[4]. Когда дело доходит до правого fib(3), ответ уже лежит в memo[3], и вызов сразу возвращает его.

Мемоизация: та же рекурсия, но ответ каждой подзадачи сохраняется в массиве, и при повторном вызове берётся оттуда. Каждое fib(i) считается один раз, время O(n), память O(n). Такой порядок называют «сверху вниз»: начинаем с большой задачи и спускаемся к маленьким.

У мемоизации остаётся глубина рекурсии n. На лабе fib(100 000) так падал с StackOverflowError: стек вызовов в Java кончается раньше.

Сделай сам. С мемоизацией fib(5) делает 9 вызовов, fib(40) 79. Сколько вызовов будет у fib(10)? Найди закономерность.
Показать ответСкрыть ответ

19. Закономерность 2n − 1: 2 · 5 − 1 = 9, 2 · 40 − 1 = 79, 2 · 10 − 1 = 19. Левая ветка спускается от n до 1, это n вызовов, и у каждого из fib(n)…fib(2) есть ещё один правый вызов, который сразу отвечает из memo или из базы. Их n − 1.

Ответить 10, «каждое число один раз». Один раз каждое число считается, но вызовов больше: повторный вызов тоже вызов, просто короткий.

Мемоизация: рекурсия + массив ответов, −1 = не считали. O(n) время и память.

Шаг 3 из 13

Табуляция: заполнить таблицу снизу

Можно обойтись без рекурсии совсем. Заводим массив dp и заполняем его слева направо, от маленьких n к большим. Буквы dp от «динамическое программирование», так массив обычно и называют.

long[] dp = new long[n + 1];
dp[0] = 0;
dp[1] = 1;
for (int i = 2; i <= n; i++)
    dp[i] = dp[i - 1] + dp[i - 2];
return dp[n];
i     0  1  2  3  4  5  6  7
dp    0  1  1  2  3  5  8  13

dp[7] = dp[6] + dp[5] = 8 + 5 = 13. Когда считаем ячейку i, ячейки i − 1 и i − 2 уже заполнены, потому что идём слева направо.

Табуляция: ответы подзадач записываются в таблицу в таком порядке, чтобы каждая ячейка считалась только из уже заполненных. Это порядок «снизу вверх». Рекурсии нет, стек не кончится.

Платим за это тем, что порядок надо придумать заранее. У Фибоначчи он простой, дальше будут таблицы, где его надо продумать.

Сделай сам. Продолжи таблицу: dp[8], dp[9], dp[10].
Показать ответСкрыть ответ

dp[8] = 13 + 8 = 21, dp[9] = 21 + 13 = 34, dp[10] = 34 + 21 = 55.

Сделать массив new long[n]. Тогда последней ячейки dp[n] нет, и программа упадёт с выходом за границу массива. Номера от 0 до n, это n + 1 ячейка.

Табуляция: цикл от базы вверх, ячейка из уже заполненных. Массив n + 1.

Шаг 4 из 13

Две переменные вместо массива

В табуляции ячейке i нужны только две предыдущие. Остальной массив хранится зря. Держим две переменные: prev это предпоследнее число, cur последнее.

long prev = 0, cur = 1;
for (int i = 2; i <= n; i++) {
    long next = prev + cur;
    prev = cur;
    cur = next;
}
return cur;
i   next   prev   cur
2   1      1      1
3   2      1      2
4   3      2      3
5   5      3      5

Если ячейка таблицы зависит только от нескольких последних, таблицу можно не хранить целиком. Здесь хватает двух переменных, память O(1) вместо O(n), время то же O(n).

Ещё одна вещь с лабы: тип long вмещает числа до примерно 9 · 10¹⁸. fib(92) ещё влезает, а fib(93) уже нет, и Java молча выдаёт отрицательное число. Для больших n берут BigInteger.

Сделай сам. Продолжи таблицу до i = 6. Потом представь, что строки в цикле переставили: сначала prev = cur;, потом cur = prev + cur;. Что вернёт такой код при n = 6?
Показать ответСкрыть ответ

i = 6: next = 3 + 5 = 8, prev = 5, cur = 8. Ответ 8, верно. Переставленный код: после prev = cur старое prev потеряно, и cur = prev + cur просто удваивает cur: 2, 4, 8, 16, 32. При n = 6 вернёт 32.

Это и есть типичная ошибка: затереть переменную раньше, чем её прочитали. Поэтому сначала next из двух старых значений, и только потом сдвиг.

Нужны только последние ячейки → храним только их. Фибоначчи: O(1) памяти.

long переполняется после fib(92).

Шаг 5 из 13

Рецепт: как придумать ДП для новой задачи

Задача: лестница из n ступенек, за раз шагаешь на 1 или на 2 ступеньки. Сколькими способами можно подняться наверх? Для n = 3: 1+1+1, 1+2, 2+1, три способа.

Разберём по пяти вопросам со слайда лабы.

вопрослестница
1. Состояние: что хранит ячейкаw[i] = число способов дойти до ступеньки i
2. Переход: как ячейка выражается через меньшиена ступеньку i пришли либо с i − 1, либо с i − 2: w[i] = w[i − 1] + w[i − 2]
3. База: простые случаиw[0] = 1 (стоять внизу, один способ), w[1] = 1
4. Порядокi от 2 до n
5. Ответ: какая ячейкаw[n]
i   0  1  2  3  4  5
w   1  1  2  3  5  8

ДП строится по рецепту: состояние, переход, база, порядок, ответ. Работает, когда у задачи есть перекрывающиеся подзадачи (шаг 1) и оптимальная подструктура: ответ большой задачи собирается из ответов меньших.

Лестница считается так же, как Фибоначчи, только база другая. Так часто бывает: новая задача сводится к знакомой таблице.

Сделай сам. Теперь можно шагать на 1, 2 или 3 ступеньки. Запиши переход и заполни w[0]…w[5].
Показать ответСкрыть ответ

Переход w[i] = w[i − 1] + w[i − 2] + w[i − 3], слагаемые с отрицательным номером не берём. База w[0] = 1. Таблица: 1, 1, 2, 4, 7, 13. Проверка для w[3] = 4: 1+1+1, 1+2, 2+1, 3.

Поставить w[0] = 0, «ведь шагать некуда». Тогда w[2] = w[1] + w[0] даст 1, а способов два: 1+1 и 2. Ноль ступенек это один способ: ничего не делать.

Рецепт ДП: 1) состояние 2) переход 3) база 4) порядок 5) ответ.

Когда работает: подзадачи повторяются + ответ собирается из ответов подзадач.

Шаг 6 из 13

Рюкзак: брать или не брать

Рюкзак выдерживает 5 кг. Предметы со слайда:

предметвесценность
Гитара11500
Магнитофон43000
Ноутбук32000
Айфон12000
Книга2500

Каждый предмет можно взять один раз или не брать, поэтому задача называется «рюкзак 0/1». Нужна наибольшая суммарная ценность при весе не больше 5. Вместимость обозначают W, здесь W = 5. Перебрать все наборы можно, но их 2ⁿ: у 5 предметов 32, у 40 предметов больше триллиона.

Состояние: dp[i][c] это лучшая ценность, если можно брать только из первых i предметов, а вместимость c. Про последний, i-й предмет два варианта:

• не берём: остаётся лучшее из первых i − 1 при той же вместимости, dp[i − 1][c];
• берём, если влезает (w[i] ≤ c): его ценность v[i] плюс лучшее из первых i − 1 на оставшееся место, dp[i − 1][c − w[i]] + v[i].

Переход рюкзака: dp[i][c] = max(dp[i − 1][c], dp[i − 1][c − w[i]] + v[i]), второй вариант только если w[i] ≤ c. База: dp[0][c] = 0, без предметов ценность ноль. Ответ dp[n][W].

Сделай сам. Рюкзак на 4 кг, предметы А (вес 1, ценность 15), Б (3, 20), В (4, 30). Переберёшь все 8 наборов? Какой лучший? Что даст правило «сначала самый дорогой»?
Показать ответСкрыть ответ

Пустой 0, А 15, Б 20, В 30, А+Б вес 4 ценность 35. А+В весит 5, Б+В 7, все три 8, не влезают. Лучший А+Б, 35. «Сначала дорогой» берёт В за 30, места больше нет, получается 30 вместо 35.

Решать рюкзак жадно: по цене или по цене за килограмм. На каких-то данных повезёт, но не всегда. Таблица ДП перебирает «брать или не брать» для каждого предмета и не ошибается.

Рюкзак 0/1: dp[i][c] = лучшее из первых i при вместимости c.

dp[i][c] = max(dp[i−1][c], dp[i−1][c−w[i]] + v[i]), если w[i] ≤ c. База 0. Ответ dp[n][W].

Шаг 7 из 13

Заполняем таблицу рюкзака

Строки это предметы по порядку, столбцы вместимость от 0 до 5. Каждая ячейка смотрит только в строку выше, поэтому заполняем построчно, слева направо.

c=012345
∅000000
Гитара (1)015001500150015001500
Магнитофон (4)015001500150030004500
Ноутбук (3)015001500200035004500
Айфон (1)020003500350040005500
Книга (2)020003500350040005500

Одна ячейка крупно: строка «Айфон», c = 5. Айфон весит 1, ценность 2000. Не берём: ячейка выше, 4500. Берём: на гитару, магнитофон и ноутбук остаётся 4 кг, в строке выше при c = 4 стоит 3500, итого 3500 + 2000 = 5500. Максимум 5500.

Таблица рюкзака заполняется по строкам: каждая ячейка берёт два числа из строки выше, прямо над собой и левее на вес предмета, и выбирает большее. Время и память O(n · W).

int[][] dp = new int[n + 1][W + 1];
for (int i = 1; i <= n; i++)
    for (int c = 0; c <= W; c++) {
        dp[i][c] = dp[i - 1][c];
        if (w[i - 1] <= c)
            dp[i][c] = Math.max(dp[i][c], dp[i - 1][c - w[i - 1]] + v[i - 1]);
    }

В коде w[i − 1], потому что массивы в Java с нуля, а строки таблицы с единицы: строка 0 это «без предметов».

Сделай сам. Заполни таблицу для А (1, 15), Б (3, 20), В (4, 30), W = 4. Совпал ли ответ с перебором из шага 6?

c=01234
∅00000
А (1)015151515
Б (3)015152035
В (4)015152035

Б при c = 4: не берём 15, берём dp[А][1] + 20 = 15 + 20 = 35. В при c = 4: не берём 35, берём dp[Б][0] + 30 = 30, остаётся 35. Ответ 35, как в переборе.

Брать число «левее на вес» из той же строки, а не из строки выше. Тогда предмет может попасть в рюкзак два раза: в строке А при c = 2 вышло бы 15 + 15 = 30.

Таблица рюкзака по строкам. Ячейка = max(над ней, строка выше левее на w[i] + v[i]). O(n · W).

Шаг 8 из 13

Какие предметы взяли

Таблица говорит, что лучший рюкзак стоит 5500. Но что в нём? Идём из правого нижнего угла вверх по строкам.

Книга, c = 5: 5500, выше тоже 5500. Ячейка не изменилась, значит книгу не брали. Айфон, c = 5: 5500, выше 4500. Изменилась, айфон взят, место уменьшаем на его вес: c = 5 − 1 = 4. Ноутбук, c = 4: 3500, выше 3000, взят, c = 4 − 3 = 1. Магнитофон, c = 1: 1500, выше 1500, не взят. Гитара, c = 1: 1500, выше 0, взята.

Итог: гитара, ноутбук, айфон. Вес 1 + 3 + 1 = 5, ценность 1500 + 2000 + 2000 = 5500.

Восстановление ответа: идём от dp[n][W] вверх. Если dp[i][c] ≠ dp[i − 1][c], предмет i взят и c уменьшается на w[i]. Если равны, предмет не брали, c не меняется.

Так почти в любой задаче ДП: сначала таблица даёт число, потом обратный проход по ней даёт само решение.

Сделай сам. Восстанови набор по своей таблице из шага 7 (А, Б, В, W = 4).
Показать ответСкрыть ответ

В, c = 4: 35, выше 35, не взят. Б, c = 4: 35, выше 15, взят, c = 1. А, c = 1: 15, выше 0, взят. Набор А + Б, как в переборе.

Шаг 9 из 13

Рюкзак в одну строку

Как в шаге 4: каждая строка таблицы зависит только от предыдущей. Значит хватит одного массива на W + 1 ячейку, который перезаписываем для каждого предмета.

int[] dp = new int[W + 1];
for (int i = 0; i < n; i++)
    for (int c = W; c >= w[i]; c--)
        dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
return dp[W];

Главное здесь то, что c идёт справа налево. Ячейка dp[c − w] левее, и при таком порядке её ещё не трогали для текущего предмета: в ней число «из строки выше». Предмет учтётся один раз.

Рюкзак 0/1 в одну строку: один массив dp[0..W], для каждого предмета c от W вниз до w[i]. Память O(W). Если пойти слева направо, получится рюкзак, где каждый предмет можно брать сколько угодно раз.

Сделай сам. Один предмет А (вес 1, ценность 15), W = 4, массив сначала [0, 0, 0, 0, 0]. Каким он станет, если идти справа налево? А если слева направо?
Показать ответСкрыть ответ

Справа налево: c = 4: max(0, dp[3] + 15) = 15, dp[3] ещё 0. Так же c = 3, 2, 1. Итог [0, 15, 15, 15, 15], А взят один раз.

Слева направо: dp[1] = 15, потом dp[2] = dp[1] + 15 = 30, dp[3] = 45, dp[4] = 60. Итог [0, 15, 30, 45, 60]: А положили четыре раза.

Написать цикл по c «как обычно», от 0 вверх, и не заметить: на примере, где каждый предмет и так не влезает дважды, ответ случайно совпадёт.

Рюкзак 0/1 одной строкой: c от W вниз. Слева направо = предметы без ограничения количества.

Шаг 10 из 13

Подпоследовательность двух строк

Подпоследовательность строки получается, если вычеркнуть из неё какие-то символы, а остальные оставить в том же порядке. Из ABCBDAB вычёркиваем A, D и последнюю B, остаётся BCBA. Символы не обязаны стоять рядом, этим подпоследовательность отличается от подстроки.

Наибольшая общая подпоследовательность двух строк, по-английски LCS: самая длинная строка, которая является подпоследовательностью обеих. Для ABCBDAB и BDCABA это BCBA, длина 4.

Шаг 11 из 13

Таблица LCS

Строки a длины n и b длины m. Состояние: dp[i][j] это длина LCS первых i символов a и первых j символов b. База: если одна из частей пустая, общего нет, dp[0][j] = dp[i][0] = 0.

Смотрим на последние символы этих кусков, a[i − 1] и b[j − 1]:

• совпали: берём символ в LCS и отрезаем его в обеих строках, dp[i][j] = dp[i − 1][j − 1] + 1;
• не совпали: хотя бы один из них в LCS не войдёт. Выкидываем последний символ у a или у b и берём лучшее: dp[i][j] = max(dp[i − 1][j], dp[i][j − 1]).

Маленький пример: a = ACB, b = ABC.

Переход LCS: символы совпали → диагональ + 1. Не совпали → max(сверху, слева). Заполняем по строкам, время и память O(n · m), ответ dp[n][m].

Шаг 12 из 13

Обратный проход: сама подпоследовательность

Таблица даёт длину, а строку собираем, как рюкзак в шаге 8, обратным проходом из правого нижнего угла.

Обратный проход LCS: стоим в dp[i][j]. Символы a[i − 1] и b[j − 1] совпали → записываем символ и идём по диагонали. Не совпали → идём к большему соседу: вверх, если dp[i − 1][j] ≥ dp[i][j − 1], иначе влево. Символы получаются с конца, в конце строку переворачиваем.

Таблица ACB и ABC из шага 11. Старт в строке B, столбце C, там 2. B ≠ C, сверху 2, слева 2, равны, идём вверх. Строка C, столбец C: совпали, пишем C, по диагонали. Строка A, столбец B: A ≠ B, сверху 0, слева 1, идём влево. Строка A, столбец A: совпали, пишем A. Собрали C, A, переворачиваем: AC.

Шаг 13 из 13

Лабиринт: ценность клетки через соседей

Последняя задача лабы. Агент ходит по клеткам лабиринта вверх, вниз, влево, вправо. Каждый шаг даёт награду −1, шаг в выход G даёт +100. Хотим знать, сколько стоит стоять в каждой клетке, если дальше ходить наилучшим образом. Эту величину называют ценностью клетки, V(s), s это клетка.

Ценность клетки складывается из награды за лучший шаг и ценности клетки, куда пришли. Будущее ценится чуть меньше настоящего: ценность следующей клетки умножают на число γ (гамма) меньше 1, на лабе γ = 0,95.

Уравнение Беллмана: V(s) = max по действиям [ r + γ · V(s′) ], r это награда за шаг, s′ клетка, куда шаг ведёт. Ценность выражается через ценность соседей, это переход ДП. База: V(G) = 0, из выхода не ходят.

Коридор, клетки пронумеруем по расстоянию до выхода. Клетка 1 рядом с G: лучший шаг в G, V = 100 + 0,95 · 0 = 100. Клетка 2: шаг в клетку 1, V = −1 + 0,95 · 100 = 94. Чем дальше от выхода, тем меньше ценность, и агент из любой клетки просто идёт к соседу с большей V.

На лабе сравнивали три способа. Обход в ширину находит кратчайший путь, если карта известна (урок про BFS). Пересчёт V по Беллману для всех клеток, пока числа не перестанут меняться, тоже требует карту, зато даёт лучший шаг из каждой клетки. Q-learning учится без карты, пробуя шаги, и платит за это десятками тысяч проб. Путь у всех трёх вышел одинаковый, 28 шагов.
