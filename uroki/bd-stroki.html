Строковые функции: склеить, отрезать, почистить

Базы данных · лаба 21.10 и слайд 9 лекции 4 · около 60 минут

На лабе 21.10 разбирали строковые функции PostgreSQL: склейку || и SUBSTRING. На лекции 4 был пример: собрать красивое имя клиента и спрятать его почту, оставив две буквы и домен. Здесь всё это на твоей базе ml_tracker, плюс функции, без которых текст не почистить: длина, регистр, пробелы, замена.

Шаг 1 из 12

Склейка ||

Хотим одну строку вида «Павленко Степан (РИ-250932)».

SELECT full_name || ' (' || grp || ')' AS podpis
FROM researchers;

a || b склеивает два куска текста в один. Кусков может быть сколько угодно, свой текст пишут в одинарных кавычках. Пробел тоже кусок: без ' (' имя и скобка слипнутся.

podpis
Павленко Степан (РИ-250932)
Щайхутдинов Азат (РИ-250932)
Иванова Мария (РИ-250931)
NULL

У Смирнова пусто целиком, даже имени нет. Если в склейке через || хоть один кусок NULL, весь результат NULL: «имя плюс неизвестно» база считает неизвестным.

Сделай сам. Для каждой модели строка «название / фреймворк», например «Resnet / pytorch».
Показать ответСкрыть ответ 
SELECT name || ' / ' || framework AS podpis
FROM models;

Пять строк: Logisticregression / sklearn, RandomForest / sklearn, Resnet / pytorch, rubert-tiny2 / pytorch, CatBoost / catboost. Пустых фреймворков нет, поэтому NULL здесь не вылезет.

Взять разделитель в двойные кавычки: name || " / " || framework. В PostgreSQL двойные кавычки значат имя столбца, и база ответит column " / " does not exist. Текст только в одинарных.

a || ' ' || b склеивает, текст в одинарных кавычках.

Один NULL в склейке ||, и вся строка NULL.

Шаг 2 из 12

CONCAT и COALESCE: склейка без пропажи

То же через функцию, как на слайде лекции.

SELECT CONCAT(full_name, ' (', grp, ')') AS podpis
FROM researchers;

CONCAT(a, b, …) склеивает все свои аргументы, а NULL просто пропускает. У Смирнова выйдет «Смирнов Олег ()». CONCAT есть и в PostgreSQL, и в MySQL, а || в MySQL по умолчанию значит «или», так что для переносимого кода бери CONCAT.

Пустые скобки некрасиво. Подставим слово вместо пустоты:

SELECT full_name || ' (' || COALESCE(grp, 'без группы') || ')' AS podpis
FROM researchers;

COALESCE ты уже видел в уроке про подзапросы, шаг 8, там он менял пустоту на 0. С текстом так же: COALESCE(x, 'замена') возвращает x, а если он NULL, то замену. Теперь у Смирнова «Смирнов Олег (без группы)», и || уже не ломается.

Сделай сам. Для каждого набора данных строка «название: ссылка», а где ссылки нет, «название: ссылки нет».
Показать ответСкрыть ответ 
SELECT CONCAT(name, ': ', COALESCE(link, 'ссылки нет')) AS podpis
FROM datasets;

Шесть строк, например «iris: https:\\gobro», а последняя «Titanic: ссылки нет».

Надеяться, что CONCAT сам напишет «ссылки нет». Он только выбрасывает NULL, и выйдет «Titanic: » с пустотой после двоеточия. Слово вместо пустоты даёт только COALESCE.

CONCAT(a, b, c) пропускает NULL, || нет.

COALESCE(x, 'замена'): пусто превращается в замену.

Шаг 4 из 12

UPPER и LOWER: большие и маленькие буквы

Ищем набор mnist, написав название маленькими.

SELECT name FROM datasets WHERE name = 'mnist';          -- пусто
SELECT name FROM datasets WHERE LOWER(name) = 'mnist';   -- MNIST

LOWER(s) делает все буквы маленькими, UPPER(s) большими. Чтобы сравнить без учёта регистра, приводят к одному виду обе стороны. В таблице MNIST остаётся как был, меняется только то, что видит сравнение.

На лекции был пример, что в PostgreSQL 'анна' не находит 'Анна'. Это то же лечение: LOWER(имя) = 'анна'. В LIKE есть готовый вариант без регистра, ILIKE, он в уроке про фильтры, шаг 7.

Сделай сам. Модели, у которых название начинается на r, большую или маленькую. Без ILIKE.
Показать ответСкрыть ответ 
SELECT name
FROM models
WHERE LOWER(name) LIKE 'r%';

RandomForest, Resnet, rubert-tiny2. Ровно то, что дал бы name ILIKE 'r%'.

Привести к маленьким столбец, а шаблон оставить с большой: LOWER(name) LIKE 'R%'. После LOWER большой R в названиях не осталось, и ответ пустой. Обе стороны в одном регистре.

LOWER(s) маленькие, UPPER(s) большие.

Без регистра: LOWER(столбец) = 'всё маленькими'.

Шаг 5 из 12

TRIM: лишние пробелы по краям

Данные часто приходят с пробелами: кто-то скопировал название из таблицы вместе с пробелом. Для базы это уже другой текст.

SELECT '  iris ' = 'iris'       AS kak_est,

TRIM(s) убирает пробелы в начале и в конце текста, внутри не трогает. LTRIM только слева, RTRIM только справа.

Ответ: false, true, 7, 4. В DBeaver false и true бывают показаны пустым и отмеченным квадратиком.

5: три пробела слева и три справа ушли. Во втором 19: по краям пробелов нет, а два пробела внутри TRIM не трогает.

Шаг 6 из 12

SUBSTRING: кусок текста

Группа РИ-250932 состоит из букв направления и номера. Достанем их по отдельности.

SELECT grp,
       SUBSTRING(grp FROM 1 FOR 2) AS bukvy,
       SUBSTRING(grp FROM 4)       AS nomer
FROM researchers
WHERE grp IS NOT NULL;

SUBSTRING(s FROM n FOR k) вырезает k символов, начиная с n-го. Символы считают с единицы. Без FOR k берёт всё до конца.

Р первый символ, И второй, дефис третий, номер с четвёртого. Выйдет РИ и 250932, у Ивановой РИ и 250931.

В MySQL вместо FROM … FOR обычно пишут через запятую: SUBSTRING(grp, 4), PostgreSQL понимает и так.

Сделай сам. Первые две цифры номера группы это год поступления, у тебя 25. Достань их из grp.
Показать ответСкрыть ответ 
SELECT full_name, SUBSTRING(grp FROM 4 FOR 2) AS god
FROM researchers;

У троих 25, у Смирнова NULL: кусок от пустоты тоже пустота.

Начать счёт с нуля, как в Python: FROM 3 FOR 2. Получится «-2», дефис и первая цифра. В SQL первый символ имеет номер 1.

SUBSTRING(s FROM n FOR k): k символов с n-го, счёт с 1.

Без FOR берёт до конца текста.

Шаг 7 из 12

LEFT и RIGHT: начало и конец

Когда кусок нужен с самого начала или с самого конца, считать номер символа незачем.

SELECT name, LEFT(name, 3) AS nachalo, RIGHT(name, 3) AS konec
FROM datasets
WHERE id = 3;

LEFT(s, k) возвращает первые k символов, RIGHT(s, k) последние k. Это короткая запись для SUBSTRING, когда кусок у края.

У California Housing выйдет Cal и ing. LEFT(name, 3) то же самое, что SUBSTRING(name FROM 1 FOR 3).

Сделай сам. Для каждого исследователя первая буква фамилии и последние две буквы почты.
Показать ответСкрыть ответ 
SELECT full_name, LEFT(full_name, 1) AS bukva, RIGHT(email, 2) AS konec
FROM researchers;

П, Щ, И, С. Конец почты у всех ru.

Ждать, что RIGHT выдаст буквы задом наперёд, «ur». Он только берёт кусок с конца, а порядок букв внутри не меняет.

LEFT(s, k) первые k символов, RIGHT(s, k) последние k.

Порядок букв в куске остаётся как в тексте.

Шаг 8 из 12

POSITION: где стоит символ

Логин в почте разной длины: stepan длиннее, чем oleg. Чтобы отрезать его, надо знать, где стоит @.

SELECT email, POSITION('@' IN email) AS gde
FROM researchers;

POSITION(кусок IN s) возвращает номер символа, с которого кусок первый раз встречается в тексте. Если куска нет, возвращает 0.

emailgde
stepan@urfu.ru7
azat@urfu.ru5
maria@urfu.ru6
oleg@urfu.ru5

В stepan шесть букв, поэтому @ седьмая. На слайде для MySQL то же самое записано через LOCATE('@', email).

Сделай сам. На каком месте пробел в full_name у каждого исследователя?
Показать ответСкрыть ответ 
SELECT full_name, POSITION(' ' IN full_name) AS probel
FROM researchers;

Павленко 9, Щайхутдинов 12, Иванова 8, Смирнов 8. Номер пробела на один больше длины фамилии.

Перепутать порядок: POSITION(full_name IN ' '). Тогда база ищет всё имя внутри одного пробела, не находит и даёт 0 у всех. Сначала что ищем, после IN где ищем.

POSITION('@' IN email): номер символа, счёт с 1.

Не нашлось: 0.

Шаг 9 из 12

SUBSTRING и POSITION вместе: логин, домен, маска

Теперь режем почту по @. Логин всё, что до неё, домен с неё до конца.

SELECT email,
       SUBSTRING(email FOR POSITION('@' IN email) - 1) AS login,
       SUBSTRING(email FROM POSITION('@' IN email))    AS domen
FROM researchers;

Число в SUBSTRING можно не писать руками, а посчитать функцией. SUBSTRING(s FOR k) без FROM берёт k символов с начала. У stepan@urfu.ru @ седьмая, значит логин это 7 − 1 = 6 первых символов, stepan. Домен с седьмого: @urfu.ru.

Пример со слайда лекции, маска почты:

SELECT CONCAT(LEFT(email, 2), '***',
              SUBSTRING(email FROM POSITION('@' IN email))) AS maska
FROM researchers;

Выйдет st***@urfu.ru, az***@urfu.ru, ma***@urfu.ru, ol***@urfu.ru. LEFT из шага 7 берёт две первые буквы, CONCAT склеивает их со звёздочками и доменом.

Сделай сам. Раздели full_name на фамилию и имя двумя столбцами. Через SUBSTRING и POSITION.
Показать ответСкрыть ответ 
SELECT SUBSTRING(full_name FOR POSITION(' ' IN full_name) - 1)  AS familiya,
       SUBSTRING(full_name FROM POSITION(' ' IN full_name) + 1) AS imya
FROM researchers;

Павленко Степан, Щайхутдинов Азат, Иванова Мария, Смирнов Олег. У имени + 1, чтобы не захватить сам пробел.

Забыть - 1 у фамилии. Тогда в неё попадёт пробел, «Павленко » с пробелом на конце. Глазами его не видно, но familiya = 'Павленко' такую строку уже не найдёт.

До символа: SUBSTRING(s FOR POSITION(c IN s) - 1).

С символа: SUBSTRING(s FROM POSITION(c IN s)).

Шаг 10 из 12

SPLIT_PART: разрезать по символу короче

Логин и домен из прошлого шага в PostgreSQL достают одной функцией, без подсчёта позиций.

SELECT email,
       SPLIT_PART(email, '@', 1) AS login,
       SPLIT_PART(email, '@', 2) AS domen
FROM researchers;

SPLIT_PART(s, разделитель, n) режет текст по разделителю на куски и возвращает кусок номер n. Куски считают с единицы. Сам разделитель ни в один кусок не попадает.

У stepan@urfu.ru первый кусок stepan, второй urfu.ru, уже без @. В прошлом шаге домен выходил с @, здесь без него. В MySQL такой функции нет, там режут через SUBSTRING и POSITION, как в шаге 9.

Сделай сам. Достань имя из full_name через SPLIT_PART.
Показать ответСкрыть ответ 
SELECT full_name, SPLIT_PART(full_name, ' ', 2) AS imya
FROM researchers;

Степан, Азат, Мария, Олег. Фамилия была бы SPLIT_PART(full_name, ' ', 1).

Считать куски с нуля, как в Python: SPLIT_PART(full_name, ' ', 0). PostgreSQL ответит field position must not be zero, «номер куска не может быть нулём».

SPLIT_PART(s, '@', 1): кусок до первого @, счёт с 1.

Разделитель в куски не попадает.

Шаг 11 из 12

REPLACE: заменить кусок везде

В твоих ссылках обратные косые: https:\\gobro. В адресе нужны прямые.

SELECT link, REPLACE(link, '\', '/') AS link2
FROM datasets;

REPLACE(s, что, на_что) заменяет каждое вхождение куска во всём тексте. Различает большие и маленькие буквы. Если куска нет, текст остаётся как был.

Получится https://gobro, https://brat и так далее, обе косые заменились. У Titanic ссылки нет, и REPLACE от NULL тоже NULL.

Так же правят опечатку в значении: REPLACE(type_task, 'analize', 'analysis') у pirs даст analysis, у остальных ничего не поменяет. Это только показ. Чтобы исправить в самой таблице, ту же функцию ставят в UPDATE … SET link = REPLACE(link, '\', '/'), как в уроке про UPDATE.

Сделай сам. Названия наборов, где пробелы заменены на подчёркивание. Какие названия изменятся?
Показать ответСкрыть ответ 
SELECT name, REPLACE(name, ' ', '_') AS bez_probelov
FROM datasets;

Изменятся два: California_Housing и IMDB_Reviews. Остальные без пробелов, их REPLACE вернёт как были.

Перепутать порядок аргументов: REPLACE(name, '_', ' '). Это «подчёркивание на пробел», а подчёркиваний в названиях нет, и ничего не поменяется. Сначала что ищем, потом на что меняем.

REPLACE(s, 'что', 'на что') меняет все вхождения.

В SELECT только показ, в таблице меняет UPDATE … SET x = REPLACE(…).

Шаг 12 из 12

Всё вместе: чистый ключ и поиск

Функции вкладываются одна в другую. Сделаем из названия набора ключ для файла: без пробелов по краям, пробелы внутри на подчёркивание, всё маленькими.

SELECT name, LOWER(REPLACE(TRIM(name), ' ', '_')) AS klyuch
FROM datasets;

Вложенные функции считаются изнутри наружу. Сначала TRIM, потом REPLACE над его ответом, потом LOWER. Выйдет iris, pirs, california_housing, imdb_reviews, mnist, titanic.

Строковые функции работают и в WHERE. Названия из двух слов можно найти так:

SELECT name FROM datasets WHERE POSITION(' ' IN name) > 0;
SELECT name FROM datasets WHERE name LIKE '% %';

Оба дают California Housing и IMDB Reviews. LIKE короче, а POSITION пригодится, когда нужен ещё и номер символа.

Сделай сам. Почту иногда вводят как попало: « Stepan@URFU.ru». Найди исследователей с почтой на домене urfu.ru так, чтобы такая запись тоже нашлась.
Показать ответСкрыть ответ 
SELECT full_name
FROM researchers
WHERE LOWER(TRIM(email)) LIKE '%@urfu.ru';

Сейчас все четверо. TRIM убирает пробел в начале, LOWER большие буквы. Можно и TRIM(email) ILIKE '%@urfu.ru'.

Забыть TRIM, если пробел стоит в конце: «stepan@urfu.ru ». Шаблон '%@urfu.ru' требует, чтобы текст кончался на ru, а он кончается пробелом. Такая строка не найдётся, хотя почта правильная.

Вложенные функции считаются изнутри наружу: LOWER(REPLACE(TRIM(s), ' ', '_')).

Перед сравнением текста его чистят: TRIM и LOWER.
