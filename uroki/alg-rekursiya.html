Java с нуля и рекурсия

Алгоритмы · лабы 26.09 и 3.10 · около 55 минут

Две лабы Зубарева. 26.09 был Java для алгоритмов с нуля: типы, калькулятор, FizzBuzz, «угадай число», статистика по массиву. 3.10 рекурсия и перебор: сумма цифр, скобки, подмножества. Лабы идут на Java 17, поэтому и код здесь на Java, в стиле Зубарева: всё в одном классе, а главная функция main вызывает остальные. Что значат служебные слова перед функциями, разберём по ходу. Двенадцать шагов: первые восемь это минимум Java, без которого рекурсию не написать, последние четыре сама рекурсия.

Как проходить: читаешь шаг, переписываешь рамку «Перепиши в тетрадь», решаешь «сделай сам» на бумаге и только потом открываешь ответ. Код из шагов можно запустить в IntelliJ IDEA и сверить вывод. Если в шаге что-то непонятно, дальше не иди: сначала задай вопрос по этому шагу.

Первая программа: класс и main

В Java у каждой переменной тип, и он пишется перед именем. Поменять тип потом нельзя. В коде ниже после // идёт комментарий: Java его не читает, он для человека.

Цикл for и условие if: FizzBuzz

Задача с лабы. Напечатать числа от 1 до 15, но вместо чисел, делящихся на 3, писать Fizz, на 5 писать Buzz, а на 3 и на 5 сразу писать FizzBuzz.

for (int i = 1; i <= 15; i++) {
    if (i % 15 == 0) System.out.println("FizzBuzz");
    else if (i % 3 == 0) System.out.println("Fizz");
    else if (i % 5 == 0) System.out.println("Buzz");

Вывод: 1, 2, Fizz, 4, Buzz, Fizz, 7, 8, Fizz, Buzz, 11, Fizz, 13, 14, FizzBuzz. Число делится на 3 и на 5 сразу, только если делится на 15.

Шаг 6 из 12

Свои функции: калькулятор

Калькулятор с лабы: два числа и знак операции, ответ число. Оформим его отдельной функцией. В Java функции называют методами.

static double calc(double a, char op, double b) {
    switch (op) {
        case '+': return a + b;
        case '-': return a - b;
        case '*': return a * b;
        case '/': return a / b;
        default:
            System.out.println("Не знаю операцию " + op);
            return 0;
    }
}

Метод: static тип_ответа имя(тип имя, …) { … }. return отдаёт ответ и сразу выходит из метода. Если ответа нет, тип пишут void, как у main. Пишется внутри класса рядом с main, вызывается по имени: calc(6, '/', 4).

Слово static значит, что метод принадлежит самому классу, и main может вызвать его просто по имени. Без static пришлось бы сначала создавать объект класса, в этом курсе так не делаем.

calc(6, '/', 4) вернёт 1.5. char это один символ, он пишется в одинарных кавычках. switch сравнивает op по очереди с каждым case и выполняет подходящую ветку. Если не подошёл ни один, срабатывает default. На ноль double делится без ошибки: calc(1, '/', 0) даст Infinity.

Сделай сам. Напиши метод sign, который получает int x и возвращает −1, если x отрицательный, 0 для нуля и 1 для положительного.
Показать ответСкрыть ответ 
static int sign(int x) {
    if (x < 0) return -1;
    if (x == 0) return 0;
    return 1;
}

else не нужен: return уже вышел из метода, до следующих строк дело не дойдёт.

Забыть последний return 1. Компилятор скажет missing return statement: метод обещал вернуть int, а для положительных x ничего не вернул.

static int f(int x) { … return …; }. void, если ответа нет.

return сразу выходит из метода.

Цикл while и break

for удобен, когда заранее известно, сколько раз повторять. Если неизвестно, берут while. Сколько раз 100 делится пополам, пока не станет 1?

int n = 100;
int steps = 0;
while (n > 1) {
    n = n / 2;
    steps++;
}
System.out.println(steps);   // 6

n проходит 100, 50, 25, 12, 6, 3, 1. Делений шесть, на единице условие n > 1 ложно, и цикл кончается. Это логарифм из первого урока.

while (условие) { … } повторяет тело, пока условие верно. while (true) крутится бесконечно, и выйти из него можно командой break: она сразу прерывает цикл.

while (true) {

    k++;
}
System.out.println(k);

Шаг 8 из 12

Ввод с клавиатуры: «угадай число»

Программа загадывает число от 1 до 100, ты вводишь догадки, она отвечает «больше» или «меньше». Цикл тут из прошлого шага: while (true), а break срабатывает, когда угадал.

import java.util.Random;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int secret = new Random().nextInt(100) + 1;   // от 1 до 100
        int tries = 0;
        while (true) {
            int guess = in.nextInt();
            tries++;
            if (guess < secret) System.out.println("больше");
            else if (guess > secret) System.out.println("меньше");
            else {
                System.out.println("угадал за " + tries);
                break;
            }
        }
    }
}

Scanner читает ввод: in.nextInt() ждёт число с клавиатуры. import подключает нужные классы и пишется в самом верху файла.

Слово new создаёт объект. new Scanner(System.in) делает читалку клавиатуры, new Random() делает генератор случайных чисел. Больше про объекты в этом уроке знать не нужно.

nextInt(100) даёт число от 0 до 99, плюс один, от 1 до 100. Как угадать быстрее всего? Каждый раз называть середину оставшегося отрезка, тогда любой ответ отбрасывает половину. Это бинарный поиск, и он угадает любое число не больше чем за 7 попыток: 2⁷ = 128 ≥ 100. Пример, загадано 37: 50 → «меньше», 25 → «больше», 37 → угадал.

Шаг 9 из 12

Рекурсия: база и шаг

Задача с лабы 3.10: сумма цифр числа, 12345 → 15. Заметим: сумма цифр 12345 это последняя цифра 5 плюс сумма цифр 1234. А сумма цифр 1234 это 4 плюс сумма цифр 123. Задача сводится к такой же, только поменьше.

static int digitSum(int n) {
    if (n < 10) return n;              // база: одна цифра
    return n % 10 + digitSum(n / 10);  // шаг
}

n % 10 последняя цифра, n / 10 число без неё, это деление целых из шага 3.

Рекурсия: метод вызывает сам себя на задаче поменьше. У неё обязательно есть база, задача, ответ на которую известен без вызовов, и шаг, который сводит задачу к меньшей. Каждый шаг обязан приближать к базе.

Сделай сам. Чему равен digitSum(9075)? Распиши цепочку вызовов.
Показать ответСкрыть ответ

5 + digitSum(907) → 7 + digitSum(90) → 0 + digitSum(9) → база 9. Итого 5 + 7 + 0 + 9 = 21.

Перепутать % и /: n / 10 + digitSum(n % 10). Тогда для 9075 выйдет 907 + digitSum(5) = 912. Код работает без ошибок, но считает не то. Цифру отрезает % 10, она и складывается, а в рекурсию уходит остаток числа / 10.

Рекурсия = база (ответ сразу) + шаг (та же задача меньше).

Сумма цифр: база n < 10, шаг n % 10 + f(n / 10).

Шаг 10 из 12

Стек вызовов и глубина

Что происходит при digitSum(345):

digitSum(345)  ждёт  5 + digitSum(34)
  digitSum(34)   ждёт  4 + digitSum(3)
    digitSum(3) = 3           ← база
  digitSum(34) = 4 + 3 = 7    ← сворачиваемся
digitSum(345) = 5 + 7 = 12

Пока вложенный вызов не вернул ответ, внешний ждёт, и его переменные хранятся в памяти. Эту память устроили как стек из первого шага урока про кучи: новый вызов кладётся сверху, закончивший снимается первым.

Стек вызовов хранит все вызовы, которые ещё ждут ответа. Глубина рекурсии это сколько вызовов в нём одновременно. Рекурсия тратит память O(глубина), даже если массивов нет.

Нет базы или шаг не приближает к ней, и вызовы копятся без конца. Стек не бесконечный, и Java падает с StackOverflowError, обычно на глубине порядка десятка тысяч вызовов, точное число зависит от размера стека. Время считается так: число вызовов умножить на работу одного. У суммы цифр вызовов столько, сколько цифр, O(log₁₀ n).

Сделай сам. Сколько вызовов сделает digitSum(1000000) и какая наибольшая глубина стека? Что будет, если шаг написать digitSum(n) вместо digitSum(n / 10)?

У миллиона 7 цифр: 1000000, 100000, 10000, 1000, 100, 10, 1. Семь вызовов, все одновременно в стеке, глубина 7. С digitSum(n) задача не уменьшается, вызовы копятся до StackOverflowError.

Считать глубину 6, по числу «делений на 10». Вызов с базой, digitSum(1), тоже лежит в стеке. Вызовов на один больше, чем делений.

Стек вызовов: ждущие вызовы, сверху новый. Память = O(глубина).

Время = число вызовов × работа одного. Нет базы → StackOverflowError.

Шаг 11 из 12

Перебор: все правильные скобки

Задача с лабы 3.10: вывести все правильные скобочные последовательности из n пар. Правильная значит, что каждая скобка закрыта, и закрывающая не встречается раньше своей открывающей. Для n = 2 это (()) и ()(), а )(() неправильная.

Строим строку по одному символу. На каждом месте пробуем оба варианта, но только разрешённые: открыть можно, пока открытых меньше n, закрыть можно, пока закрытых меньше, чем открытых.

static void gen(String s, int open, int close, int n) {
    if (s.length() == 2 * n) {          // база: строка готова
        System.out.println(s);
        return;
    }
    if (open < n) gen(s + "(", open + 1, close, n);
    if (close < open) gen(s + ")", open, close + 1, n);
}

s.length() это длина строки s. s + "(" даёт новую строку, к которой в конец приписана скобка.

Перебор рекурсией: на каждом шаге ветвимся по всем разрешённым вариантам, база это готовый ответ. Правило «закрыть, только если есть что закрывать» отсекает неправильные ветки сразу, а не после построения.

Вызов gen("", 0, 0, 2) печатает (()), потом ()(). Первой всегда идёт ветка «открыть», поэтому (()) раньше.

Сделай сам. Выпиши, что напечатает gen("", 0, 0, 3), в том же порядке.
Показать ответСкрыть ответ

((())), (()()), (())(), ()(()), ()()(). Пять штук. Для n = 4 их будет 14.

Условие закрытия написать close < n. Тогда пройдут строки вроде ())((): закрывающих не больше трёх, но в начале закрыли больше, чем открыли.

Скобки: открыть если open < n, закрыть если close < open. База: длина 2n.

Все подмножества и откат

Последняя задача лабы 3.10: вывести все подмножества массива {1, 2, 3}. Подмножество это любой набор его элементов, в том числе пустой и весь массив. Для каждого элемента два варианта: не брать или брать.

// вверху файла: import java.util.ArrayList; import java.util.List;
static void subsets(int[] a, int i, List<Integer> cur) {
    if (i == a.length) {             // база: про все элементы решили
        System.out.println(cur);
        return;
    }
    subsets(a, i + 1, cur);          // не берём a[i]
    cur.add(a[i]);
    subsets(a, i + 1, cur);          // берём a[i]
    cur.remove(cur.size() - 1);      // откат: убрали, что добавили
}
// вызов: subsets(new int[]{1, 2, 3}, 0, new ArrayList<>());

List<Integer> это список целых, который умеет расти, как динамический массив из урока про кучи. В угловых скобках тип элементов, Integer это тот же int, только в таком виде его можно положить в список. new ArrayList<>() создаёт пустой такой список. add добавляет в конец, size() говорит, сколько в нём элементов, remove(k) убирает элемент номер k. Значит remove(cur.size() - 1) убирает последний. new int[]{1, 2, 3} создаёт массив прямо в вызове.

Откат: после ветки «взял элемент» убрать его обратно, чтобы следующая ветка начала с того же состояния. Подмножеств у n элементов 2ⁿ, поэтому перебор стоит O(2ⁿ) вызовов. Рекуррента T(n) = 2T(n − 1) + 1, как у Ханоя в уроке про мастер-теорему.

Вывод: [], [3], [2], [2, 3], [1], [1, 3], [1, 2], [1, 2, 3]. Восемь, 2³.

а) Только {3, 7}. Остальные суммы: 0, 3, 5, 7, 8, 12, 15. б) 2²⁰ = 1 048 576, это доли секунды. 2⁴⁰ ≈ 1.1 · 10¹², это около 11 000 секунд, три часа. Добавили 20 элементов, а время выросло в миллион раз.

Забыть строку отката. Тогда добавленный элемент остаётся в cur навсегда, и следующие ветки печатают лишнее, например [3, 2] вместо [2]. Каждому add в переборе нужен свой remove.
