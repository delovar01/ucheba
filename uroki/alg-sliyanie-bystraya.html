Две главные сортировки «разделяй и властвуй». Рекурренту слияния ты уже видел в уроке про мастер-теорему, а слияние разбирали на лабе 17.10. Здесь сами алгоритмы: как работают по шагам, код на Java, время, память и устойчивость. Это вопросы 5 и 6 из пробного экзамена. Девять шагов.

Шаг 1 из 9

Слияние двух отсортированных массивов

Две отсортированные пачки: [1, 4, 7] и [2, 3, 8]. Надо получить одну отсортированную. Самый маленький элемент точно стоит первым в одной из пачек, больше ему негде быть.

Слияние: меньший из двух первых в ответ, кончилась пачка → дописать остаток. Θ(n).

Шаг 2 из 9

Сортировка слиянием: пополам до одного

Слияние умеет склеить две отсортированные половины. Откуда их взять? Отсортировать каждую половину этой же сортировкой. Массив из одного элемента уже отсортирован, это база рекурсии.

Сортировка слиянием: если элементов меньше двух, ничего не делаем. Иначе делим пополам, сортируем левую половину, сортируем правую, сливаем. Это схема «разделяй и властвуй»: разделить на части, решить части, собрать ответ.

Массив [5, 2, 4, 7, 1, 3, 2, 6]. Снизу вверх по уровням слияния:

5 2 | 4 7 | 1 3 | 2 6      пары
 2 5    4 7    1 3    2 6  слили пары
  2 4 5 7   |   1 2 3 6    слили четвёрки
   1 2 2 3 4 5 6 7         слили всё

Уровней три, это log₂ 8. На каждом уровне слияния вместе проходят все 8 элементов.

Сделай сам. Отсортируй слиянием [38, 27, 43, 3, 9, 82, 10]. Элементов 7, середина левее: левая половина из 3, правая из 4. Запиши все слияния по порядку.

Левая [38, 27, 43] делится на [38] и [27, 43]. Сливаем 27 и 43: [27, 43]. Сливаем с 38: [27, 38, 43].

Правая [3, 9, 82, 10]: [3, 9], [10, 82], вместе [3, 9, 10, 82].

Последнее слияние: [3, 9, 10, 27, 38, 43, 82].

Сливать половины, которые ещё не отсортированы. Слияние работает только на отсортированных пачках. Сначала рекурсия доводит каждую половину до порядка, и только потом её сливают.

mergeSort: < 2 элементов → готово. Иначе пополам, сортирую обе половины, сливаю.

Шаг 3 из 9

Слиянием на Java, время и память

// сортирует a[lo..hi), hi не входит
static void mergeSort(int[] a, int lo, int hi, int[] tmp) {
    if (hi - lo <= 1) return;               // 0 или 1 элемент
    int mid = (lo + hi) / 2;
    mergeSort(a, lo, mid, tmp);
    mergeSort(a, mid, hi, tmp);
    int i = lo, j = mid, k = lo;            // слияние
    while (i < mid && j < hi) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];
        else              tmp[k++] = a[j++];
    }
    while (i < mid) tmp[k++] = a[i++];      // остаток левой
    while (j < hi)  tmp[k++] = a[j++];      // остаток правой
    for (k = lo; k < hi; k++) a[k] = tmp[k];
}

// в main:
int[] a = {5, 2, 4, 7, 1, 3, 2, 6};
mergeSort(a, 0, a.length, new int[a.length]);
System.out.println(Arrays.toString(a));    // [1, 2, 2, 3, 4, 5, 6, 7]

tmp[k++] = a[i++] значит: записать, потом увеличить оба счётчика на 1. Для Arrays.toString вверху файла нужен import java.util.*;.

Рекуррента T(n) = 2T(n/2) + Θ(n), по мастер-теореме Θ(n log n). Это в любом случае, на любых данных: массив всегда делится ровно пополам. Дополнительная память Θ(n) на массив tmp.

Сделай сам. Почему условие hi - lo <= 1, а не hi - lo == 1? И сколько примерно сравнений сделает сортировка слиянием на миллионе элементов, если log₂ 10⁶ ≈ 20?
Показать ответСкрыть ответ

Кусок может оказаться пустым: например, если позвать mergeSort на пустом массиве, hi - lo = 0. С условием == 1 рекурсия на нём не остановится. Сравнений не больше n log₂ n ≈ 10⁶ · 20 = 2 · 10⁷.

Забыть последний цикл, который копирует tmp обратно в a. Слитый кусок останется лежать в tmp, а в a будет старый порядок, и следующие слияния возьмут неотсортированные половины.

Слиянием: T(n) = 2T(n/2) + n = Θ(n log n) всегда. Память Θ(n).

Шаг 4 из 9

Устойчивость: равные не меняются местами

Сортируем людей по оценке: Аня 4, Боря 3, Вика 4, Гоша 3. Список был по алфавиту. Хорошо бы, чтобы среди равных оценок алфавит сохранился: Боря раньше Гоши, Аня раньше Вики.

Сортировка устойчивая, если элементы с равными ключами остаются в том же порядке, что были. Сортировка слиянием устойчивая, если при равенстве брать элемент из левой половины. В коде это <= в строке if (a[i] <= a[j]).

С <= выйдет: Боря 3, Гоша 3, Аня 4, Вика 4. Алфавит внутри равных сохранился.

Сделай сам. Что выйдет на этом же примере, если в слиянии написать < вместо <=? Половины: Аня 4, Боря 3 и Вика 4, Гоша 3.
Показать ответСкрыть ответ

Левая половина после сортировки: Боря 3, Аня 4. Правая: Гоша 3, Вика 4. Сливаем: 3 и 3 равны, при < берём правую, Гошу. Потом Боря 3 против Вики 4, Боря. Потом Аня 4 против Вики 4, равны, берём правую, Вику. Итог: Гоша, Боря, Вика, Аня. Числа отсортированы, но порядок равных перевернулся.

Думать, что устойчивость важна только для «красоты». Сортировки делают цепочкой: сначала по имени, потом по оценке. Неустойчивая вторая сортировка сломает результат первой. Поразрядная сортировка из урока про линейные сортировки на этом и держится.

Устойчивая: равные сохраняют порядок. Слияние устойчиво при <=, берём из левой.

Шаг 5 из 9

Быстрая сортировка: разбиение вокруг опорного

Другой способ разделять. Слияние делит пополам не глядя, а всю работу делает при сборке. Быстрая сортировка, наоборот, вся работа в делении, а собирать ничего не надо.

Быстрая сортировка: выбираем опорный элемент. Переставляем массив так, чтобы слева от опорного были меньшие, справа не меньшие, а опорный встал на своё окончательное место. Это разбиение. Потом той же сортировкой сортируем левую и правую части.

Разбиение по схеме Ломуто, опорный последний элемент. Счётчик i показывает, куда класть следующий меньший. Идём j по массиву, нашли меньший опорного, меняем его с a[i] и сдвигаем i. В конце меняем опорный с a[i].

Массив [3, 7, 1, 6, 2, 5, 4], опорный 4:

ja[j]что делаеммассивi

4 стоит на месте 3 и больше не сдвинется. Слева 3, 1, 2, все меньше. Справа 7, 5, 6, все больше. Их сортируют отдельно.

Опорный 4. j = 0: 6 пропуск. j = 1: 2 меньше, обмен a[0] и a[1], [2, 6, 8, 5, 1, 7, 4], i = 1. j = 2, 3: 8 и 5 пропуск. j = 4: 1 меньше, обмен a[1] и a[4], [2, 1, 8, 5, 6, 7, 4], i = 2. j = 5: 7 пропуск. Опорный в a[2]: [2, 1, 4, 5, 6, 7, 8], место 2.

Ждать, что после разбиения половины уже отсортированы. Слева 2, 1, порядок не тот. Разбиение обещает только «меньше слева, больше справа», остальное доделает рекурсия.

Быстрая: разбиение вокруг опорного (меньше | опорный | не меньше), потом рекурсия на обе части.

Ломуто: опорный последний, i = куда класть меньший, в конце опорный в a[i].

Шаг 6 из 9

Быстрая сортировка на Java

static void swap(int[] a, int x, int y) {
    int t = a[x]; a[x] = a[y]; a[y] = t;
}

static int partition(int[] a, int lo, int hi) {
    int pivot = a[hi];                     // опорный последний
    int i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) {
            swap(a, i, j);
            i++;
        }
    swap(a, i, hi);                        // опорный на своё место
    return i;
}

// сортирует a[lo..hi], hi входит
static void quickSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
}

// в main:
int[] a = {3, 7, 1, 6, 2, 5, 4};
quickSort(a, 0, a.length - 1);             // [1, 2, 3, 4, 5, 6, 7]

В quickSort опорный a[p] в рекурсию не идёт: lo..p − 1 и p + 1..hi. Он уже на месте. Сортировка идёт внутри того же массива, второй массив не нужен, только стек рекурсии.

На примере: разбиение всего массива ставит 4 на место 3. Левая часть [3, 1, 2] с опорным 2 даёт [1, 2, 3]. Правая [7, 5, 6] с опорным 6 даёт [5, 6, 7]. Куски по одному элементу рекурсия не трогает.

Сделай сам. Что будет, если в quickSort написать quickSort(a, lo, p) вместо quickSort(a, lo, p - 1)? Подумай про кусок [1, 2], где опорный 2.
Показать ответСкрыть ответ

Разбиение [1, 2] ставит 2 на место 1, p = hi. Вызов quickSort(a, lo, p) получает тот же кусок [1, 2], снова p = hi, и так без конца. Программа упадёт с StackOverflowError: стек вызовов переполнится.

Путать границы двух сортировок. В mergeSort из шага 3 правая граница не входит, a.length. В quickSort входит, a.length - 1. Перепутаешь, и выйдешь за массив с ArrayIndexOutOfBoundsException.

quickSort: p = partition, рекурсия на lo..p−1 и p+1..hi. Опорный не трогаю. Сортирует на месте.

Шаг 7 из 9

Худший случай: Θ(n²)

Дадим быстрой сортировке уже отсортированный [1, 2, 3, 4, 5]. Опорный 5, все меньше, разбиение даёт левую часть из 4 и пустую правую. Потом опорный 4, левая из 3. И так далее.

Худший случай быстрой сортировки: опорный каждый раз оказывается самым маленьким или самым большим. Тогда кусок уменьшается всего на один элемент: T(n) = T(n − 1) + Θ(n) = Θ(n²). Глубина рекурсии n.

Сравнений на [1, 2, 3, 4, 5]: 4 + 3 + 2 + 1 = 10. В общем случае n(n − 1)/2. Для тысячи элементов это 499 500 сравнений, а при удачных опорных было бы около 1000 · 10 = 10⁴.

Сделай сам. Будет ли худший случай на [5, 4, 3, 2, 1], отсортированном наоборот? А на [2, 2, 2, 2]? Посчитай сравнения.
Показать ответСкрыть ответ

Да, оба худшие. [5, 4, 3, 2, 1]: опорный 1 самый маленький, справа остаётся 4 элемента, дальше опорные тоже крайние, сравнений 4 + 3 + 2 + 1 = 10. [2, 2, 2, 2]: условие a[j] < pivot ни разу не выполняется, опорный встаёт в начало, справа остаются 3 элемента. Сравнений 3 + 2 + 1 = 6, это тоже n(n − 1)/2.

Думать, что худший случай бывает только на «специально плохих» данных. Уже отсортированный массив и массив из одинаковых значений встречаются в жизни постоянно: например, добавили пару записей к отсортированной таблице и сортируют снова.

Худший: опорный крайний, T(n) = T(n−1) + n = Θ(n²), глубина n. Бывает на отсортированном и на равных.

Шаг 8 из 9

Средний случай и как избежать худшего

Если опорный делит кусок хотя бы примерно пополам, выходит та же рекуррента, что у слияния: 2T(n/2) + n. Даже деление в пропорции 1 к 9 на каждом шаге даёт n log n, только с большим множителем.

Средний случай быстрой сортировки Θ(n log n). Чтобы худший не случался на типичных данных, опорный выбирают иначе. Случайный опорный: берут случайный элемент куска и меняют его с последним. Медиана трёх: из первого, среднего и последнего берут средний по величине. Стек рекурсии в среднем O(log n).

// случайный опорный: первые строки partition
int r = lo + (int) (Math.random() * (hi - lo + 1));
swap(a, r, hi);
int pivot = a[hi];

Math.random() даёт дробь от 0 до 1, умножение и (int) превращают её в номер от lo до hi. Быстрая сортировка неустойчивая: обмены прыгают через равные элементы.

Сделай сам. Массив [1, 2, 3, 4, 5, 6, 7]. Какой опорный даст медиана трёх для всего массива? Как он разобьёт массив?
Показать ответСкрыть ответ

Первый 1, средний 4, последний 7. Средний по величине 4. Слева окажутся 1, 2, 3, справа 5, 6, 7, ровно пополам. На отсортированном массиве медиана трёх даёт лучший случай вместо худшего.

Брать средний по номеру элемент и считать, что это медиана трёх. Медиана трёх это средний по величине из трёх чисел. На [9, 1, 5] средний по номеру 1, а медиана 5.

Средний Θ(n log n), стек O(log n). Против худшего: случайный опорный или медиана трёх.

Быстрая неустойчива.

Слияние предсказуемо и устойчиво, но просит память. Быстрая на практике обычно быстрее, потому что работает на месте и бережно обходится с кэшем процессора, но у неё есть худший случай. Обе оптимальны среди сортировок сравнениями: быстрее n log n нельзя, это нижняя граница из урока про мастер-теорему.

В самой Java так и сделано. Arrays.sort для массива int[] использует быструю сортировку с двумя опорными. Для массива объектов, например строк, используется сортировка на основе слияния, потому что там важна устойчивость.

Сделай сам. Что выберешь и почему: а) отсортировать миллион чисел, памяти мало, б) отсортировать заказы по сумме так, чтобы заказы с равной суммой остались по времени, в) сортировка в системе, где худшее время ответа должно быть гарантировано.
Показать ответСкрыть ответ

а) Быструю со случайным опорным: на месте, без второго массива. б) Слиянием: нужна устойчивость. в) Слиянием: у неё n log n в худшем случае, у быстрой худший n².

Отвечать на билете «быстрая всегда быстрее, потому что так называется». Название историческое. В худшем случае она медленнее слияния, и на экзамене это спросят.

Слияние: всегда n log n, память n, устойчиво. Быстрая: в среднем n log n, худший n², на месте, неустойчива.
