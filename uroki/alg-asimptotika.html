Шаг 1 из 10

Размер входа и число операций T(n)

Ищем минимум в массиве [5, 3, 8, 1, 4]. Запоминаем первое число 5, потом сравниваем его по очереди с 3, 8, 1 и 4, и каждый раз оставляем меньшее. Сравнений вышло 4.

Секунды мерить бесполезно: на другом компьютере выйдет другое число. Поэтому считают операции: сравнения, сложения, записи в память. И считают их не для одного массива, а как формулу от размера.

Размер входа n это сколько данных пришло на вход, для массива число элементов. T(n) это число элементарных операций алгоритма на самом плохом входе размера n. Это называют худшим случаем.

Для минимума T(n) = n − 1: каждый элемент, кроме первого, сравнили один раз. Худший случай берут потому, что он даёт гарантию на любом входе.

Зачем это. Компьютер делает около 10⁸ простых операций в секунду. При n = 10⁶ алгоритм с n² операций сделает 10¹² операций, это 10⁴ секунд, почти три часа. Алгоритм с n log₂ n сделает около 2 · 10⁷ операций, пятую часть секунды.

log₂ n показывает, сколько раз n можно поделить пополам, пока не останется 1. Например, log₂ 8 = 3: 8, 4, 2, 1. Для миллиона выходит около 20. Подробно в шаге 1 матана, а пока хватит этого смысла.

Сделай сам. Ищем, есть ли в массиве из n элементов число 7, перебирая элементы слева направо. Сколько сравнений в худшем случае? Какой вход худший?
Показать ответСкрыть ответ

T(n) = n. Худший вход: семёрки нет совсем или она стоит последней. Тогда приходится посмотреть все n элементов.

Ответить «одно сравнение, если 7 стоит первой». Это лучший случай. Он ничего не обещает: на другом входе работа будет в n раз дольше. По умолчанию сложность считают по худшему.

n это размер входа. T(n) это число операций на худшем входе размера n.

Минимум массива: T(n) = n − 1.

Шаг 2 из 10

O большое: верхняя граница

Точная формула вроде 3n + 5 часто не нужна. Важно, что при росте n она растёт как n, а тройка и пятёрка зависят от того, что именно считать операцией.

Проверим, что 3n + 5 ≤ 4n. Переносим: 5 ≤ n. Значит, начиная с n = 5, функция 3n + 5 не больше 4n. Говорят: 3n + 5 = O(n).

f(n) = O(g(n)), если есть число c > 0 и номер n₀, что f(n) ≤ c · g(n) для всех n ≥ n₀. Читается «f растёт не быстрее g». Это как знак ≤, только с точностью до множителя.

Две детали. Числа c и n₀ выбираешь ты сам, но они не должны зависеть от n. И что творится при маленьких n, неважно, смотрим только на n ≥ n₀. Здесь подошли c = 4 и n₀ = 5. Подошли бы и c = 8, n₀ = 1: 3n + 5 ≤ 3n + 5n = 8n.

Сделай сам. Докажи, что 2n + 10 = O(n): подбери c и n₀.
Показать ответСкрыть ответ

Возьмём c = 3. 2n + 10 ≤ 3n значит 10 ≤ n, то есть n₀ = 10. Можно и c = 12, n₀ = 1: при n ≥ 1 верно 10 ≤ 10n, поэтому 2n + 10 ≤ 12n.

Взять c = 2. Тогда нужно 2n + 10 ≤ 2n, то есть 10 ≤ 0, и это неверно ни при каком n. Множитель должен быть с запасом, больше, чем при n в самой функции.

f = O(g) ⇔ есть c > 0 и n₀: f(n) ≤ c·g(n) при всех n ≥ n₀.

c и n₀ не зависят от n.

Шаг 3 из 10

Ω и Θ: нижняя граница и точный порядок

O говорит только «не быстрее». Формально n = O(n³) тоже правда, но толку от неё мало. Нужна ещё граница снизу.

f = Ω(g) («омега»), если f(n) ≥ c · g(n) при всех n ≥ n₀, растёт не медленнее. f = Θ(g) («тета»), если верно и O, и Ω сразу: c₁ · g(n) ≤ f(n) ≤ c₂ · g(n). Это точный порядок роста.

Пример с лекции: 3n² + 10n + 5 = Θ(n²).

  1. Снизу: 3n² + 10n + 5 ≥ 3n² при любом n. Значит c₁ = 3.
  2. Сверху: при n ≥ 1 верно 10n ≤ 10n² и 5 ≤ 5n². Сумма не больше 3n² + 10n² + 5n² = 18n², значит c₂ = 18.
  3. Обе границы верны с n₀ = 1, поэтому Θ(n²).
Сделай сам. Докажи ½n² − 3n = Θ(n²): найди c₁, c₂ и n₀. Подсказка для низа: здесь минус, и выкинуть слагаемое, как в примере, нельзя. Найди, с какого n вычитаемое 3n не больше ¼n². Тогда от ½n² отнимается не больше четверти n² и остаётся хотя бы ¼n².
Показать ответСкрыть ответ

Сверху: ½n² − 3n ≤ ½n², c₂ = ½. Снизу: 3n ≤ ¼n² при n ≥ 12 (делим на n: 3 ≤ n/4). Тогда ½n² − 3n ≥ ½n² − ¼n² = ¼n², c₁ = ¼. Итого c₁ = ¼, c₂ = ½, n₀ = 12. Проверка на n = 12: 72 − 36 = 36, и ¼ · 144 = 36, равенство.

Взять n₀ = 1. При n = 1 функция равна 0.5 − 3 = −2.5, она отрицательная и меньше любого c₁ · 1. Нижняя граница работает только с того места, где минус уже не перевешивает.

Ω: f ≥ c·g (не медленнее). Θ: и O, и Ω (c₁g ≤ f ≤ c₂g).

O ≈ «≤», Ω ≈ «≥», Θ ≈ «=» с точностью до множителя.

Шаг 4 из 10

Правила упрощения

Доказывать через c и n₀ каждый раз долго. Из определения сразу следуют правила, по ним O пишут за секунду.

Множители-константы выбрасываем: O(8n + 6) = O(n). В сумме остаётся самое быстрое слагаемое: O(3n² + 7n + 6) = O(n²). Какое слагаемое быстрее, смотрим по лестнице роста.

Лестница из шага 5 матана, каждая ступень растёт быстрее всех левых:

1 ≪ log n ≪ √n ≪ n ≪ n log n ≪ n² ≪ n³ ≪ 2ⁿ ≪ n!

Знак ≪ читается «растёт гораздо медленнее». n! читается «эн факториал», это произведение 1 · 2 · 3 · … · n, например 4! = 24. Единица в начале значит число операций, которое от n не зависит.

Пример:O(10 log n + 85 + n) = O(n), потому что n выше логарифма и числа на лестнице.

Шаг 5 из 10

Основание логарифма неважно, основание степени важно

Почему в O(log n) не пишут основание? По правилу смены основания из шага 2 матана log₂ n = log₁₀ n / log₁₀ 2 ≈ 3.32 · log₁₀ n. Логарифмы отличаются только множителем 3.32, а множители O выбрасывает.

Со степенью иначе. 4ⁿ = (2²)ⁿ = 2²ⁿ. Делим: 4ⁿ / 2ⁿ = 2ⁿ, и эта дробь растёт без конца. Никакой постоянный множитель c не удержит 4ⁿ ≤ c · 2ⁿ.

Основание логарифма в O неважно: log₂ n = Θ(log₁₀ n). Основание степени важно: 4ⁿ ≠ O(2ⁿ).

Зато сдвиг в показателе не страшен: 2ⁿ⁺¹ = 2 · 2ⁿ, это множитель 2, и 2ⁿ⁺¹ = O(2ⁿ).

Сделай сам. Верно или нет: а) log₃ n = Θ(log₂ n), б) 2²ⁿ = O(2ⁿ), в) 3ⁿ⁺² = O(3ⁿ).
Показать ответСкрыть ответ

а) Да, отличаются множителем log₂ 3 ≈ 1.58. б) Нет, 2²ⁿ = 4ⁿ. в) Да, 3ⁿ⁺² = 9 · 3ⁿ, множитель 9.

Перенести правило с логарифмов на степени: «основание же не важно, значит 4ⁿ = O(2ⁿ)». Логарифмы по разным основаниям отличаются в постоянное число раз, а степени в 2ⁿ раз, и это число растёт.

log_a n = log_b n / log_b a → основание логарифма в O не пишут.

4ⁿ = 2²ⁿ ≠ O(2ⁿ), а 2ⁿ⁺¹ = 2·2ⁿ = O(2ⁿ).

Шаг 6 из 10

Сравнение двух алгоритмов через предел

Алгоритм A делает n log₂ n операций, алгоритм B делает n². Какой лучше на больших данных? Смотрим на дробь A / B, когда n растёт. Предел дроби разобран в шаге 4 матана, правило Лопиталя в шаге 7.

Сокращаем на n: n log₂ n / n² = log₂ n / n. Сверху и снизу бесконечность, поэтому берём Лопиталя: заменяем верх и низ их производными. Производная log₂ n равна 1/(n ln 2), где ln это логарифм по основанию e ≈ 2.72. Производная n равна 1. Выходит (1/(n ln 2)) / 1, а это при росте n уходит в 0. Предел 0, значит A растёт медленнее, A эффективнее.

L = lim f_A(n) / f_B(n). L = 0: A эффективнее. L конечное и больше 0: один порядок, Θ. L = ∞: B эффективнее.

Ещё пример: n³ против 2ⁿ. Производная 2ⁿ равна 2ⁿ ln 2, то есть каждый раз добавляется множитель ln 2. Запись ln² 2 значит ln 2 · ln 2. Лопиталь три раза: 3n² / (2ⁿ ln 2), потом 6n / (2ⁿ ln² 2), потом 6 / (2ⁿ ln³ 2) → 0. Кубический лучше, хотя при n = 5 выходит 125 > 32.

Сделай сам. Сравни через предел: а) A = 100n и B = 0.01n², б) A = 5n² + n и B = n².
Показать ответСкрыть ответ

а) 100n / 0.01n² = 10⁴ / n → 0. A эффективнее, большие константы B не спасают. б) (5n² + n) / n² = 5 + 1/n → 5. Конечное и больше нуля, один порядок Θ(n²).

В пункте а решить по маленькому n: при n = 100 у A 10 000, у B 100, «значит B лучше». Они сравняются при n = 10 000, а дальше B только хуже. Предел смотрит на большие n.

lim f_A / f_B: 0 → A лучше, число > 0 → Θ, один порядок, ∞ → B лучше.

Шаг 7 из 10

Код: блоки подряд и вложенные циклы

Теперь считаем сложность прямо по коду. Два случая.

# подряд
for i in range(n):
    работа()
for j in range(m):
    работа()

# вложенные
for i in range(n):
    for j in range(m):
        работа()

Подряд: сначала n раз, потом m раз, всего n + m. Вложенные: на каждый из n шагов внешнего цикла внутренний делает m шагов, всего n · m.

Блоки подряд складываем, остаётся самый тяжёлый. Вложенные независимые циклы перемножаем: O(f) · O(g) = O(f·g).

Пример с лекции: умножение матриц n × n в лоб. Три вложенных цикла по n, внутри одно умножение и сложение, итого Θ(n³).

for i in range(n):
    for j in range(n):
        for k in range(3):
            работа()
for i in range(n):
    работа()
Показать ответСкрыть ответ

Первый блок n · n · 3 = 3n², второй n. Сумма 3n² + n = Θ(n²). При n = 10: 300 + 10 = 310.

Написать Θ(n³), потому что «три цикла один в другом». Третий цикл идёт до 3, а не до n. Он даёт множитель 3, который выбрасывается.

Подряд: складываем, остаётся тяжёлый. Вложенные: перемножаем.

Цикл до константы даёт множитель, а не n.

Шаг 8 из 10

Внутренний цикл зависит от внешнего

Сравнить каждую пару элементов один раз:

for i in range(n):
    for j in range(i + 1, n):
        сравнить(a[i], a[j])

a[i] это элемент массива a под номером i, счёт с нуля. range(i + 1, n) перебирает числа от i + 1 до n − 1.

Здесь внутренний цикл короче на каждом шаге. При i = 0 он делает n − 1 шагов, при i = 1 делает n − 2, и так до 0. Перемножить n на n нельзя, длины разные.

Если внутренний цикл зависит от внешнего, выписываем число шагов как сумму и считаем её. Здесь (n − 1) + (n − 2) + … + 0 = n(n − 1)/2 = Θ(n²).

Формула суммы 1 + 2 + … + n = n(n + 1)/2 выведена в шаге 8 матана. При n = 1024 выходит 1024 · 1023 / 2 = 523 776. Это вдвое меньше n², но множитель ½ порядок не меняет.

Шаг 10 из 10

Ловушка: внутренний цикл до i, а не до n
