Шаг 1 из 10

Скалярная и агрегатная функция

Два запроса к одной таблице:

SELECT UPPER(name) FROM models;   -- 5 строк
SELECT COUNT(*) FROM models;      -- 1 строка: 5

Так их делит памятка. Скалярная функция обрабатывает значение в каждой строке отдельно: сколько строк пришло, столько и вернулось. Агрегатная собирает много строк в одно значение, по всей таблице или по каждой кучке из GROUP BY.

UPPER скалярная: пять моделей, пять строк большими буквами. COUNT агрегатная: пять строк свернулись в одно число.

Сделай сам. Скалярная или агрегатная: LENGTH, MAX, COALESCE, SUM, TO_CHAR? Сколько строк вернёт SELECT LENGTH(name) FROM datasets, а сколько SELECT MAX(count) FROM datasets?
Показать ответСкрыть ответ

Скалярные: LENGTH, COALESCE, TO_CHAR. Агрегатные: MAX, SUM. Первый запрос вернёт 6 строк, по одной на набор. Второй одну строку, 70000.

Смешать без GROUP BY: SELECT name, MAX(count) FROM datasets. Агрегатная хочет одну строку, а name шесть. PostgreSQL ответит column "datasets.name" must appear in the GROUP BY clause. Скалярные с обычными столбцами смешивать можно.

Скалярная: строка на входе, строка на выходе. Агрегатная: много строк в одно значение, на таблицу или на кучку.

INITCAP: каждое слово с большой буквы

Названия моделей в базе записаны кто как: rubert-tiny2 маленькими, CatBoost с большой в середине. Хочется одинаково.

SELECT name, INITCAP(name) AS krasivo
FROM models;

INITCAP(s) делает первую букву каждого слова заглавной, а все остальные маленькими. Словом считается кусок из букв и цифр подряд. Дефис, пробел и другие знаки разделяют слова.

Пример из памятки: INITCAP('smart city') даёт Smart City. В rubert-tiny2 дефис разделил два слова, поэтому большие буквы две.

Imdb Reviews, Mnist, California Housing. Последний не изменился, он и так записан по правилу.

Думать, что INITCAP только поднимает первую букву, а остальное не трогает. Она ещё и опускает все остальные. Поэтому сокращения вроде MNIST и CatBoost она портит, для них INITCAP не годится.

INITCAP: первая буква каждого слова большая, остальные маленькие. Сокращения портит.

ABS: расстояние без знака

ABS(x) это модуль числа: убирает минус. ABS(-5) даёт 5, ABS(5) тоже 5. Разность a − b под ABS это расстояние между a и b, без разницы, кто больше.

Первой станет самая низкая оценка, f1 0.721 у запуска 1: разность −0.179, это самое маленькое число. Без ABS сортировка ставит вперёд самые отрицательные, то есть самые далёкие снизу.

Поставить ABS не туда: ABS(mean_metric) - 0.9. Оценки и так положительные, ABS их не меняет, а минус после вычитания остаётся. Под модулем должна стоять вся разность.

ABS(x): модуль, без знака. ABS(a − b): насколько a далеко от b.

Шаг 4 из 10

CAST и ::, а заодно ловушка целого деления

SELECT 150 / 32;            -- 4
SELECT 150::numeric / 32;   -- 4.6875

Первый ответ не опечатка. Если оба числа целые, PostgreSQL делит нацело и выбрасывает дробную часть, как / для int в Java.

CAST(x AS тип) или короче x::тип переводит значение в другой тип. numeric это число с дробной частью без потери точности, int целое, date дата, text текст. Пример из памятки: '5'::int даёт число 5 из текста '5'.

Ещё полезное: created_at::date отрезает время. Из 2026-09-20 18:00 останется 2026-09-20. В DBeaver дробь покажется с хвостом нулей, 4.6875000000000000, это то же число.

Сделай сам. Что вернут: а) SELECT 891 / 32, б) SELECT CAST(891 AS numeric) / 32, в) SELECT '2026-10-25'::date - '2026-09-20'::date?
Показать ответСкрыть ответ

а) 27, целое деление. б) 27.84375. в) 35: разность двух дат PostgreSQL отдаёт целым числом дней. С 20 сентября до 30 сентября 10 дней, плюс 25 дней октября.

Перевести в тип то, что в него не переводится: 'abc'::int. PostgreSQL ответит invalid input syntax for type integer: "abc". Текст становится числом, только если в нём и правда записано число.

x::тип = CAST(x AS тип). Целое / целое = целое, для дроби одно из чисел ::numeric.

created_at::date отрезает время.

CEIL(x) округляет вверх до целого, FLOOR(x) вниз. Пример из памятки: CEIL(8.1) даёт 9. Если число уже целое, обе функции его не меняют.

У iris 150 / 32 = 4.6875: четыре полные пачки и пятая неполная на 22 примера. У California Housing ровно 645 пачек, поэтому оба столбца равны.

Показать ответСкрыть ответ

Путать, куда округляют отрицательные: FLOOR(-2.5) даёт −3, а не −2. Вниз значит к меньшему числу, а −3 меньше −2. CEIL(-2.5) даёт −2.

Шаг 6 из 10

NULLIF: защита от деления на ноль

Хотим процент удачных запусков у каждого исследователя, Олега тоже не терять, поэтому LEFT JOIN:

SELECT r.full_name,
       100.0 * SUM(CASE WHEN e.status = 'done' THEN 1 ELSE 0 END)
             / COUNT(e.id) AS udachnyh
FROM researchers r
LEFT JOIN experiments e ON e.researcher_id = r.id
GROUP BY r.full_name;

Запрос падает: ERROR: division by zero. У Олега запусков нет, COUNT(e.id) у него 0, и на ноль делить нельзя.

NULLIF(a, b) возвращает NULL, если a равно b, а иначе само a. NULLIF(x, 0) превращает ноль в NULL. Деление на NULL не падает, а даёт NULL, то есть «посчитать нельзя».

       ... / NULLIF(COUNT(e.id), 0) AS udachnyh
full_nameudachnyh

Щайхутдинов Азат33.33…

У Азата 1 удачный из 3, DBeaver покажет длинную дробь 33.3333…, а у Степана и Марии 100 с хвостом нулей.100.0 с точкой нужно по той же причине, что в шаге 4: иначе 100 · 1 / 3 нацело даст 33. Порядок строк может быть другим.

Сделай сам. Что вернут NULLIF(5, 0), NULLIF(0, 0) и 10 / NULLIF(0, 0)? А что вернёт COALESCE(10 / NULLIF(0, 0), 0)?
Показать ответСкрыть ответ

5, NULL, NULL. Последнее 0: COALESCE из урока про строки берёт первое не пустое значение, и вместо NULL ставит 0.

Перепутать аргументы: NULLIF(0, COUNT(e.id)). Функция вернёт первый аргумент, ноль, всем, у кого запуски есть, и все проценты станут нулями. Первым пишут то, что возвращаем, вторым то, что надо спрятать.

NULLIF(a, b): NULL, если a = b, иначе a.

Делитель может быть 0 → / NULLIF(делитель, 0).

Шаг 7 из 10

CURRENT_DATE: сегодняшняя дата

SELECT CURRENT_DATE;   -- 2026-10-25, если сегодня 25.10.2026

CURRENT_DATE это сегодняшняя дата на сервере базы. Скобок после него нет. С датой можно считать: CURRENT_DATE - 30 это дата 30 дней назад, а разность двух дат это число дней.

Запуски за последние 30 дней:

SELECT id, created_at
FROM experiments
WHERE created_at >= CURRENT_DATE - 30;

Если сегодня 25.10.2026, граница 25.09.2026, и подойдут запуски 6, 7, 8 и 9. Завтра ответ может стать другим: запрос с CURRENT_DATE каждый день считает заново. Сверяя ответ в DBeaver, учитывай, какое у тебя сегодня число.

Сделай сам. Сколько дней прошло с каждого запуска до сегодня? Напиши запрос и посчитай для запусков 1 и 9, если сегодня 25.10.2026.
Показать ответСкрыть ответ 
SELECT id, CURRENT_DATE - created_at::date AS dney
FROM experiments;

Запуск 1 от 20.09: 35 дней. Запуск 9 от 15.10: 10 дней.

Вычесть без ::date: CURRENT_DATE - created_at. created_at хранит ещё и время, и разность выйдет интервалом вроде 34 days 06:00:00, а не числом дней. Время сначала отрезают.

CURRENT_DATE: сегодня, без скобок. Дата − число = дата. Дата − дата = дней.

Шаг 8 из 10

AGE: возраст в месяцах и днях

35 дней читать неудобно. Человек скажет «месяц и пять дней».

SELECT id, AGE(CURRENT_DATE, created_at::date) AS proshlo
FROM experiments;

AGE(d1, d2) возвращает промежуток от d2 до d1 в годах, месяцах и днях. Тип у результата не число, а интервал. Если сегодня 25.10.2026, у запуска 1 будет 1 mon 5 days: от 20.09 месяц до 20.10 и ещё 5 дней.

Порядок важен: сначала более поздняя дата. В DBeaver интервал может показаться длиннее, например 0 years 1 mons 5 days 0 hours 0 mins 0.0 secs. Это то же самое.

Сделай сам. Что покажет proshlo для запуска 5 от 24.09 и запуска 6 от 2.10, если сегодня 25.10.2026? Чем это отличается от разности дат из шага 7?
Показать ответСкрыть ответ

Запуск 5: 1 mon 1 day. Запуск 6: 23 days, месяца ещё не прошло. Разность дат дала бы просто 31 и 23 числом. AGE удобна, чтобы читать глазами, а с разностью дат удобнее считать и сравнивать.

Поставить даты наоборот: AGE(created_at::date, CURRENT_DATE). Выйдет минус: -1 mons -5 days. Сначала поздняя дата, потом ранняя.

Хотим у каждого исследователя список моделей, с которыми он работал, одной строкой.

SELECT r.full_name,
       STRING_AGG(m.name, ', ' ORDER BY m.name) AS modeli
FROM researchers r
JOIN experiments e ON e.researcher_id = r.id
JOIN models m      ON m.id = e.model_id
GROUP BY r.full_name;

STRING_AGG(x, разделитель) агрегатная: склеивает значения всей кучки в одну строку через разделитель. ORDER BY внутри скобок задаёт порядок в списке, без него порядок любой.

У Азата RandomForest дважды: запуски 3 и 7 были на одной модели. Убрать повторы помогает DISTINCT внутри скобок: STRING_AGG(DISTINCT m.name, ', ' ORDER BY m.name) даст RandomForest, Resnet.

Сделай сам. Напиши запрос: у каждого исследователя статусы его запусков одной строкой в порядке номеров запусков. Что выйдет у Азата?
Показать ответСкрыть ответ 
SELECT r.full_name,
       STRING_AGG(e.status, ', ' ORDER BY e.id) AS statusy
FROM researchers r
JOIN experiments e ON e.researcher_id = r.id
GROUP BY r.full_name;

У Азата done, failed, running, это запуски 3, 7, 8. У Степана и Марии done, done, done.

Склеивать числа: STRING_AGG(e.id, ', '). PostgreSQL ответит function string_agg(integer, unknown) does not exist: функция склеивает только текст. Число переводят шагом 4: STRING_AGG(e.id::text, ', ').

STRING_AGG(x, ', ' ORDER BY …): кучку в одну строку. Повторы убирает DISTINCT, числа сначала ::text.

BOOL_OR(условие) агрегатная: true, если условие верно хоть для одной строки кучки. BOOL_AND(условие): true, если верно для всех. Внутри пишут то же условие, что в WHERE.

Сделай сам. У кого был хоть один запуск на 5 эпох и больше? Напиши запрос и ответь глазами по таблице. Учти, что у запуска 2 эпох NULL.

SELECT r.full_name, BOOL_OR(e.count_apoh >= 5) AS dolgie
FROM researchers r
JOIN experiments e ON e.researcher_id = r.id
GROUP BY r.full_name;

Степан false: у него 1, NULL и 3. Азат true, запуск 8 на 10 эпох. Мария true, запуск 5 на 5 эпох. NULL функция пропускает, как COUNT(столбец).

BOOL_OR: хоть одна строка кучки. BOOL_AND: все строки. NULL пропускают.
