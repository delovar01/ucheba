Сортировки за линейное время

Алгоритмы · лекция 17.09 · под ПР2 · около 60 минут

Как сортировать быстрее, чем n log n, если про числа кое-что известно заранее. Три сортировки: подсчётом, поразрядная и карманная. Это тема ПР2, тест там с одной попыткой, поэтому открывай его только после этого урока и мини-самостоятельной. Тринадцать шагов, в каждом одна новая вещь.

Как проходить: читаешь шаг, переписываешь рамку «Перепиши в тетрадь», решаешь «сделай сам» на бумаге и только потом открываешь ответ. Массивы пиши в тетради строчкой с номерами ячеек сверху, так проще не сбиться. Если в шаге что-то непонятно, дальше не иди: сначала задай вопрос по этому шагу.

Подсчёт и поразрядная были на лекции 17.09 в части «выход за границы модели». Карманной на слайдах не было, она по учебнику Кормена, глава 8, потому что это третья классическая сортировка за линейное время.

Шаг 1 из 13

Граница n log n и как её обойти

В уроке про мастер-теорему доказали: сортировка, которая узнаёт порядок только сравнениями «a < b?», делает в худшем случае не меньше log₂ n! сравнений, а это порядка n log n. Сравнение даёт ответ «да» или «нет», один бит, а угадать надо один порядок из n!.

Но бывают данные, про которые известно больше. Пусть надо отсортировать оценки группы: 4, 3, 5, 4, 3. Оценок всего три вида. Можно вообще не сравнивать, а просто посчитать: троек две, четвёрок две, пятёрка одна. Ответ сразу: 3, 3, 4, 4, 5.

Граница n log n верна только для сортировок сравнениями. Если ключи это целые числа из небольшого диапазона, число можно использовать как номер ячейки массива. Это уже не сравнение, и граница на такой алгоритм не действует.

Ключ это то, по чему сортируют. У оценок ключ сама оценка. Номер ячейки массива называют индексом.

Сделай сам. Надо отсортировать миллион чисел от 0 до 100. Примерно сколько сравнений сделает лучшая сортировка сравнениями? Сколько шагов, если просто один раз пройти по числам и посчитать каждое? log₂ 10⁶ ≈ 20.
Показать ответСкрыть ответ

Сравнениями порядка n log₂ n = 10⁶ · 20 = 2 · 10⁷. Подсчёт: один проход по миллиону чисел и ещё 101 ячейка счётчиков, около 10⁶. Выигрыш примерно в 20 раз, и он растёт вместе с n.

Решить, что подсчёт опровергает доказанную границу. Граница про другую модель: там с числами можно только сравнивать. Подсчёт делает то, что там запрещено, обращается к массиву по номеру, равному числу.

Сравнениями не быстрее n log n.

Целые ключи из малого диапазона → число как индекс, граница не действует.

Заводим массив счётчиков C из k + 1 = 5 ячеек, номера от 0 до 4, сначала все нули. Идём по A и для каждого числа x прибавляем единицу в ячейку с номером x.

Шаг 3 из 13

Префиксные суммы: где кончается каждое значение

Возьмём C из шага 2: [1, 3, 0, 2, 1]. Заменим каждую ячейку суммой её самой и всех ячеек левее. Идём слева направо и прибавляем к ячейке предыдущую, уже пересчитанную:

номер   0  1  2  3  4
было  [ 1, 3, 0, 2, 1 ]
стало [ 1, 4, 4, 6, 7 ]

Первая ячейка остаётся 1. Потом 1 + 3 = 4. Потом 4 + 0 = 4. Потом 4 + 2 = 6. Потом 6 + 1 = 7. Сумма всех ячеек от начала до данной называется префиксной суммой.

После префиксных сумм C[x] равно числу элементов, которые не больше x. В готовом массиве значение x стоит на местах с номерами от C[x − 1] до C[x] − 1. Последнее место для x имеет номер C[x] − 1.

Проверка на тройках: C[2] = 4, C[3] = 6. Значит тройки займут места 4 и 5. В ответе [0, 1, 1, 1, 3, 3, 4] так и есть. Для нуля левой ячейки нет, он начинается с места 0.

Сделай сам. Посчитай префиксные суммы для C = [2, 1, 3, 0, 1] из прошлого «сделай сам». На каких местах будут стоять двойки?
Показать ответСкрыть ответ

[2, 3, 6, 6, 7]. Двойки на местах от C[1] = 3 до C[2] − 1 = 5, то есть 3, 4, 5. В ответе [0, 0, 1, 2, 2, 2, 4] двойки как раз там.

Складывать с исходным соседом, а не с уже пересчитанным: [2, 3, 4, 3, 1]. Так получаются суммы пар соседей, а не всех ячеек слева. Проверка простая: последняя ячейка обязана равняться n, у нас 7.

Префиксы: C[x] += C[x − 1] слева направо.

C[x] = сколько элементов ≤ x. Последнее место x: C[x] − 1. Последняя ячейка = n.

Шаг 4 из 13

Расстановка справа налево

Готовим пустой массив B той же длины, что A. Идём по A с конца. Для числа x уменьшаем C[x] на 1 и кладём x в B[C[x]]. Так x занимает последнее свободное место своего значения, а следующее такое же встанет левее.

A = [3, 1, 4, 1, 0, 3, 1], C = [1, 4, 4, 6, 7]. Пустое место в B пишу точкой.

6  1   3            [ ., ., ., 1, ., ., . ]
5  3   5            [ ., ., ., 1, ., 3, . ]
4  0   0            [ 0, ., ., 1, ., 3, . ]
3  1   2            [ 0, ., 1, 1, ., 3, . ]
2  4   6            [ 0, ., 1, 1, ., 3, 4 ]
1  1   1            [ 0, 1, 1, 1, ., 3, 4 ]
0  3   4            [ 0, 1, 1, 1, 3, 3, 4 ]

Расстановка: идём по A от последнего элемента к первому. Для x делаем C[x] −= 1, потом B[C[x]] = x. Каждый элемент встаёт сразу на своё место, сравнений нет.

Шаг 5 из 13

Устойчивость: зачем идти справа налево

Сортируем записи, а не числа. Список студентов уже стоит по алфавиту: Аня 4, Боря 3, Вика 4, Гоша 3, Даша 5. Сортируем по оценке подсчётом, ключ это оценка. Троек две, четвёрок две, пятёрка одна. Префиксы: C[3] = 2, C[4] = 4, C[5] = 5. Ячейки 0, 1 и 2 пустые, таких оценок нет.

Справа налево получится: Боря 3, Гоша 3, Аня 4, Вика 4, Даша 5. Внутри одной оценки алфавит сохранился. Если идти слева направо тем же способом, первой на последнее место четвёрок встанет Аня, и выйдет: Гоша 3, Боря 3, Вика 4, Аня 4, Даша 5. Равные развернулись.

Сортировка устойчивая, если записи с равными ключами остаются в том же порядке, что были до сортировки. Подсчёт с проходом справа налево устойчивый: последняя из равных записей встаёт на последнее место своего значения, предпоследняя перед ней, и так далее.

Зачем это нужно. Таблицу отсортировали по имени, потом по оценке. С устойчивой сортировкой внутри каждой оценки имена остаются по алфавиту, и сортировку по имени не надо делать заново. В шаге 9 увидишь, что без устойчивости поразрядная сортировка вообще не работает.

Шаг 6 из 13

Время O(n + k) и когда k портит всё

Посчитаем работу. Обнулить C: k + 1 шагов. Посчитать: n шагов. Префиксы: k шагов. Расставить: n шагов. Всего около 2n + 2k. Память: C на k + 1 ячеек и B на n.

Сортировка подсчётом работает за O(n + k) и занимает O(n + k) памяти. Это линейное время, только если k не больше n по порядку, то есть k = O(n).

Когда k портит всё. Тысяча чисел, но каждое до миллиарда. Тогда k = 10⁹, массив C на миллиард ячеек. Целое число в Java занимает 4 байта, это 4 гигабайта памяти ради тысячи чисел. И миллиард шагов на префиксы. Сортировка сравнениями сделает тут около 1000 · 10 = 10⁴ сравнений, ведь log₂ 1000 ≈ 10.

Сделай сам. Примерно сколько шагов у подсчёта и сравнениями в трёх случаях? а) n = 10⁶, числа от 0 до 100. б) n = 1000, числа от 0 до n² = 10⁶. в) n = 10⁶, числа от 0 до 10⁶. Где подсчёт выигрывает?
Показать ответСкрыть ответ

а) Подсчёт около 10⁶ + 100, сравнения 10⁶ · 20 = 2 · 10⁷. Подсчёт выигрывает. б) Подсчёт около 1000 + 10⁶ ≈ 10⁶, сравнения 1000 · 10 = 10⁴. Подсчёт проигрывает в сто раз. в) Подсчёт около 2 · 10⁶, сравнения 2 · 10⁷. Подсчёт выигрывает, потому что k того же порядка, что n.

Запомнить «подсчёт это O(n)» и забыть про k. Без условия k = O(n) это неправда: в случае б работа почти вся уходит на пустые счётчики.

Подсчёт: время и память O(n + k).

Линейно только при k = O(n). Большой диапазон → много памяти и пустых шагов.

Шаг 7 из 13

Код на Java и отрицательные числа

Код повторяет шаги 2–4. Одно добавление: числа могут быть отрицательными, а номера ячеек массива нет. Поэтому ищем минимум и сдвигаем все числа на него. Число x лежит в ячейке x − min. Самое маленькое число попадает в ячейку 0, самое большое в ячейку max − min.

Код на Java, потому что задания курса сдают на нём. Если Java ещё не проходил, хватит пяти вещей. int[] a это массив целых чисел, new int[k] создаёт такой массив из k нулей. for (int x : a) значит «по очереди для каждого числа x из a». static int[] countingSort(…) это функция, которая возвращает массив. Arrays.toString печатает массив в скобках, для неё нужна первая строка с import. Подробно Java разобрана в уроке «Java и рекурсия».

import java.util.Arrays;

public class Main {
    static int[] countingSort(int[] a) {
        int min = a[0], max = a[0];
        for (int x : a) {
            if (x < min) min = x;
            if (x > max) max = x;
        }
        int[] c = new int[max - min + 1];          // счётчики
        for (int x : a) c[x - min]++;
        for (int v = 1; v < c.length; v++) {
            c[v] += c[v - 1];                      // префиксные суммы
        }
        int[] b = new int[a.length];
        for (int i = a.length - 1; i >= 0; i--) {  // справа налево
            int v = a[i] - min;
            c[v]--;
            b[c[v]] = a[i];
        }
        return b;
    }

    public static void main(String[] args) {
        int[] a = {3, 1, 4, 1, 0, 3, 1};
        System.out.println(Arrays.toString(countingSort(a)));
        int[] d = {-2, 5, -2, 0, 3};
        System.out.println(Arrays.toString(countingSort(d)));
    }
}

Вывод программы:

[0, 1, 1, 1, 3, 3, 4]
[-2, -2, 0, 3, 5]

Сдвиг на минимум: счётчик числа x лежит в ячейке x − min, ячеек max − min + 1. Так подсчёт работает с любыми целыми, и k теперь это размах max − min, а не само максимальное число.

Сделай сам. Какой длины будет массив c для {-2, 5, -2, 0, 3}? А для {7, 5, 7, 6}, и что напечатает программа для этого массива?
Показать ответСкрыть ответ

Для первого 5 − (−2) + 1 = 8. Для второго 7 − 5 + 1 = 3, ячейки для 5, 6 и 7. Напечатает [5, 6, 7, 7]. Оба ответа проверены запуском.

Писать new int[max + 1] и c[x]++ без сдвига. Для массива с −2 Java упадёт с ошибкой ArrayIndexOutOfBoundsException: Index -2 out of bounds for length 6. А для {7, 5, 7, 6} без сдвига ячейки 0…4 будут пустыми зря.

Ячейка x − min, длина max − min + 1. Работает с отрицательными.

Шаг 8 из 13

Поразрядная сортировка с младшей цифры

Подсчёт плох на больших числах. Но у трёхзначного числа всего три цифры, и каждая от 0 до 9. Разряд это место цифры в числе: единицы, десятки, сотни. Идея: сортировать числа по одной цифре за раз, каждый раз подсчётом с k = 9.

Массив [253, 512, 351, 213, 152]. Сортируем по единицам, потом по десяткам, потом по сотням. Внутри прохода числа с одинаковой цифрой оставляем в том порядке, в каком они пришли.

                       цифры прохода    результат
по единицам            3, 2, 1, 3, 2    [351, 512, 152, 253, 213]
по десяткам            5, 1, 5, 5, 1    [512, 213, 351, 152, 253]
по сотням              5, 2, 3, 1, 2    [152, 213, 253, 351, 512]

Цифры прохода выписаны для чисел в том порядке, в каком они стояли перед этим проходом. После третьего прохода массив отсортирован.

Поразрядная сортировка LSD: сортируем по младшему разряду, потом по следующему, и так до старшего. Каждый проход это устойчивая сортировка подсчётом по одной цифре. LSD значит «с младшего разряда», по-английски least significant digit.

Числа разной длины дополняют нулями слева: 7 считается как 007.

Сделай сам. Отсортируй поразрядно [421, 132, 413, 231, 122]. Для каждого прохода выпиши цифры и результат.
Показать ответСкрыть ответ 
по единицам   1, 2, 3, 1, 2   [421, 231, 132, 122, 413]
по десяткам   2, 3, 3, 2, 1   [413, 421, 122, 231, 132]
по сотням     4, 4, 1, 2, 1   [122, 132, 231, 413, 421]

Брать цифры прохода из исходного массива, а не из результата прошлого прохода. Каждый проход переставляет числа, и следующий работает уже с новым порядком. Если всё время смотреть на исходный порядок, проходы не складываются, и ответ будет отсортирован только по сотням.

LSD: по единицам → десяткам → сотням, каждый проход устойчивым подсчётом, k = 9.

Следующий проход берёт результат прошлого.

Шаг 9 из 13

Почему каждый проход обязан быть устойчивым

Посмотри на последний проход в шаге 8. Перед ним массив [512, 213, 351, 152, 253]. У 213 и 253 одна сотня, 2. Кто из них меньше, решают десятки, а по десяткам их уже упорядочил прошлый проход: 213 стоит раньше 253. Устойчивый проход по сотням этот порядок сохраняет.

Если проход неустойчивый, ему разрешено поставить равные по сотне числа как угодно. Например, проход слева направо из шага 5 разворачивает равные, и тогда выйдет [152, 253, 213, 351, 512]. 253 перед 213, ответ неверный.

В поразрядной сортировке каждый проход обязан быть устойчивым. Перед проходом по разряду числа уже упорядочены по всем младшим разрядам. Устойчивость сохраняет этот порядок у чисел с одинаковой текущей цифрой.

Сделай сам. Отсортируй поразрядно [31, 23, 32, 21], но по ошибке начни со старшей цифры: сначала по десяткам, потом по единицам. Оба прохода устойчивые. Что получится и почему?
Показать ответСкрыть ответ

По десяткам: [23, 21, 31, 32]. По единицам: [21, 31, 32, 23]. Не отсортировано. Последний проход главный, он решает итоговый порядок, а прошлые решают только при равенстве в нём. Поэтому последним должен идти самый старший разряд.

Думать, что порядок разрядов не важен, «всё равно все цифры пройдём». В LSD порядок строго от младшего к старшему. Бывает и сортировка со старшего разряда, MSD, но она устроена иначе: делит числа на группы по старшей цифре и сортирует каждую группу отдельно.

Каждый проход устойчив, иначе теряется порядок по младшим разрядам.

Шаг 10 из 13

Время поразрядной и выбор основания

Обычная запись числа десятичная, основание 10, цифры от 0 до 9. Но цифрой можно считать и кусок побольше. Число 123 456 789 в основании 1000 имеет три «цифры»: 123, 456 и 789, каждая от 0 до 999. Основание обозначают b, число разрядов d.

Один проход это подсчёт с k = b − 1, он стоит O(n + b). Проходов d.

Поразрядная сортировка работает за O(d · (n + b)), где d разрядов в основании b. Больше основание, меньше проходов, но каждый проход дороже на b.

Пример: миллион чисел, каждое меньше 10⁹. Основание 10: 9 разрядов, около 9 · (10⁶ + 10) ≈ 9 · 10⁶ шагов. Основание 1000: 3 разряда, около 3 · (10⁶ + 1000) ≈ 3 · 10⁶. Подсчёт целиком потребовал бы миллиард ячеек.

Сделай сам. n = 1000 чисел от 0 до 999 999. Сколько примерно шагов у поразрядной в основании 10, в основании 1000 и у подсчёта целиком?
Показать ответСкрыть ответ

Основание 10: 6 разрядов, 6 · (1000 + 10) = 6060. Основание 1000: 2 разряда, 2 · (1000 + 1000) = 4000. Подсчёт: 1000 + 10⁶, около миллиона. Основание, равное n, даёт два прохода: числа до n² в основании n двузначные. Отсюда правило: числа до n² или n³ поразрядная сортирует за O(n).

Брать основание как можно больше, «чтобы был один проход». При основании 10⁶ проход один, но это уже подсчёт с миллионом ячеек. Основание выбирают около n, тогда и проходов мало, и каждый дешёвый.

Поразрядная: O(d · (n + b)), d разрядов в основании b.

b ≈ n → числа до n^c за c проходов, O(n).

Шаг 11 из 13

Карманная сортировка на дробях

Подсчёт и поразрядная работают с целыми. А если числа дробные от 0 до 1? Запись [0, 1) значит: от 0 включительно до 1, но сама 1 не входит.

Делим отрезок на n равных кусков, карманов. Число x кладём в карман с номером ⌊n · x⌋, скобки ⌊ ⌋ значат «округлить вниз». Каждый карман сортируем вставками и склеиваем карманы по порядку.

Сортировка вставками: берём элементы по одному и сдвигаем каждый влево, пока сосед слева больше. Карман [0.42, 0.45, 0.40]: 0.45 больше 0.42, стоит. 0.40 меньше 0.45 и меньше 0.42, уезжает в начало: [0.40, 0.42, 0.45]. На карман из m элементов в худшем случае m · (m − 1) / 2 сравнений.

Пример, n = 8: [0.42, 0.07, 0.91, 0.45, 0.13, 0.68, 0.40, 0.66].

x      8·x    карман

0.07   0.56   0
0.91   7.28   7
0.45   3.60   3
0.13   1.04   1
0.68   5.44   5
0.40   3.20   3

Карман 0: 0.07. Карман 1: 0.13. Карман 3: 0.42, 0.45, 0.40, после вставок 0.40, 0.42, 0.45. Карман 5: 0.68, 0.66, после вставок 0.66, 0.68. Карман 7: 0.91. Карманы 2, 4 и 6 пустые. Склеиваем: [0.07, 0.13, 0.40, 0.42, 0.45, 0.66, 0.68, 0.91].

Карманная сортировка для чисел из [0, 1): n карманов, x идёт в карман ⌊n · x⌋, каждый карман сортируем вставками, карманы склеиваем по номерам. В кармане с большим номером все числа больше, поэтому склейка даёт отсортированный массив.

Сделай сам. Отсортируй карманами [0.73, 0.15, 0.58, 0.11, 0.79]. Сколько карманов, куда попадёт каждое число?
Показать ответСкрыть ответ

Чисел 5, карманов 5. 5 · 0.73 = 3.65 → 3. 0.75 → 0. 2.90 → 2. 0.55 → 0. 3.95 → 3. Карман 0: 0.15, 0.11, после вставок 0.11, 0.15. Карман 2: 0.58. Карман 3: 0.73, 0.79. Итог [0.11, 0.15, 0.58, 0.73, 0.79].

Округлить 3.95 до 4 по обычным правилам. Номер кармана округляют только вниз. Иначе 0.79 попадёт в карман 4, а число вроде 0.99 при n = 5 даст 4.95 → 5, а кармана 5 нет.

Карманная: x ∈ [0, 1) → карман ⌊n · x⌋, вставки в кармане, склейка.

Шаг 12 из 13

Карманная: среднее и худшее время

Если числа разбросаны по [0, 1) равномерно, то есть любое место отрезка одинаково вероятно, в каждый из n карманов в среднем попадает один элемент. Вставки в кармане из одного-двух элементов почти бесплатны, и всё время уходит на раскладку и склейку, это O(n).

Если все числа упали в один карман, карманы ничего не дали. Остались вставки на n элементах: до n · (n − 1) / 2 сравнений. Восемь чисел из [0, 0.125) при восьми карманах все попадут в карман 0, это до 28 сравнений вместо примерно восьми шагов.

Карманная сортировка в среднем работает за O(n), если числа распределены равномерно. В худшем случае, когда почти всё в одном кармане, O(n²). Память O(n) на карманы.

Устойчивость: если класть в карман в порядке прохода и сортировать вставками, равные не меняются местами. Карманная сортировка тогда устойчивая.

Сделай сам. n = 1000 чисел, 1000 карманов. Примерно сколько элементов в кармане и какое время в трёх случаях? а) числа равномерно по [0, 1). б) равномерно по [0, 0.5). в) все из [0, 0.001).
Показать ответСкрыть ответ

а) По одному на карман, O(n). б) Заняты карманы 0…499, примерно по 2 элемента, вставки по одному сравнению на карман. Всё ещё O(n), просто половина карманов пустая. в) 1000 · x < 1, все в кармане 0. Вставки на 1000 элементах: до 1000 · 999 / 2 = 499 500 сравнений, это O(n²).

Сказать, что карманная всегда O(n), как подсчёт. Её линейность держится на предположении о распределении. Подсчёт линеен на любых данных при малом k, карманная только в среднем на равномерных.

Карманная: в среднем O(n) при равномерных, худший O(n²), всё в одном кармане.

Шаг 13 из 13

Как выбрать сортировку под задачу

Выбор: малый диапазон целых → подсчёт. Большие целые фиксированной длины → поразрядная. Равномерные дроби → карманная. Ничего не известно → сортировка сравнениями.

В Java Arrays.sort для массива объектов и sorted() в Python сортируют сравнениями, за n log n. Линейные сортировки пишут сами, когда данные подходят.

Малый диапазон → подсчёт. Большие целые → поразрядная. Равномерные дроби → карманная. Иначе n log n.
