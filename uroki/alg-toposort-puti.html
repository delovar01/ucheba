Шаг 1 из 7

Граф зависимостей и топологический порядок

Пять курсов. Теорвер можно брать только после матана. Алгоритмы после матана и Java. ML после алгоритмов и теорвера. Нарисуем стрелку «сначала → потом»:

  Матан ──→ Теорвер ──┐
    │                 ↓
    └──→ Алгоритмы ──→ ML
            ↑
  Java ─────┘

Это ориентированный граф. Цикла в нём нет: нельзя, выйдя из курса по стрелкам, вернуться в него же. Такой граф называют DAG, от английского «направленный граф без циклов».

Топологический порядок это порядок вершин, в котором каждая стрелка u→v идёт слева направо: u стоит раньше v. Он есть только у графа без циклов, и часто их несколько.

Например: Java, Матан, Алгоритмы, Теорвер, ML. Проверь все пять стрелок, каждая смотрит вправо.

Например, Матан, Теорвер, Java, Алгоритмы, ML. Второй порядок не годится: стрелка Java → Алгоритмы смотрит влево, Алгоритмы стоят раньше Java.

Проверять только соседние пары. Стрелка может соединять вершины далеко друг от друга, например Матан → ML. Проверяют каждую стрелку графа, а не каждую пару соседей в списке.

Шаг 2 из 7

Топосортировка через DFS

Вспомни DFS из урока про обходы: заходим в вершину, рекурсивно идём во всех новых соседей, потом возвращаемся. Важный момент тут именно возврат. Когда DFS выходит из вершины, все вершины, до которых из неё можно дойти, уже обработаны.

Топологическая сортировка DFS: запускаем DFS от каждой непосещённой вершины. В момент выхода из вершины дописываем её в список. В конце список разворачиваем. Время O(n + m), как у обычного DFS.

Номера: 0 Матан, 1 Java, 2 Теорвер, 3 Алгоритмы, 4 ML. Стрелки 0→2, 0→3, 1→3, 2→4, 3→4. Соседей берём по возрастанию.

  1. DFS(0) → сосед 2 → DFS(2) → сосед 4 → DFS(4). У 4 соседей нет, выход: список [4].
  2. Выход из 2: [4, 2].
  3. Снова в 0, сосед 3 → DFS(3). Сосед 4 уже посещён, выход: [4, 2, 3].
  4. Выход из 0: [4, 2, 3, 0].
  5. Вершина 1 не посещена → DFS(1). Сосед 3 посещён, выход: [4, 2, 3, 0, 1].

Разворачиваем: 1, 0, 3, 2, 4. Это Java, Матан, Алгоритмы, Теорвер, ML, порядок из шага 1.

DFS(0) → 3, выход 3, выход 0: [3, 0]. DFS(1) → 2 → сосед 3 посещён, сосед 4 → выход 4, выход 2, выход 1: [3, 0, 4, 2, 1]. DFS(5): сосед 4 посещён, выход 5: [3, 0, 4, 2, 1, 5].

Развернули: 5, 1, 2, 4, 0, 3. Рубашка, трусы, брюки, ремень, носки, ботинки. Все пять стрелок смотрят вправо.

Записывать вершину в момент входа, как в обычном порядке DFS. Тогда выйдет 0, 3, 1, 2, 4, 5, и ремень окажется раньше рубашки, хотя стрелка 5→4. Писать надо на выходе и потом разворачивать.

Топосорт: DFS от всех непосещённых, вершину в список при выходе, в конце развернуть. O(n + m).

Шаг 3 из 7

Топосортировка на Java

Граф храним списками, как в уроке про обходы: g.get(v) это список тех, куда ведут стрелки из v.

// вверху файла: import java.util.*;
static void dfsOut(List<List<Integer>> g, int v,
                   boolean[] seen, List<Integer> out) {
    seen[v] = true;
    for (int w : g.get(v))
        if (!seen[w]) dfsOut(g, w, seen, out);
    out.add(v);                       // момент выхода
}

static List<Integer> topoSort(List<List<Integer>> g) {
    int n = g.size();
    boolean[] seen = new boolean[n];
    List<Integer> out = new ArrayList<>();
    for (int v = 0; v < n; v++)
        if (!seen[v]) dfsOut(g, v, seen, out);
    Collections.reverse(out);         // развернуть
    return out;
}

От обычного DFS отличие в одной строке: out.add(v) стоит после цикла по соседям, а не до него. Collections.reverse переворачивает список на месте.

Для курсов из шага 2 вернётся [1, 0, 3, 2, 4].

Порядок входа 0, 2, 4, 3, 1, после разворота [1, 3, 4, 2, 0]. Не годится: стрелка 0→2 смотрит влево, Матан в самом конце.

Забыть Collections.reverse. Тогда выйдет [4, 2, 3, 0, 1], ML первым. Это порядок наоборот: каждая стрелка смотрит влево. Иногда так и нужно, но топологический порядок это развёрнутый список.

Шаг 4 из 7

Цикл в ориентированном графе: три цвета

Добавим стрелку ML → Матан. Получился цикл Матан → Алгоритмы → ML → Матан, и топологического порядка больше нет. Код из шага 3 этого не заметит и молча вернёт какой-то список. Цикл надо уметь находить.

Правило из урока про обходы «встретил посещённую вершину, не родителя, значит цикл» работает только для неориентированных графов. Пример: 0→1, 0→2, 1→2. DFS(0) → 1 → 2. Вернулись в 0, сосед 2 уже посещён и не родитель. Но цикла нет: из 2 никуда не уйти.

Три цвета. Белая вершина: ещё не заходили. Серая: зашли и ещё не вышли, она на текущем пути рекурсии. Чёрная: вышли. Цикл есть, если DFS из серой вершины видит стрелку в серую. Стрелка в чёрную цикла не даёт.

// color: 0 белая, 1 серая, 2 чёрная
static boolean hasCycle(List<List<Integer>> g, int v, int[] color) {
    color[v] = 1;
    for (int w : g.get(v)) {
        if (color[w] == 1) return true;              // стрелка в серую
        if (color[w] == 0 && hasCycle(g, w, color)) return true;
    }
    color[v] = 2;
    return false;
}

Запускают так же, как топосорт: от каждой белой вершины по очереди.

Сделай сам. Пройди hasCycle на графе 0→1, 0→2, 1→2. Какого цвета 2, когда из 0 смотрим на неё? А на курсах со стрелкой 4→0: в какой момент сработает return true?
Показать ответСкрыть ответ

Первый граф: 0 серая → 1 серая → 2 серая, у 2 соседей нет, 2 чёрная, 1 чёрная. Из 0 смотрим на 2, она чёрная, цикла нет, ответ false.

Курсы: 0 серая → 2 серая → 4 серая. Из 4 стрелка в 0, а 0 серая. Срабатывает return true. Цикл 0 → 2 → 4 → 0, то есть Матан → Теорвер → ML → Матан.

Обойтись двумя цветами, «был или не был». Тогда чёрную 2 в первом графе не отличить от серой, и найдётся цикл, которого нет. Серый цвет нужен, чтобы знать, кто сейчас на пути.

Белая: не были. Серая: на пути. Чёрная: вышли.

Стрелка в серую → цикл, топопорядка нет. Стрелка в чёрную → не цикл.

Шаг 5 из 7

Форд–Беллман: все рёбра n − 1 раз

Вторая тема. В уроке про Дейкстру, шаг 8, был граф S→A 4, S→B 5, B→A −3, A→C 2, и Дейкстра выдала A = 4, C = 6 вместо A = 2, C = 4. Нужен алгоритм, которого отрицательный вес не ломает.

Алгоритм Форда–Беллмана: dist[s] = 0, остальные ∞. Повторяем n − 1 раз: проходим по всем рёбрам и каждое релаксируем. Хватает n − 1 прохода, потому что в кратчайшем пути не больше n − 1 рёбер. Время O(n · m).

Релаксация та же, что в Дейкстре: если dist[u] + w < dist[v], то dist[v] = dist[u] + w. Проход 1, рёбра в порядке S→A, S→B, B→A, A→C:

старт0∞∞∞
S→A 40 + 4 < ∞04∞∞
S→B 50 + 5 < ∞045∞
B→A −35 − 3 = 2 < 4025∞
A→C 22 + 2 < ∞0254

Проходы 2 и 3 ничего не меняют. Ответ A = 2, B = 5, C = 4, верный.

Сделай сам. Тот же граф, но рёбра идут в обратном порядке: A→C, B→A, S→B, S→A. Посчитай dist после каждого прохода. Сколько проходов понадобилось, пока всё не стало верным?
Показать ответСкрыть ответ

Проход 1: A→C и B→A пропускаем, у A и B ещё ∞. S→B: B = 5. S→A: A = 4. Итог A 4, B 5, C ∞.

Проход 2: A→C: C = 6. B→A: 5 − 3 = 2, A = 2. Итог A 2, B 5, C 6.

Проход 3: A→C: 2 + 2 = 4, C = 4. Итог A 2, B 5, C 4. Понадобились все три прохода, это ровно n − 1 = 3.

Остановиться после первого прохода, раз в прямом порядке хватило одного. Сколько проходов понадобится, зависит от порядка рёбер. Гарантию даёт только n − 1.

Форд–Беллман: n − 1 раз релаксировать все рёбра. O(n · m). Веса могут быть отрицательными.

Шаг 6 из 7

Отрицательный цикл: проход номер n

Граф S→A 1, A→B −2, B→A 1, B→C 3. Цикл A→B→A весит −2 + 1 = −1. Каждый круг по нему уменьшает длину на 1, и кратчайшего пути до A, B и C просто нет: можно крутиться бесконечно.

После n − 1 прохода все настоящие кратчайшие пути уже найдены. Делаем ещё один, n-й проход. Если хоть одно расстояние уменьшилось, в графе есть отрицательный цикл, достижимый из старта.

// edges[i] = {u, v, вес}; null значит отрицательный цикл
static int[] bellmanFord(int n, int[][] edges, int s) {
    final int INF = Integer.MAX_VALUE;
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[s] = 0;
    for (int k = 0; k < n - 1; k++)
        for (int[] e : edges)
            if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]])
                dist[e[1]] = dist[e[0]] + e[2];
    for (int[] e : edges)                         // проход номер n
        if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]])
            return null;
    return dist;
}

Проверка dist[e[0]] != INF защищает от переполнения: к MAX_VALUE нельзя прибавлять, ловушка та же, что в Дейкстре.

Проход 1: A = 1, B = −1, A = min(1, −1 + 1) = 0, C = 2. Итог A 0, B −1, C 2.

Проход 2: A 0 → B −2, A −1, C 1. Проход 3: B −3, A −2, C 0. Каждый проход всё уменьшает на 1.

Проход 4, он же n-й: S→A не улучшает, а A→B улучшает, −2 − 2 = −4 < −3. Метод вернёт null: отрицательный цикл.

Считать отрицательным циклом любое отрицательное ребро. В графе из шага 5 есть ребро −3, но цикла через него нет, и n-й проход там ничего не меняет. Важен вес всего цикла.

Проход номер n что-то улучшил → отрицательный цикл, кратчайших путей нет.

Шаг 7 из 7

Флойд: все пары сразу

Дейкстра и Форд–Беллман ищут пути от одной вершины. Если нужны расстояния между всеми парами, например таблица расстояний между городами, удобнее Флойд.

Алгоритм Флойда, или Флойда–Уоршелла. Матрица d[i][j]: сначала вес ребра i→j, 0 на диагонали, ∞ если ребра нет. Для каждой вершины k по очереди спрашиваем про каждую пару: станет ли путь i→j короче, если идти через k? Если d[i][k] + d[k][j] < d[i][j], обновляем. Время O(n³).

// INF = 1_000_000_000, чтобы INF + INF не переполнило int
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];

Пример с лекции: 1→2 4, 2→3 1, 1→3 7, 3→1 2. Строка это откуда, столбец куда.

послечто изменилосьматрица по строкам
старт[0 4 7] [∞ 0 1] [2 ∞ 0]
k = 13→2 через 1: 2 + 4 = 6[0 4 7] [∞ 0 1] [2 6 0]
k = 21→3 через 2: 4 + 1 = 5 < 7[0 4 5] [∞ 0 1] [2 6 0]
k = 32→1 через 3: 1 + 2 = 3[0 4 5] [3 0 1] [2 6 0]

Цикл по k обязательно внешний. Когда k = 3, пути через вершины 1 и 2 уже посчитаны, и их можно продолжать через 3.

Старт: [0 2 9] [∞ 0 3] [1 ∞ 0].

k = 1: 3→2 через 1: 1 + 2 = 3. Стало [0 2 9] [∞ 0 3] [1 3 0].

k = 2: 1→3 через 2: 2 + 3 = 5 < 9. Стало [0 2 5] [∞ 0 3] [1 3 0].

Поставить цикл по k внутрь, после i и j. Тогда пару i, j проверят через все k один раз, пока многие промежуточные пути ещё ∞, и часть расстояний останется неверной. Порядок циклов только k, i, j.

Флойд: for k, for i, for j: d[i][j] = min(d[i][j], d[i][k] + d[k][j]). O(n³), k внешний.

Один источник, веса ≥ 0 → Дейкстра. Есть отрицательные → Форд–Беллман. Все пары, n маленькое → Флойд.
