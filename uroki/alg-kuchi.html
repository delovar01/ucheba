Кучи и амортизационный анализ

Шаг 1 из 11

Стек

Структура данных это способ хранить данные плюс набор операций над ними. От способа хранения зависит, какие операции быстрые.

Кладём по очереди 1, 2, 3 в стопку тарелок. Стопка отдаёт верхнюю, последнюю положенную: 3. Потом 2, потом 1.

Стек: последним пришёл, первым ушёл, по-английски LIFO. Операции push положить наверх и pop снять верхний.

Обе операции стоят O(1): работаем только с верхом, искать ничего не надо.

Стек LIFO: push наверх, pop сверху. Обе O(1).

Шаг 2 из 11

Очередь и дек

Очередь в кассу устроена наоборот. Кладём 1, 2, 3, и первым уходит тот, кто пришёл первым: 1. Потом 2, потом 3.

Очередь: первым пришёл, первым ушёл, по-английски FIFO. Кладут в конец, достают из начала. Обе операции O(1).

Бывает и смесь стека с очередью, её называют дек: класть и снимать можно с обоих концов. В Java дек пригодится в уроке про графы, им там пользуются как очередью.

Сделай сам. Те же операции, что в шаге 1: положить 5, положить 7, достать, положить 2, достать, достать. Что и в каком порядке достанет очередь?
Показать ответСкрыть ответ

5, 7, 2. Все уходят в порядке прихода, и то, что 2 пришла между «достать», порядок не меняет.

Ответить 7, 2, 5, как у стека. Очередь отдаёт не последнего, а самого давнего: первым в ней стоял 5.

Очередь FIFO: в конец, из начала, O(1). Дек: оба конца.

Шаг 3 из 11

Очередь с приоритетом: зачем нужна куча

Больница: пациентов принимают не по порядку прихода, а по тяжести. Нужна структура, которая умеет две вещи: добавить пациента и достать самого тяжёлого.

Каждому пациенту дадим число, ключ: чем тяжелее случай, тем ключ меньше. Ключ это то, по чему элементы сравнивают.

Очередь с приоритетом хранит элементы с ключами и умеет добавить элемент и достать элемент с наименьшим ключом. Куча это способ сделать обе операции быстро.

Простые способы плохи. Обычный список: добавить за O(1), но чтобы найти минимум, надо посмотреть всех, O(n). Отсортированный список: минимум первый, но вставка в середину сдвигает хвост, O(n). Куча даёт O(log n) на обе операции.

Где это в курсе: алгоритм Дейкстры на графах всё время достаёт ближайшую вершину. Это и есть очередь с приоритетом.

Сделай сам. Надо добавить миллион элементов и миллион раз достать минимум. Примерно сколько операций у обычного списка и у кучи? log₂ 10⁶ ≈ 20.
Показать ответСкрыть ответ

Список: каждое извлечение до 10⁶ шагов, всего порядка 10⁶ · 10⁶ = 10¹². Куча: каждая операция около 20 шагов, всего 2 · 10⁶ · 20 = 4 · 10⁷. Разница в десятки тысяч раз.

Считать только добавления: «у списка O(1), значит он быстрее». Цена структуры это цена всех операций, которые с ней делают. Дешёвое добавление не спасает, если каждое извлечение стоит n.

Очередь с приоритетом: добавить, достать минимум.

Список O(1) / O(n), сортированный O(n) / O(1), куча O(log n) / O(log n).

Шаг 4 из 11

Полное двоичное дерево

Дерево рисуют сверху вниз. Верхний узел называют корнем. У каждого узла могут быть потомки, их называют сыновьями, а сам узел для них родитель. Узлы без сыновей называют листьями.

          1
       /     \
      3       2
     / \     /
    7   4   5

Двоичное дерево: у каждого узла не больше двух сыновей. Полное двоичное дерево: все уровни заполнены целиком, кроме, может быть, последнего, а последний заполняется слева направо.

Дерево выше полное: уровни 1, 2 и 3 узла, на последнем дыра только справа. На каждом уровне узлов вдвое больше, чем на предыдущем: 1, 2, 4, 8. На трёх полных уровнях помещается 7 узлов, на четырёх 15. Число уровней растёт на один, когда n удваивается, это и есть логарифм. Поэтому в полном дереве из n узлов ⌊log₂ n⌋ + 1 уровней. Скобки ⌊ ⌋ значат «округлить вниз». Для 6 узлов: ⌊2.58⌋ + 1 = 3.

Сделай сам. Сколько уровней в полном двоичном дереве из 7 узлов? Из 8? Из 1000?
Показать ответСкрыть ответ

7 узлов: 1 + 2 + 4, три уровня ровно. 8 узлов: восьмой уже не влезает, начинается четвёртый уровень, итого 4. 1000 узлов: 2⁹ = 512 ≤ 1000 < 1024, значит ⌊log₂ 1000⌋ = 9 и 10 уровней.

Для 8 узлов ответить 3, «ведь log₂ 8 = 3». Формула с плюс единицей: на трёх уровнях помещается только 7 узлов.

Полное двоичное дерево: уровни целиком, последний слева направо.

Уровней ⌊log₂ n⌋ + 1.

Шаг 5 из 11

Свойство кучи

В дереве из шага 4 у каждого узла число не больше, чем у его сыновей: 1 меньше 3 и 2, 3 меньше 7 и 4, 2 меньше 5. Отсюда сразу видно: самое маленькое число стоит в корне.

Свойство, которое структура обязана сохранять между любыми операциями, называют инвариантом. Каждая операция кучи устроена так, чтобы инвариант после неё снова был верен.

Min-куча это полное двоичное дерево, где ключ каждого узла не больше ключей его сыновей. Минимум всегда в корне, достать его можно за O(1).

Братья между собой никак не упорядочены. 3 слева, 2 справа, и это нормально. Куча не отсортированный массив, она требует только «родитель не больше сыновей».

Сделай сам. Это min-кучи или нет? Нарисуй деревом по уровням слева направо. а) 1, 3, 2, 7, 4. б) 1, 3, 2, 2, 4. в) 2, 2, 2.
Показать ответСкрыть ответ

а) Да: у 1 сыновья 3 и 2, у 3 сыновья 7 и 4. б) Нет: у 3 сыновья 2 и 4, а 3 > 2. в) Да: равные числа инвариант не нарушают, нужно «не больше», а не «меньше».

Сказать, что а) не куча, потому что 3 стоит раньше 2. Порядок между братьями не важен, сравнивают только родителя с его сыновьями.

Min-куча: полное дерево, родитель ≤ сыновей. Минимум в корне.

Инвариант: свойство, верное между любыми операциями.

Шаг 6 из 11

Куча в массиве

Хранить кучу ссылками на сыновей не нужно. Выпишем узлы по уровням слева направо в обычный массив: дерево из шага 4 станет [1, 3, 2, 7, 4, 5]. Индекс это номер ячейки массива, счёт идёт с нуля: в ячейке 0 лежит 1, в ячейке 1 лежит 3.

У узла с индексом i левый сын 2i + 1, правый 2i + 2, родитель (i − 1) // 2. Деление нацело, //.

Проверка: у корня, i = 0, сыновья 1 и 2, это 3 и 2. У i = 1 сыновья 3 и 4, это 7 и 4. У i = 2 левый сын 5, это 5, а правый 6 за концом массива. Родитель узла 5: (5 − 1) // 2 = 2.

Готовая очередь с приоритетом есть в Java, она называется PriorityQueue, и в Python, модуль heapq. Обе хранят кучу именно так: массив лежит в памяти подряд, и процессор читает его быстро.

Писать сыновей 2i и 2i + 1. Это формулы для массива с единицы. С нуля у корня сыновьями вышли бы 0 и 1, то есть он сам себе сын.

Индексы с 0: сыновья 2i+1, 2i+2, родитель (i−1)//2.

Шаг 7 из 11

Вставка: просеивание вверх

Пример с лекции. Куча [1, 3, 2, 7, 4], вставляем 0.

  1. Кладём в конец, чтобы дерево осталось полным: [1, 3, 2, 7, 4, 0], индекс 5.
  2. Родитель (5 − 1) // 2 = 2, там 2. 2 > 0, меняем: [1, 3, 0, 7, 4, 2].
  3. Родитель индекса 2 это 0, там 1. 1 > 0, меняем: [0, 3, 1, 7, 4, 2].
  4. Дошли до корня, стоп. Минимум снова в начале.

Вставка: кладём элемент в конец и меняем с родителем, пока родитель больше. Это называют просеиванием вверх. Подъём не длиннее высоты дерева, O(log n).

Сделай сам. Вставь 1 в кучу [2, 5, 3, 8, 6, 4]. Запиши массив после каждого обмена.
Показать ответСкрыть ответ

В конец: [2, 5, 3, 8, 6, 4, 1], индекс 6. Родитель 2, там 3, меняем: [2, 5, 1, 8, 6, 4, 3]. Родитель 0, там 2, меняем: [1, 5, 2, 8, 6, 4, 3]. Корень, стоп.

Вставить 1 сразу в начало и сдвинуть остальные. Это O(n) сдвигов, и вдобавок ломает свойство кучи: родители и сыновья перемешаются. Элемент всегда входит в конец и поднимается обменами.

Вставка: в конец → меняю с родителем, пока он больше. O(log n).

Шаг 8 из 11

Извлечение минимума: просеивание вниз

Из кучи [0, 3, 1, 7, 4, 2] достаём минимум 0.

  1. Забираем корень. На его место ставим последний элемент 2, массив укоротился: [2, 3, 1, 7, 4].
  2. Сыновья корня 3 и 1, меньший 1. 2 > 1, меняем: [1, 3, 2, 7, 4].
  3. У индекса 2 сыновья 5 и 6, оба за концом массива. Стоп.

Извлечение минимума: забираем корень, на его место последний элемент, и меняем его с меньшим из сыновей, пока он больше этого сына. Это просеивание вниз, O(log n).

Почему с меньшим. Если поменять с большим, наверх встанет большее из двух чисел, и оно окажется больше своего нового сына. Инвариант сломается.

Сделай сам. Достань минимум из [1, 5, 2, 8, 6, 4, 3]. Какой массив получится?

Забираем 1, последний 3 в корень: [3, 5, 2, 8, 6, 4]. Сыновья 5 и 2, меньший 2, меняем: [2, 5, 3, 8, 6, 4]. У индекса 2 есть только левый сын, индекс 5, там 4. 3 < 4, стоп. Ответ [2, 5, 3, 8, 6, 4].

Поставить в корень не последний элемент, а меньшего из сыновей и тянуть их вверх по цепочке. Дыра уедет вниз в случайное место, и дерево перестанет быть полным.

Извлечь min: корень забрал, последний в корень → меняю с меньшим сыном, пока он больше. O(log n).

Шаг 9 из 11

Построение кучи за O(n)

Дан готовый массив, надо сделать из него кучу. Можно вставить n элементов по одному, это n · log n. Можно быстрее: просеивать вниз все узлы, у которых есть сыновья, начиная с последнего такого и идя к корню.

Массив [5, 3, 8, 1, 4, 2], n = 6. Последний узел с сыновьями n // 2 − 1 = 2. Почему так: у узла 3 левый сын был бы 2 · 3 + 1 = 7, а такого индекса в массиве из 6 нет. Значит узлы 3, 4, 5 листья, и просеивать их не нужно.

  1. i = 2: число 8, сын 2. Меняем: [5, 3, 2, 1, 4, 8].
  2. i = 1: число 3, сыновья 1 и 4. Меняем с 1: [5, 1, 2, 3, 4, 8].
  3. i = 0: число 5, сыновья 1 и 2. Меняем с 1: [1, 5, 2, 3, 4, 8]. Пятёрка теперь на индексе 1, её сыновья 3 и 4. Меняем с 3: [1, 3, 2, 5, 4, 8].

Построение снизу вверх стоит O(n). Половина узлов это листья, они не двигаются. Четверть опускается не больше чем на 1 уровень, восьмая часть не больше чем на 2, и так далее. Сумма меньше n.

Посчитаем для полного дерева из 15 узлов: 8 листьев по 0, 4 узла по 1, 2 узла по 2, корень 3. Всего 0 + 4 + 4 + 3 = 11 < 15. Почти вся работа внизу, где путь короткий. Так же, как в геометрической сумме из шага 9 матана, большие слагаемые редки.

Шаг 10 из 11

Амортизация: динамический массив с удвоением

Список в Python и ArrayList в Java растут сами. Внутри это массив с запасом места, его размер называют ёмкостью. Когда место кончилось, выделяется массив вдвое больше, и всё копируется.

Обычно добавление стоит 1, но иногда копирование всего массива стоит n. Наивно: n добавлений по n, итого n². Это неверно. Посчитаем честно для 8 добавлений с ёмкостью 1 в начале.

Первый элемент ложится в ёмкость 1. Второму места нет: новый массив на 2, копируем 1 элемент. Третьему нет: массив на 4, копируем 2. Четвёртый влез. Пятому нет: массив на 8, копируем 4. С шестого по восьмой места хватает.

Записей самих элементов 8. Копирования при переполнениях: при ёмкости 1, 2 и 4, итого 1 + 2 + 4 = 7. Всего 8 + 7 = 15 < 2 · 8.

Амортизационная стоимость это полная цена n операций, делённая на n: T(n) / n. Для массива с удвоением T(n) < 2n, значит добавление стоит O(1) амортизированно. Такой подсчёт целиком называют методом агрегирования.

Это не средний случай с вероятностями. Гарантия верна для любой последовательности добавлений, даже подобранной назло.

Сделай сам. Сколько всего операций уйдёт на 16 добавлений? А на 1024? Ёмкость сначала 1.
Показать ответСкрыть ответ

Включить в копирования и 16: «на 16-м добавлении копируем 16». На 16-м добавлении в массиве 15 элементов, а ёмкость 16, место ещё есть. Удвоение до 32 случится только на 17-м.

Амортизация: T(n)/n на любой последовательности, без вероятностей.

Удвоение: n + (1 + 2 + … ) < 2n → O(1) на добавление.

Шаг 11 из 11

Метод учёта и рост на добавку

Второй способ посчитать то же самое. Каждой операции назначаем тариф в монетах. Переплату кладём в банк, дорогую операцию оплачиваем из банка. Главное правило: банк никогда не уходит в минус.

Массив с удвоением, тариф добавления 3 монеты: 1 на запись, 2 кладём на сам элемент. Ёмкость 4, лежат a, b, c, d. Монеты a и b уже потрачены на прошлое копирование. Элементы c и d добавлены после удвоения с 2 до 4, на каждом лежит по 2 монеты, всего 4. Приходит пятый, надо скопировать 4 элемента, банк платит ровно 4. Значит каждое добавление стоит не больше 3.

Метод учёта: тариф на операцию, переплата в банк, баланс никогда не меньше нуля. Тогда n операций стоят не больше суммы тарифов.

А если расти не вдвое, а на 10 мест? Ёмкость 10, потом 20, 30… На 100 добавлений копирования 10 + 20 + … + 90 = 450. На 1000 уже 10 + 20 + … + 990 = 49 500, это около n²/20. Делим на n добавлений: около n/20 на каждое, это растёт вместе с n. Рост в постоянное число раз даёт геометрическую сумму и O(1). Рост на постоянную добавку даёт арифметическую сумму и O(n) на добавление.

Настоящая цена 1 + 1 + 1 + 2 + 1 = 6. Тарифы 2 · 4 = 8. В банке 8 − 6 = 2 монеты, ровно по одной на каждый элемент в стеке. Каждый PUSH положил монету на свой элемент, и снятие оплачено ею.

Сказать: «MULTIPOP может стоить n, значит n операций стоят n²». Снять можно только то, что положили, а каждый элемент кладут один раз. Поэтому все снятия вместе не дороже всех PUSH.

Метод учёта: тариф, переплата в банк, банк ≥ 0 всегда.

Рост ×2 → O(1) аморт. Рост +10 → O(n).
