Шаг 1 из 9

Класс на UML-диаграмме

UML по слайду 5 это язык схем для описания программ. Диаграмма классов показывает классы и связи между ними картинкой, без кода. Её рисуют до программы, чтобы договориться, что из чего состоит.

class Student {
    private String name;
    private int age;

    public String getName() {
        return name;
    }
}

На диаграмме этот класс выглядит так:

┌──────────────────────┐
│ Student              │
├──────────────────────┤
│ - name: String       │
│ - age: int           │
├──────────────────────┤
│ + getName(): String  │
└──────────────────────┘

Класс на UML это прямоугольник из трёх частей: имя, поля, методы. Перед полем или методом знак доступа: - значит private, + public, # protected. Тип пишут после имени через двоеточие: name: String, а у метода после скобок: getName(): String.

Шаг 2 из 9

Ассоциация: классы знают друг о друге

Пример со слайдов 7–8: студент записан на курсы, на курсе учатся студенты. Каждый из них живёт сам по себе: курс не исчезнет, если один студент отчислится, и студент не исчезнет, если курс закроют.

class Course {
    private final List<Student> students = new ArrayList<>();

    void addStudent(Student s) {
        students.add(s);
        s.addCourse(this);          // вторая сторона связи
    }
}

class Student {
    private final List<Course> courses = new ArrayList<>();

    void addCourse(Course c) {
        courses.add(c);
    }

    int courseCount() {
        return courses.size();
    }
}

Student ───── записан на ───── Course

this внутри метода курса это сам курс. Строка s.addCourse(this) говорит студенту «запиши меня в свои курсы».

Шаг 3 из 9

Множественность: 1, *, 10..100

Линия говорит, что связь есть. Но сколько студентов на курсе? У скольких преподавателей один курс? Это пишут числами у концов линии.

Множественность по слайду 6. Точное число: 1. Любое количество, от нуля и больше: *. Интервал: 10..100, от 10 до 100 включительно. Ещё бывают 0..1, ноль или один, и 1..*, хотя бы один. Число стоит у того класса, который считаем, и говорит, сколько его объектов связано с одним объектом на другом конце.

Teacher 1 ──── ведёт ──── * Course
Course  * ── записан на ── 10..100 Student

Первая линия читается в обе стороны. У курса один преподаватель, единица стоит возле Teacher. Преподаватель ведёт сколько угодно курсов, звёздочка стоит возле Course.

На одном курсе от 10 до 100 студентов, это число у Student. Один студент записан на сколько угодно курсов, может и ни на один, это * у Course.

Возле Wheel стоит 4: у одной машины четыре колеса. Возле Car стоит 0..1: колесо либо на одной машине, либо ни на какой.

Шаг 4 из 9

Множественность в коде

Диаграмма обещает «от 10 до 100 студентов». Java сама этого не проверит, обещание надо выполнить кодом.

class Teacher {
    private final String name;
    Teacher(String name) { this.name = name; }
}

class Course {
    private final Teacher teacher;                        // 1
    private final List<String> students = new ArrayList<>(); // 10..100

    Course(Teacher teacher) {
        if (teacher == null)
            throw new IllegalArgumentException("у курса должен быть преподаватель");
        this.teacher = teacher;
    }

    void addStudent(String name) {
        if (students.size() == 100)
            throw new IllegalStateException("на курсе уже 100 студентов");
        students.add(name);
    }

    boolean canStart() {
        return students.size() >= 10;
    }
}

Студентов здесь для краткости храним просто именами. IllegalArgumentException ты видел в уроке про инкапсуляцию: плохой аргумент. IllegalStateException значит «аргумент нормальный, но объект сейчас в таком состоянии, что так нельзя»: курс уже полон.

Как множественность превращается в код. 1: одно поле-объект, и оно не может быть null. 0..1: одно поле, null разрешён. *: список. Интервал вроде 10..100: список плюс проверки границ в методах.

Сделай сам. Создали курс и в цикле добавили 9 студентов. Что вернёт canStart()? Что случится, если в цикле добавлять 101 студента?
Показать ответСкрыть ответ

9 меньше 10, canStart() вернёт false. При 101 студенте первые 100 добавятся, на сто первом students.size() == 100, и программа упадёт с IllegalStateException: на курсе уже 100 студентов.

Проверять нижнюю границу 10 в addStudent и не давать добавить первого студента, «пока их меньше 10». Тогда на курс никого не запишешь вообще. Нижняя граница проверяется там, где она важна, например перед стартом курса.

1: поле, не null. 0..1: поле, null можно. *: список. Интервал: список + проверки границ.

Шаг 5 из 9

Агрегация: имеет, но часть живёт сама

Слайд 9: «студент имеет адрес». Двое соседей по общаге живут по одному адресу. Студент отчислился, а дом стоит, и сосед живёт там же.

class Address {
    private final String city;
    private final String street;

    Address(String city, String street) {
        this.city = city;
        this.street = street;
    }

    @Override
    public String toString() {
        return city + ", " + street;
    }
}

class Student {
    private final String name;
    private final Address address;

    Student(String name, Address address) {   // адрес приходит снаружи
        this.name = name;
        this.address = address;
    }

    Address getAddress() { return address; }
}

Student boris = new Student("Борис", dorm);
anya = null;

Один объект адреса, на него ссылаются dorm и поле address у Бориса. Это агрегация: адрес создан снаружи, его отдали двум студентам, и он пережил Аню.

Решить, что раз у студента есть поле-объект, это композиция. В уроке про классы так и называли любое поле-объект, это обычное слово программистов. В UML строже: если часть приходит снаружи и может быть общей, это агрегация.

Шаг 6 из 9

Композиция: часть не живёт без целого

Слайд 10: «студент имеет имя». Имя «Аня» в базе студентов без самой Ани ничего не значит. Пример нагляднее: комнаты дома. Снесли дом, его кухни отдельно не бывает.

class Room {
    private final String name;
    private final double area;

    Room(String name, double area) {
        this.name = name;
        this.area = area;
    }

    double getArea() { return area; }
}

class House {
    private final List<Room> rooms = new ArrayList<>();

    House() {                          // комнаты создаёт сам дом
        rooms.add(new Room("кухня", 9.5));
        rooms.add(new Room("комната", 18.0));
    }

    double totalArea() {
        double sum = 0;
        for (Room r : rooms) sum += r.getArea();
        return sum;
    }
}

Композиция по слайду 10: особая форма агрегации, когда часть не может существовать сама по себе. Часть принадлежит ровно одному целому и живёт, пока живёт оно. В коде целое обычно само создаёт части и не отдаёт их наружу. На UML это линия с закрашенным ромбом у целого.

House ◆────── Room

У ромба множественность целого всегда 1: у комнаты ровно один дом. Поэтому её часто и не пишут.

Сделай сам. Что вернёт new House().totalArea()? И что нужно поменять в коде шага 5, чтобы адрес студента стал композицией?

9.5 + 18.0 = 27.5, напечатается 27.5.

Чтобы адрес стал композицией, студент должен создавать его сам и ни с кем не делить: конструктор Student(String name, String city, String street), внутри this.address = new Address(city, street);, и метод getAddress не отдаёт сам объект наружу.

Создать комнату снаружи и передать в дом, а потом положить ту же комнату во второй дом. Код соберётся, но это уже не композиция: одна кухня в двух домах. Java не следит за этим сама, следит тот, кто пишет код.

Композиция: часть живёт, только пока живёт целое, и только у одного целого. UML: закрашенный ромб ◆ у целого.

В коде целое само создаёт части через new.

Шаг 7 из 9

Три связи: как отличить

Слайд 11 ставит три слова рядом: ассоциация, агрегация, композиция. Это матрёшка. Каждая следующая связь это особый случай предыдущей.

Три вопроса по порядку. Есть ли «целое и часть»? Нет, значит ассоциация: просто взаимодействуют. Да, тогда может ли часть жить без целого или быть у двух целых сразу? Может, значит агрегация ◇. Не может, значит композиция ◆.

Шаг 8 из 9

is-a и has-a

Связи шагов 5 и 6 читаются «имеет». Связь из урока про наследование читается «является»: электромобиль является машиной. На лекции их называли по-английски.

is-a, «является», моделируют наследованием extends. На UML линия с пустым треугольником у родителя. has-a, «имеет», моделируют полем: агрегацией или композицией. Слайды 18–19 добавляют: не наследуй только ради чужих методов, и не каждое «является» из жизни стоит делать наследованием.

ElectricCar ─────▷ Car       is-a: электромобиль является машиной
Car ◇────── Engine           has-a: у машины есть двигатель

Пример плохого наследования: class Stack extends ArrayList. Стек получит все методы списка, и любой сможет вставить элемент в середину стека, хотя стек так не умеет. Правильно: стек имеет список, поле private final List<Integer> items.

Сделай сам. is-a или has-a, и что в коде: а) Студент и Человек, б) Студент и Зачётка, в) Квадрат и Фигура, г) Машина и Колесо.

is-a «является» → extends, UML ─▷ к родителю. has-a «имеет» → поле, ◇ или ◆.
