sealed-типы и record

Java · лекция 4, 5.10 (Корелин), его код seminar3: герои-бандиты, Range, Result · на зачёт · около 60 минут

Две вещи из Java 16–21. record заменяет целый класс с данными одной строкой. sealed закрывает список наследников. Вместе они дают switch, который сам проверяет, что ты разобрал все варианты. Нужны уроки инкапсуляция и наследование, лямбды из урока про ФП встретятся в последнем шаге.

Код требует Java 21, в IDEA проверь, что у проекта стоит JDK 21.

Шаг 5 из 10

sealed: закрытый список наследников

Пример лекции: шутер, где герой бывает бандитом или контрбандитом.

sealed interface Hero permits Bandit, CounterBandit {
}

final class Bandit implements Hero {
    public void detonateBomb() {
        System.out.println("Бомба заложена");
    }
}

final class CounterBandit implements Hero {
    public void defuseBomb() {
        System.out.println("Бомба обезврежена");
    }
}

Строки внутри main:

new Bandit().detonateBomb();
new CounterBandit().defuseBomb();
Бомба заложена
Бомба обезврежена

sealed, запечатанный, значит «реализовать или наследовать можно только тем, кто перечислен». Список идёт после permits, «разрешает». Если все классы лежат в одном файле, permits можно не писать, Java соберёт список сама. Иначе наследники должны быть в том же пакете.

Зачем запрещать наследование, три причины со слайдов. Класс входит в готовую библиотеку, которой пользуются другие программисты, и не должен меняться под чужих наследников. Класс неизменяемый, и наследник может это сломать. Предпочитай композицию наследованию, урок про наследование, шаг 12. final class запрещает всех наследников, sealed разрешает только известных.

Шаг 7 из 10

switch по типу: и зачем там default

Сначала обычный, не запечатанный интерфейс героя:

interface Hero {
}

class Bandit implements Hero {
}

class CounterBandit implements Hero {
}

public class Main {
    static String role(Hero h) {
        return switch (h) {
            case Bandit b -> "закладывает бомбу";
            case CounterBandit c -> "обезвреживает";
        };
    }
}
Main.java:12: error: the switch expression does not cover all possible input values
        return switch (h) {
               ^
1 error

Здесь сразу две новые вещи, разберём по одной. Первая: switch (h) берёт значение h и проверяет ветки case сверху вниз, как цепочка else if. Срабатывает первая подходящая. Справа от стрелки -> стоит значение ветки, и весь switch возвращает его, поэтому его можно сразу отдать в return. Такой switch называют выражением, после закрывающей скобки ставят ;. Вторая: case Bandit b это шаблон по типу: ветка срабатывает, если объект бандит, и сразу кладёт его в переменную b, как instanceof Bandit b из урока про наследование.

Ошибка «switch не покрывает все возможные значения». Интерфейс открыт, завтра кто-то напишет третьего героя, и компилятор этого не знает. Приходится писать default -> "неизвестный герой";. Тогда всё собирается, и класс Doctor, о котором switch не знает, тихо попадает в default: для доктора печатается «неизвестный герой».

Шаг 10 из 10

Практика лекции: Result

Результат операции бывает успехом со значением или ошибкой с текстом. Решение из seminar3, билеты получают только с 18 лет. У Корелина в билете случайный номер и время, здесь вместо них имя владельца, чтобы вывод не менялся от запуска к запуску.

В этом шаге три новые вещи сразу, поэтому сначала каждая отдельно, на одной строке.

1. Буква в угловых скобках. Result<T> читается «результат с чем-то внутри», T заменяется настоящим типом при использовании: Result<Integer> хранит число, Result<String> строку. Ты уже видел такое у списков: List<String> в уроке про лямбды. Такой тип называют обобщённым, по-английски generic.

2. default-метод. Метод интерфейса со словом default приходит уже с телом, его не надо писать в каждой записи. Здесь это ifSuccess: «если успех, сделай действие со значением».

3. Разбор записи прямо в проверке. В шаге 9 ты писал case Rectangle(double w, double h). Тот же приём работает и в if: this instanceof Success<T>(T value) значит «если этот результат успех, достань из него значение в переменную value». А в switch пишут так же, как в шаге 9, только с типом в скобках: case Success<Double>(Double v).

Теперь код целиком, он склеен из этих трёх кусков:

import java.util.function.Consumer;

sealed interface Result<T> permits Success, Failure {
    default void ifSuccess(Consumer<T> action) {
        if (this instanceof Success<T>(T value)) {
            action.accept(value);
        }
    }

    default void ifFailure(Consumer<String> action) {
        if (this instanceof Failure<T>(String message)) {
            action.accept(message);
        }
    }

    default boolean isSuccess() {
        return switch (this) {
            case Success<T> s -> true;
            case Failure<T> f -> false;
        };
    }
}

record Success<T>(T result) implements Result<T> {
}

record Failure<T>(String message) implements Result<T> {
}

record Ticket(String owner) {
}

record User(String name, int age) {
    Result<Ticket> takeTicket() {
        if (age < 18) {
            return new Failure<>("Age must be at least 18");
        }
        return new Success<>(new Ticket(name));
    }
}

public class Main {
    public static void main(String[] args) {
        Result<Ticket> anton = new User("Anton", 17).takeTicket();
        Result<Ticket> mariya = new User("Mariya", 18).takeTicket();
        System.out.println("Anton: " + anton.isSuccess());
        System.out.println("Mariya: " + mariya.isSuccess());
        anton.ifFailure(msg -> System.out.println("Ошибка: " + msg));
        mariya.ifSuccess(t -> System.out.println("Билет: " + t));
        anton.ifSuccess(t -> System.out.println("сюда не попадём"));
    }
}
Anton: false
Mariya: true
Ошибка: Age must be at least 18
Билет: Ticket[owner=Mariya]

Всё из урока в одном месте. Запечатанный интерфейс фиксирует два варианта, каждый вариант запись. <T> значит, что успех может нести значение любого типа, здесь билет. Слово default здесь значит другое, чем в switch: default-метод в интерфейсе имеет тело, и его получают все реализации: ifSuccess написан один раз для обоих вариантов. Внутри шаблон записи работает и в instanceof: this instanceof Success<T>(T value) проверяет и достаёт значение. Действие передаётся лямбдой, Consumer из урока про ФП.

Метод не бросает исключение и не возвращает null, он честно говорит типом: «тут может быть ошибка». Вызывающий не может про неё забыть.

Сделай сам. Метод divide(a, b) возвращает Result<Double>: на ноль ошибка «деление на ноль», иначе частное. Напиши show через switch с шаблонами записей. Что напечатают show(divide(7, 2)) и show(divide(7, 0))?

static Result<Double> divide(double a, double b) {
    if (b == 0) {
        return new Failure<>("деление на ноль");
    }
    return new Success<>(a / b);
}

static String show(Result<Double> r) {
    return switch (r) {
        case Success<Double>(Double v) -> "ответ " + v;
        case Failure<Double>(String msg) -> "ошибка: " + msg;
    };
}
ответ 3.5
ошибка: деление на ноль

default не нужен, вариантов ровно два. Это пример из конспекта лекции, проверен запуском.

Писать в шаблоне double v вместо Double v. Компилятор ответит pattern of type double is not applicable at Double: внутри дженерика лежит класс-обёртка, и тип в шаблоне должен ему соответствовать.

sealed + record + switch: варианты результата, которые нельзя забыть обработать.

default метод интерфейса с телом достаётся всем реализациям.

Что спросят на зачёте

  • Что record делает сам и чего не умеет: шаги 1–2.
  • Компактный конструктор и неизменяемость: шаги 3–4.
  • sealed, permits, три пометки наследника, зачем запрещать наследование: шаги 5–6.
  • Почему по sealed можно без default: шаги 7–8.
  • Шаблоны записей и Result: шаги 9–10. История: record в Java 14 как проба, в 16 насовсем, шаблоны записей в 21.
