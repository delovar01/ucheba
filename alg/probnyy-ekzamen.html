Часть 1. Теория

Вопрос 1. Нижняя граница для сортировок сравнениями. Сформулируй теорему и объясни идею доказательства. Почему сортировка подсчётом работает быстрее и при этом не нарушает теорему?
Показать ответСкрыть ответ

Теорема. Любая сортировка, которая узнаёт о порядке элементов только сравнениями, в худшем случае делает Ω(n log n) сравнений.

Идея доказательства.

  1. Работу алгоритма рисуем деревом решений: в каждом узле одно сравнение «ai ≤ aj?», две ветки «да» и «нет».
  2. Каждый лист это готовый порядок. Разных порядков n штук элементов n!, и каждый должен быть каким-то листом. Значит, листьев не меньше n!.
  3. У двоичного дерева высоты h не больше 2h листьев. Отсюда 2h ≥ n!, то есть h ≥ log₂(n!).
  4. В n! хотя бы n/2 множителей не меньше n/2, поэтому log₂(n!) ≥ (n/2)·log₂(n/2) = Ω(n log n). Высота дерева и есть число сравнений в худшем случае.

Подсчёт. Он вообще не сравнивает элементы: использует значение как номер ячейки массива. Это другая модель вычислений (Word RAM), теорема доказана только для модели сравнений. Плата за скорость: ключи должны быть целыми из небольшого диапазона.

Написать «листьев n» вместо n!. Лист это перестановка, а не элемент. Ещё частая ошибка: сказать, что подсчёт «опровергает» теорему. Он её не касается, потому что не сравнивает.

Вопрос 2. Амортизационный анализ. Что это и чем отличается от среднего случая? Покажи на динамическом массиве, который при переполнении удваивается: почему добавление в конец стоит O(1) амортизированно.
Показать ответСкрыть ответ

Амортизационная стоимость это общая стоимость n операций в худшем случае, делённая на n. Случайности тут нет: оценка верна для любой последовательности операций. Средний случай, наоборот, усредняет по случайным входам.

Пример (групповой метод). Начинаем с ёмкости 1 и делаем n добавлений. Обычное добавление стоит 1. При переполнении копируем все элементы в массив вдвое больше: копирований будет 1 + 2 + 4 + … ≤ 2n. Итого n + 2n = 3n действий на n операций, то есть 3 на операцию, O(1).

Бухгалтерский метод то же самое словами: каждое добавление платит 3 монеты. Одна на себя, две копим. Когда массив удваивается, накопленных монет хватает на все копирования.

Третий метод с лекции: метод потенциалов.

Сказать «одно добавление иногда стоит O(n), значит, всё O(n)». Дорогих добавлений мало, и они идут всё реже. Вторая ошибка: увеличивать массив на 1 или на 10 элементов, а не вдвое. Тогда копирований будет порядка n², и O(1) уже не получится.

Часть 2. Задачи

Задача 1. Сложность кода. Для каждого фрагмента найди Θ от n и посчитай, сколько раз выполнится count++ при указанном n. 
// а) при n = 8

    for (int j = 0; j < i; j++)
        count++;

// б) при n = 4

    for (int j = i; j < n; j++)
        count++;

// в) только Θ
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= n; j += i)
        count++;
Показать ответСкрыть ответ

а) Θ(n), при n = 8 будет 7. i принимает значения 1, 2, 4 (8 уже не меньше 8). Внутренний цикл делает i шагов: 1 + 2 + 4 = 7. В общем случае 1 + 2 + 4 + … + (меньше n) < 2n.

б) Θ(n²), при n = 4 будет 10. При i = 0 внутренний делает 4 шага, потом 3, 2, 1. Сумма 4 + 3 + 2 + 1 = 10. В общем случае n(n + 1)/2.

в) Θ(n log n). При данном i внутренний цикл делает примерно n/i шагов. Сумма n/1 + n/2 + … + n/n = n·(1 + 1/2 + … + 1/n) ≈ n·ln n.

В а) увидеть «внешний log n, внутренний до n» и написать Θ(n log n). Внутренний идёт не до n, а до i, и шаги складываются в геометрическую сумму. Это ловушка с лекции.

Задача 2. Рекуррентные соотношения. Найди Θ. Для каждого скажи, каким способом решал: какой случай мастер-теоремы, Акра–Бацци или раскрытие.
  1. T(n) = 4T(n/2) + n
  2. T(n) = 2T(n/2) + n²
  3. T(n) = 2T(n/2) + n log n
  4. T(n) = T(n − 1) + n
  5. T(n) = T(n/3) + T(2n/3) + n
Показать ответСкрыть ответ

Везде сначала считаем число листьев nlog_b a и сравниваем с f(n).

а) Θ(n²). a = 4, b = 2, листьев nlog₂4 = n². f = n меньше n² в n раз (полиномиально). Случай 1, побеждают листья.

б) Θ(n²). Листьев nlog₂2 = n. f = n² больше в n раз. Случай 3, но надо проверить регулярность: a·f(n/b) = 2·(n/2)² = n²/2 ≤ c·n² при c = 1/2 < 1. Выполнена, ответ f(n).

в) Θ(n log² n). Листьев n, f = n log n больше всего в log n раз, а не в nε. Обычная мастер-теорема не применима. Расширенный случай 2 с k = 1: n·logk+1 n = n log² n.

г) Θ(n²). Подзадача n − 1, а не n/b, мастер-теорема не подходит. Раскрываем: T(n) = n + (n − 1) + … + 1 = n(n + 1)/2.

д) Θ(n log n). Подзадачи разного размера, нужна Акра–Бацци. Ищем p из (1/3)p + (2/3)p = 1, подходит p = 1. g(n) = n, то есть q = 1 = p, значит Θ(np log n) = Θ(n log n).

В в) написать Θ(n log n) «по случаю 2». Случай 2 требует f = Θ(nlog_b a) ровно, а здесь f больше в log n раз. В б) забыть проверить регулярность: на экзамене за это снимают.

Задача 5. Рекурсия на Java. Напиши рекурсивную функцию sumDigits(int n), которая возвращает сумму цифр неотрицательного n. Что она вернёт для 4096? Оцени время и память через n.

static int sumDigits(int n) {
    if (n < 10) return n;              // база: одна цифра
    return n % 10 + sumDigits(n / 10); // последняя цифра + остальные
}

sumDigits(4096) = 6 + sumDigits(409) = 6 + 9 + sumDigits(40) = 6 + 9 + 0 + 4 = 19.

Каждый вызов отрезает одну цифру, цифр у n примерно log₁₀ n. Время Θ(log n), память тоже Θ(log n): столько вызовов одновременно лежит в стеке.

Вся теория для повторения

Вопросы, которые могут попасть в теоретическую часть. Сначала ответь вслух, потом открой.

1. Определения O, Ω, Θ.

f = O(g), если есть c > 0 и n₀, что f(n) ≤ c·g(n) при всех n ≥ n₀ (сверху). Ω это то же снизу: f(n) ≥ c·g(n). Θ значит и O, и Ω одновременно.

2. Сравни рост n log n и n^1,5 через предел.

(n log n) / n^1,5 = log n / √n → 0. Значит, n log n растёт медленнее: n log n = o(n^1,5).

3. Мастер-теорема: три случая и когда она не применима.

T(n) = aT(n/b) + f(n). Сравниваем f с nlog_b a. Меньше полиномиально: Θ(nlog_b a). Равно: Θ(nlog_b a log n). Больше полиномиально и выполнена регулярность a·f(n/b) ≤ c·f(n), c < 1: Θ(f(n)). Не применима: подзадачи разного размера, T(n − 1), a не константа, разница с nlog_b a только в log n раз.

4. Метод подстановки: что делаем?

Угадываем вид ответа и доказываем по индукции с той же константой. Это проверка догадки, а не способ найти ответ.

5. Сортировка слиянием: рекуррента, время, память, устойчивость.

T(n) = 2T(n/2) + Θ(n) = Θ(n log n) в любом случае. Дополнительная память Θ(n). Устойчива, если при равенстве брать элемент из левой половины.

6. Быстрая сортировка: худший и средний случай, как избежать худшего.

Худший Θ(n²): опорный каждый раз оказывается самым маленьким или самым большим, например последний элемент на уже отсортированном массиве. Средний Θ(n log n). Спасает случайный опорный или медиана трёх. Память на стек O(log n) в среднем.

7. Подсчёт, поразрядная, карманная: когда работают и за сколько.

Подсчёт: целые от 0 до k, O(n + k). Поразрядная: d разрядов с основанием b, O(d(n + b)), внутри нужна устойчивая сортировка. Карманная: равномерно распределённые числа из [0, 1), O(n) в среднем, O(n²) в худшем.

8. Бинарная куча в массиве: где дети и родитель, сколько стоят операции.

Для индекса i (с нуля): дети 2i + 1 и 2i + 2, родитель (i − 1)/2 нацело. Вставка и извлечение минимума O(log n), минимум посмотреть O(1), построить кучу из массива O(n).

9. Три метода амортизационного анализа.

Групповой (общая стоимость n операций / n), бухгалтерский (операции платят монеты вперёд), метод потенциалов (функция Φ от состояния структуры, амортизированная стоимость = реальная + ΔΦ).

10. Как хранить граф и сколько это памяти.

Матрица смежности O(V²), проверка ребра O(1). Списки смежности O(V + E), соседи вершины за O(deg v). Для разреженных графов почти всегда списки.

11. BFS и DFS: структура, сложность, для чего.

BFS: очередь, O(n + m), кратчайший путь в графе без весов. DFS: стек или рекурсия, O(n + m), поиск циклов, топологическая сортировка, компоненты.

12. Дейкстра, Форд–Беллман, Флойд: когда что.

Дейкстра: от одной вершины, веса ≥ 0, O(n²) на массиве. Форд–Беллман: от одной вершины, любые веса, O(V·E), находит отрицательный цикл, хватает n − 1 прохода. Флойд–Уоршелл: все пары, O(n³).

13. Минимальный остов: Краскал и Прим.

Краскал: сортируем рёбра по весу и берём ребро, если оно не создаёт цикл (проверка через DSU), O(E log E). Прим: растим дерево из вершины, каждый раз самое лёгкое ребро наружу, с кучей O(E log V).

14. Почему наивный рекурсивный Фибоначчи медленный и как его ускорить.

Каждый вызов порождает два, одни и те же значения считаются много раз: время растёт экспоненциально (примерно 1,6n). С запоминанием уже посчитанного или циклом снизу вверх Θ(n).
