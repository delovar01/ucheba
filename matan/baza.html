Шаг 1 из 10

Что такое логарифм

Вопрос: в какую степень надо возвести 2, чтобы получить 8? Ответ 3, потому что 2³ = 8. Это число 3 и называют логарифмом 8 по основанию 2.

log_b x = y значит ровно b^y = x. Логарифм — это показатель степени.

Главный смысл для алгоритмов: log₂ n — сколько раз можно поделить n пополам, пока не останется 1. Пример: 16 → 8 → 4 → 2 → 1, четыре деления, и log₂ 16 = 4.

Поэтому бинарный поиск (ищем в отсортированном массиве, каждый раз смотрим в середину) в массиве из 16 элементов за 4 шага сужает поиск до одного элемента: каждый шаг выкидывает половину.

Сделай сам. Посчитай log₂ 32, log₂ 1 и log₁₀ 1000.
Показать ответСкрыть ответ

log₂ 32 = 5 (2⁵ = 32). log₂ 1 = 0 (любое число в нулевой степени — 1). log₁₀ 1000 = 3.

Ответить log₂ 32 = 16, поделив 32 на 2. Логарифм — не деление, а число делений пополам: 32 → 16 → 8 → 4 → 2 → 1, пять раз.

log_b x = y ⇔ b^y = x

log₂ n = сколько раз делим n пополам до 1.

Шаг 2 из 10

Три правила логарифмов

Логарифм — это показатель степени, а показатели при умножении складываются: 2³ · 2⁴ = 2⁷. Отсюда правила.

log(x·y) = log x + log y, log(x / y) = log x − log y, log(x^k) = k · log x.

Примеры: log₂(8 · 4) = 3 + 2 = 5, и правда log₂ 32 = 5. log₂(n / 2) = log₂ n − 1: поделили пополам — логарифм уменьшился на один. log₂(n²) = 2 log₂ n.

Ещё одно правило, смена основания: log_a x = log_b x / log_b a. Например, log₄ n = log₂ n / log₂ 4 = log₂ n / 2. Логарифмы по разным основаниям отличаются только множителем-числом. Сложность алгоритма записывают через O(…) («о большое»): эта запись говорит, как растёт число шагов, и постоянные множители в ней отбрасывают. Поэтому в O(log n) основание не пишут.

Сделай сам. Посчитай log₂(1024 · 2) и упрости log₂(n³).
Показать ответСкрыть ответ

log₂ 1024 = 10, log₂ 2 = 1, вместе 11. log₂(n³) = 3 log₂ n.

Написать log(x·y) = log x · log y. Логарифм произведения — сумма, а не произведение: log₂(8·4) равно 5, а 3 · 2 = 6.

log(xy) = log x + log y, log(x/y) = log x − log y, log x^k = k log x

log_a x = log_b x / log_b a — основание в O не важно.

Шаг 3 из 10

Прикидки в уме

На собеседованиях и в задачах часто нужно быстро понять, сколько это — log₂ миллиона.

2¹⁰ = 1024 ≈ 1000. Значит, каждые три нуля дают примерно 10 к логарифму: log₂ 10³ ≈ 10, log₂ 10⁶ ≈ 20, log₂ 10⁹ ≈ 30.

Что из этого следует. Бинарный поиск по миллиарду записей — около 30 шагов. А перебор всего миллиарда — миллиард шагов. Вот почему O(log n) считают почти бесплатным.

Сделай сам. Сколько примерно шагов сделает бинарный поиск в отсортированном списке из миллиона телефонных номеров?
Показать ответСкрыть ответ

Около 20: log₂ 10⁶ ≈ 2 · 10 = 20.

Ответить «около 6», взяв log₁₀. Деление идёт пополам, значит основание 2.

2¹⁰ ≈ 10³ → log₂ 10⁶ ≈ 20, log₂ 10⁹ ≈ 30.

Шаг 4 из 10

Предел отношения: кто растёт быстрее

Есть два алгоритма. Первый делает f(n) шагов, второй g(n). Какой хуже на больших данных? Смотрим, что происходит с дробью f(n) / g(n), когда n становится огромным.

Предел lim f(n)/g(n) при n → ∞ — число, к которому дробь приближается при росте n.

Предел 0 — g растёт быстрее. Предел ∞ — f растёт быстрее. Конечное число больше нуля — растут одинаково, с точностью до множителя.

Пример: f = 3n², g = n². Дробь всегда равна 3, предел 3, растут одинаково. Пример: f = n, g = n². Дробь 1/n: при n = 10 это 0.1, при n = 1000 это 0.001, предел 0. Значит n² растёт быстрее.

Сделай сам. Сравни через предел f = n² + n и g = n².
Показать ответСкрыть ответ

(n² + n) / n² = 1 + 1/n. При росте n слагаемое 1/n уходит в 0, предел 1. Растут одинаково: младшее слагаемое n на скорость не влияет.

Решить, что f быстрее, «потому что там больше слагаемых». Для скорости роста важен только самый быстрый член, остальные при больших n теряются.

lim f/g: 0 → g быстрее; ∞ → f быстрее; число > 0 → одинаково.

Шаг 5 из 10

Лестница скоростей роста

Чтобы не считать предел каждый раз, запоминают лестницу. Каждая следующая ступень растёт быстрее любой предыдущей.

1 ≪ log n ≪ √n ≪ n ≪ n log n ≪ n² ≪ n³ ≪ 2ⁿ ≪ n!. Знак ≪ значит «растёт намного медленнее».

Прочувствуй на n = 20:

log₂ nnn log₂ nn²2ⁿ
≈ 4.320≈ 864001 048 576

Два правила из лестницы. Любая степень n медленнее любой показательной функции (где n стоит в показателе: 2ⁿ, 3ⁿ): n¹⁰⁰ в итоге проиграет 2ⁿ. Логарифм медленнее любой степени: даже √n обгонит log n.

Сделай сам. Расставь по скорости роста, от медленного: n², log n, 2ⁿ, n log n, n.
Показать ответСкрыть ответ

log n, n, n log n, n², 2ⁿ.

Поставить n² после 2ⁿ, глядя на маленькие n: при n = 2 оба равны 4, а при n = 3 даже n² = 9 больше 2³ = 8. Скорость роста решается на больших n, а там 2ⁿ улетает вверх.

1 ≪ log n ≪ √n ≪ n ≪ n log n ≪ n² ≪ n³ ≪ 2ⁿ ≪ n!

Шаг 6 из 10

Производная: скорость изменения

Производная f'(x) показывает, как быстро меняется функция в точке x. Положительная — функция растёт, отрицательная — падает, ноль — в этой точке ни растёт, ни падает (там бывает минимум или максимум).

Обозначения: e ≈ 2,718 — особое число, ln x — логарифм по основанию e (натуральный).

Таблица минимума: (x^k)' = k·x^(k−1), (eˣ)' = eˣ, (ln x)' = 1/x, число-константа даёт 0. Производная суммы — сумма производных, число-множитель выносится.

Пример: f(x) = 3x² + 5x + 7. Каждое слагаемое отдельно: 3 · 2x = 6x, 5 · 1 = 5, 7 → 0. Итого f'(x) = 6x + 5. В точке x = 1 скорость 11.

Ещё два правила для сложных случаев: произведение (f·g)' = f'·g + f·g', сложная функция (f(g(x)))' = f'(g(x)) · g'(x).

Сделай сам. Найди производную f(x) = x³ − 4x и её значение в точке x = 2.
Показать ответСкрыть ответ

f'(x) = 3x² − 4. В точке 2: 3 · 4 − 4 = 8, функция там растёт.

Написать (x³)' = 3x³, забыв уменьшить степень. Степень всегда падает на один: x³ → 3x².

(x^k)' = k x^(k−1), (eˣ)' = eˣ, (ln x)' = 1/x, (c)' = 0

(fg)' = f'g + fg', (f(g))' = f'(g)·g'

Шаг 7 из 10

Правило Лопиталя

Иногда предел дроби считать трудно: и верх, и низ уходят в бесконечность. Например, ln n / n. Кто победит?

Правило Лопиталя: если верх и низ оба уходят в ∞ (или оба в 0), то lim f/g = lim f'/g'. Берём производную отдельно от верха и отдельно от низа.

Пример: lim ln n / n. Верх (ln n)' = 1/n, низ (n)' = 1. Новая дробь (1/n) / 1 = 1/n → 0. Предел 0, значит n растёт быстрее ln n. Это ровно ступенька лестницы из шага 5.

Если после одного раза снова ∞/∞, правило применяют ещё раз.

Сделай сам. Найди по Лопиталю lim n² / eⁿ.
Показать ответСкрыть ответ

Первый раз: 2n / eⁿ, снова ∞/∞. Второй раз: 2 / eⁿ → 0. Предел 0: показательная eⁿ растёт быстрее n².

Взять производную от всей дроби как от частного, по правилу (f/g)'. Лопиталь — это отдельно производная числителя и отдельно знаменателя, без формулы частного.

Лопиталь: ∞/∞ или 0/0 → lim f/g = lim f'/g'. Верх и низ дифференцируем отдельно.

Шаг 8 из 10

Сумма 1 + 2 + … + n и вложенные циклы

Знак Σ (сигма) значит «сложить». Σ i от 1 до n — это 1 + 2 + … + n.

1 + 2 + … + n = n(n+1)/2. Растёт как n².

Откуда: сложим первое с последним 1 + n, второе с предпоследним 2 + (n−1) — каждый раз n + 1, а пар n/2. Для n = 100: 100 · 101 / 2 = 5050.

Где это в коде. Сравнить каждый элемент с каждым следующим:

for i in range(n):
    for j in range(i + 1, n):
        сравнить(a[i], a[j])

При i = 0 внутренний цикл делает n − 1 шагов, при i = 1 — n − 2, …, в конце 0. Всего (n−1) + (n−2) + … + 0 = n(n−1)/2, это Θ(n²). Запись Θ(n²) («тета») значит «растёт ровно как n², с точностью до множителя»: предел отношения к n² — конечное число больше нуля, как в шаге 4. Здесь он равен 1/2.

Сделай сам. Сколько раз сработает сравнить при n = 5? И при n = 1000 примерно?
Показать ответСкрыть ответ

n = 5: 4 + 3 + 2 + 1 + 0 = 10 = 5 · 4 / 2. n = 1000: 1000 · 999 / 2 ≈ 500 000.

Сказать «раз внутренний цикл короче, это быстрее, чем n²». Он короче в среднем вдвое, а половина от n² — всё ещё Θ(n²): множитель 1/2 в сложности не важен.

1 + 2 + … + n = n(n+1)/2 = Θ(n²)

Цикл в цикле «каждый с каждым» → Θ(n²).

Шаг 9 из 10

Геометрическая сумма: 1 + 2 + 4 + … + n

Геометрическая прогрессия — каждое следующее число в одно и то же число раз больше: 1, 2, 4, 8, 16.

Сумма геометрической прогрессии примерно равна своему самому большому члену. 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1, то есть меньше удвоенного последнего.

Проверка: 1 + 2 + 4 + 8 = 15 = 16 − 1. Самое большое слагаемое 8, сумма меньше 16.

Где это в коде. Динамический массив (список в Python) при переполнении удваивается и копирует всё. Копирования за всю жизнь: 1 + 2 + 4 + … + n < 2n. Поэтому добавление в конец в среднем O(1), хотя иногда бывает дорогое копирование.

А цикл, где i удваивается, делает мало шагов:

i = 1
while i < n:
    i = i * 2

i проходит 1, 2, 4, …, пока меньше n. Это log₂ n шагов из шага 1.

Сделай сам. Чему равна 1 + 2 + 4 + … + 64? И сколько раз выполнится тело цикла выше при n = 64?
Показать ответСкрыть ответ

Сумма 128 − 1 = 127. Цикл: i было 1, 2, 4, 8, 16, 32 — шесть раз, на 64 условие 64 < 64 ложно. Шесть = log₂ 64.

Посчитать сумму как 64 · 7 или складывать вручную до ошибки. Сумма степеней двойки — всегда следующая степень минус один.

Геометрическая сумма ≈ самый большой член. 1 + 2 + … + 2ᵏ = 2ᵏ⁺¹ − 1.

i удваивается до n → Θ(log n) шагов.

Шаг 10 из 10

Гармоническая сумма: 1 + 1/2 + … + 1/n

Сумму H_n = 1 + 1/2 + 1/3 + … + 1/n называют гармонической.

H_n ≈ ln n. Растёт, но очень медленно, как логарифм.

Почему так: сумму можно оценить площадью под кривой 1/x, а площадь от 1 до n равна ln n (из шага 6: производная ln x равна 1/x). Так в тетради и оценивают суммы интегралом. Проверка на n = 4: 1 + 0.5 + 0.33 + 0.25 ≈ 2.08, а ln 4 ≈ 1.39. Разница около 0.7, и с ростом n она не растёт, а приближается к 0.58. Постоянная добавка на скорость роста не влияет.

Где это в коде. Внутренний цикл идёт с шагом i:

for i in range(1, n + 1):
    for j in range(0, n, i):
        работа()

При i = 1 внутренний цикл делает n шагов, при i = 2 — n/2, при i = 3 — n/3. Всего n · (1 + 1/2 + … + 1/n) = n · H_n ≈ n ln n. Это Θ(n log n), а не n².

Сделай сам. Тот же цикл, но внутренний всегда идёт с шагом 1: for j in range(n). Какая сложность? Во сколько раз медленнее при n = 1000, грубо?
Показать ответСкрыть ответ

n · n = Θ(n²). При n = 1000: n² = 10⁶, а цикл с шагом i делает около 8000 шагов (n · H_n ≈ 1000 · 7,5 = 7500, остальное — округления вверх, ведь при n/i с остатком внутренний цикл делает лишний шаг). Разница больше чем в 100 раз.

Видеть два вложенных цикла и сразу писать n². Сложность считают по числу шагов внутреннего цикла, а оно зависит от шага. С шагом i это гармоническая сумма.

H_n = 1 + 1/2 + … + 1/n ≈ ln n

Внутренний цикл с шагом i → n · H_n = Θ(n log n).
